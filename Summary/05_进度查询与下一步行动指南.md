## 0. 先记住一张全景图



```
一本知识库 = 七段流程：
  原料/原文 → 底座切条 → 装填解读 → 层成品打包 → 跨层索引 → 验证 → 交付

每本书的进度 = 一个 7 位数组 stageStates，每位 0=未做 / 1=在建 / 2=完成。
全仓所有"进度"视图（看板、盘点、时间线）都是这一个数组 + 每阶段最后执行时间戳 GTIMES + 卷进度 GVOLS 推出来的。
```

查任何进度问题，最终都落到三个数据源：



| 想看什么          | 去哪看                                                                   |
| ------------- | --------------------------------------------------------------------- |
| 整体一目了然、可筛选可下钻 | 看板 `Summary/html/dashboard.html`（浏览器直接打开）                             |
| 纸面台账、人工盘点口径   | `Summary/01_书目总览.md`、`02_各书产出层.md`、`03_层数据结构与描述.md`、`04_待处理书目.md`     |
| 最近磁盘上哪些书被动过   | `node Skills/progress-dashboard-integration/scripts/check_updates.js` |
| 跨书全局欠账与方法论说明  | 根目录 `README.md`（尤其 §6.6 三条线、§9 已知待办）                                  |

## 2. 想查 "某本书具体卡在哪"—— 四条定位路径

### 路径 A：看板点书名 → 看两处（最快）

打开 `Summary/html/dashboard.html`，「书目总览」点书名进「书籍详情」：



1. **流程表「下一步该怎么做」列** —— 每阶段写好了下一步动作，直接照做。

2. **「⚠ 与标准流程 / 全量契约的偏移点」折叠面板** —— 这本书所有已知的坑、特例、遗留问题全登记在这里（drift 字段）。**这是每本书最有信息量的一栏，必读。**

3. 顶部步骤条看它停在七段流程的哪一段：停在 "装填" 就是没装完，停在 "打包" 就是层文件还没归一。

### 路径 B：查官方待办清单（排优先级用）



* `Summary/04_待处理书目.md` —— 唯一一份 "哪些没做完" 的正式清单，分「无产出待开工 / 在建待收口 / 附带欠账」三档。排优先级先读它。

### 路径 C：数据质量类缺口（不是没做完，是做完但有问题）



| 缺口类型                  | 在哪查   | 命令                                                                    |
| --------------------- | ----- | --------------------------------------------------------------------- |
| 枚举值漂移（层产物跑出定义外取值）     | 存量体检线 | `cd tools/kb-mcp && python server.py drift --book <目录名>`              |
| 哪层压根没有枚举护栏            | 全库体检  | `python server.py checklist`                                          |
| 跨书合并误并待人工裁决（当前 243 条） | 联邦线   | `cd tools/kb-federation && python federation.py conflicts --limit 20` |
| 待人工复核条目队列             | 工厂台账  | `Skills/00-book-knowledge-factory/references/pending-review.md`       |

### 路径 D：跨书级欠账（不属于任何一本书）

根目录 `README.md` **§9 已知待办**：客座枚举 v4 回溯（704 条库外记录）、新官轨范实例 skill 待回填（编号 06）、水东日记阅读器只有设计稿、层命名未统一等。

## 3. 下一步怎么做 —— 按你的处境对号入座

### 处境 1：接一本在建书（如野获编 / 会典 / 地理志）



1. 看板进该书详情，读 drift 面板 + 流程表 "下一步" 列。

2. 读该书自己的实例 skill：`Skills/<NN>-<书名>-knowledge/SKILL.md`（先进遗风这类内含式的在工程目录里）。

3. 读该书的案例反馈：`Skills/00-book-knowledge-factory/references/case-feedback-<slug>.md`—— 前人踩过的坑都在里面。

4. 按七段流程的 mark 判定特征确认磁盘现状（见 `html/stages.js`），从断点继续，不要重跑已完成段。

### 处境 2：收一本已完成书的尾巴（如客座 v4 回溯、食货志入库）



* 枚举回溯类：读 `Skills/00-book-knowledge-factory/references/increment-upgrade.md`（走 registerVersion+1 增量升级，不重跑全卷）。

* 补实例 skill 类（新官轨范）：照 `Skills/00-book-knowledge-factory/assets/samples/xinguan-guifan/` 的样例回填，编号 06。

* 纯工程卫生类（食货志 untracked）：直接 `git add` 入库即可。

### 处境 3：新开一本书（第 7 本起）

**不要自己拍脑袋**，按 `docs/新书开工流程.md` 走：



```
结构看不清？ → 先跑工厂 B（Skills/book-skill-factory）探底切条
Step 0 查契约 → tools/book-mcp（contract_list / layer_list / enum_get）
Step 1–2 定向+定层 → 工厂 A（Skills/00-book-knowledge-factory）
Step 3–4 实例化+试点 3~5 条
Step 5 全量四段式管线（切条→装填→打包→验证）
Step 6 交付后移交 tools/kb-mcp 体检
```

### 处境 4：刷新看板，让数据反映最新磁盘状态



```
node Skills/progress-dashboard-integration/scripts/check_updates.js   # 哪本书动过
node Skills/progress-dashboard-integration/scripts/diff_times.js      # 阶段时间戳变化对比
# 人工复核后改 Summary/html/times.js 与 data.js，再 check_updates.js --update 回写基线
```

完整规范见 `Skills/progress-dashboard-integration/SKILL.md`（含已知盲区表：会典 / 选举志 / 野获编等 7 处采集器会误报，须以人工登记为准）。
