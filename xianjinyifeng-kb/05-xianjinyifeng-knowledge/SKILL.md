## 2. 底座（公共地基，先做）

1. 输入文件：`assets/sources/先进遗风_全本.txt`（**源文件随实例存放**；钦定四库全书本《先进遗风》全本，含书名行与两卷标记）。**以该文件为唯一权威来源**——外部资料只作内容性质/学术定位辅助，不作条目抽取依据（版本差异坑，见工厂 pitfalls.md #11）
2. 章节划分：2 卷。卷号按卷名直接映射：卷上=01、卷下=02；书名/卷标记行不入正文条目（不入任何卷，仅作元信息记录）
3. 条目切分：以空行分隔的段落为"条"；相邻空行并入上一段；剔除书名行与"先进遗风卷上/卷下"两行卷标记（作卷边界锚点本身）。全书预计约 100 条。输出 `_extract\01_先进遗风卷上.txt` / `_extract\02_先进遗风卷下.txt`（格式 `条N|正文`）
4. 指纹库 `_item_registry.json`：key=`NN-NNN`，value=original/norm；norm 归一规则：异体字归一（如 濓/濂、竒/奇、徃/往、尚/上 按字形/通行字归并）、缺字括注 `■〈□〉` 保留原字形、标点统一为现代标点
5. 全部条目建 task 清单（阶段可见、完成可核）
6. **业务 ID 由打包器自动分配**：AI 源数据只写卷内顺序槽位，不手写业务 ID；打包器按「卷号 × 段容量 +1」段位分配，段容量 = 卷条数 × 单层最大扩展系数预留（默认 500）——pitfalls.md #13/#22。
7. **写盘与并行纪律**：写文件一律「临时文件 + rename 落盘」；共享汇总文件统一增量合并语义（`--volumes` 只重算请求卷、合并写回，不覆盖共享文件）——pitfalls.md #12/#14；验证脚本写文件输出，不依赖 stdout——pitfalls.md #6

## 3. 实体层方案（确认启用）

- 实体类型枚举：**继承基准库 `../book-knowledge-factory/references/enum-library.md` §1.1 规范值快照（18 值）** + 本书归纳增量。本书预期高频类型：person 人物 / official 职官 / institution 机构 / place 地名 / era 年号朝代 / work 文献书名 / posthumous 谥号 / system 制度 / behavior 行为 / doc 文书 / unknown 类型待定（兜底）。新增值需有原文证据 + 使用说明，registerVersion+1 回溯
- 种子词典规则：全文本内生（词条必须出现在原文，否则自动剔除）
- 归一规则：异体/同义归并（如"濓/濂"）；复合词形（"学士宋文宪公濓"→宋濂）用 alias_index 手工映射，不动标注
- 主键表：ENT-001..N + alias_index（词形 → ent_id；复合解读词形手工映射）
- 每卷 JSON + 全局归一 + 标注总报告

## 4. 职官任职层方案（确认启用，层库 C1 定制）

- 触发词词典：授/擢/迁/改/除/罢/谪/致仕/兼/领/督/巡抚/提督/荐/升/召/起/历官/累官/累迁/徙/转/调 + 官职词典（尚书/侍郎/都给事中/御史/佥事/布政使/按察使/知府/知州/知县/主事/郎中/员外郎/洗马/给事中/司业/祭酒/翰林 等全文本内生）
- 任职状态枚举：**继承基准库 §1.10 APPT_STATUS（12 值）**：现任/致仕/升迁/贬谪/罢黜/兼领/暂代/追赠/未明 + 起复/世袭/举荐
- 槽位 schema：person（含 person_ent_ids）/ office（含 official_ent_ids）/ institution（含 ent_ids）/ when（未明写"未明"）/ status / evidence / original。一条目多任职拆多条共享 item_id
- 执行流程：任职动词 + 官职词典 → 正则候选 → AI 复核 → 人工校验闭环（V2）

## 5. 人物关系层方案（确认启用，层库 C3 定制）

- 关系类型枚举：**继承基准库 §1.4 REL_TYPES（13 值）**：同僚/师生/姻亲/同乡/同科/举荐/弹劾/恩怨/上下级/父子亲属/敌对/同窗/其他；方向 direction=单向/双向/未明
- 槽位 schema：person_a（含 ent_ids）/ person_b（含 ent_ids）/ relation_type / direction / evidence / original
- 执行纪律：**只建文本有直接证据的关系，推测关系不建**（宁缺毋滥）；举荐关系的"荐/疏荐/特荐/拔"词触发，师生关系的"受业/从游/门人/师事"触发

## 6. 事件层方案（确认启用）

- 五元组：who（含 who_ent_ids）/ action / what / when / where；未明显式写"未明"
- 事件类型枚举：**继承基准库 §1.3 事件类型子库顶层规范全集（23 值）**（笔记/轶事体只继承顶层，不引入行政过程子类型）；本书预期高频：朝政/人事任免/弹劾/建言/科举/文事/赈济/司法/礼仪/轶事/军事/家事。新增值走 registerVersion 动态回填
- 执行方式：试点 1 卷验收 → 全量；未建模条目如实单列缺口

## 7. 作者论说层方案（确认启用，层库 C9 定制）

- 触发词：论曰/愚按/耿子曰/余按/予谓/余以为/余闻/盖尝论（作者直接议论、判断、评价句）
- 立场枚举：**继承基准库 §1.8 OPN_STANCES（5 值）**：肯定/否定/怀疑/讽刺/中立
- 槽位 schema：opn_id / item_id / topic / stance / argument（AI 解读要点，非原文）/ evidence_refs（可引用 CIT 或条目）/ original
- 执行流程：AI 逐条判定论说句；argument 只写要点概要不抄原文；与事件层分工——OPN 收"作者评价"，具体事件归 EVT

## 8. 古今翻译层方案（确认启用，层库 C5 定制）

- 翻译风格枚举：**继承基准库 §1.13 TRL_STYLES（3 值）**：直译/意译/注释性翻译
- 槽位 schema：trl_id / item_id / translation / style / note / confidence / original
- 执行流程：AI 逐条翻译（代码只验覆盖：条目数=翻译数）；专名保留原词+括注；缺字/异体按 norm 归一后译；长文分句群翻译保留分段；支持按卷分步
- 风格基准：本实例未固化专属风格文件；默认以"直译为主、意译达意、专名保留、四字格点缀"为基准，必要时按用户要求固化 `references/translation-style.md`

## 9. 跨层整合

- ID 对齐审计点：实体主键唯一 / 引用槽位合法 / item_id 全回填 / target 用 ID / 枚举口径一致
- 跨层索引：`_kg_join.json` + `_kg_join_flat.csv`（每行 = 一条目，layer_count 贯通层数）
- 枚举治理：枚举单点文件 + registerVersion（新增值 version+1 回溯存量）；校验用**「收集-报告-暂存」**模式，未匹配值入 pending 表不中断，收尾统一决议——pitfalls.md #15

## 9.5 治理组件（确认启用）

- **V2 人工校验闭环**：同名异人（同号/同谥/同姓名）/存疑判定自动收集入"待核清单"CSV（含 provenance：卷-条号 + evidence），人工核前不强行合并（宁建勿并），核后回写。
- **V3 枚举校准**：执行期未匹配枚举值 → 收集-报告-暂存 → 收尾决议（新增/归并/改名）→ registerVersion+1 → 回溯存量；新增值必须有实例证据。
