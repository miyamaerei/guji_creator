# 跨书身份判定方法论

> 联邦库实体身份识别的顶层设计文档  
> 版本：v1.0  
> 日期：2026-10-14

---

## 1. 引言：问题与目标

### 1.1 问题陈述

古籍联邦库的核心挑战：**如何判定两个实体节点是"同一个"**。

当前实现仅依赖归一化名字键的精确匹配，导致：
- 「明太祖」与「朱元璋」分属两个 canonical 组（零词法交集）
- 629 条 official 类精确匹配被标记为 conflict（名字相等≠身份相等）
- 42% 的 record_refs 歧义（引用消解失败）
- 跨书合并覆盖率仅 27%（18,433 个节点未参与任何跨书对齐）

### 1.2 设计目标

建立一套**类型驱动、证据流驱动、选择性驱动**的身份判定体系：
- **类型驱动**：不同类型实体（人/官/地/事/轶闻）有不同的身份逻辑
- **证据流驱动**：身份由多条证据流合议决定，而非单一字段
- **选择性驱动**：键的唯一性半径决定阶梯深度（一步定 vs 多步升级）

## 2. 本体论基础：持续体与发生体

### 2.1 第一性区分

语料中的实体分两个本体类，"同一个 node" 对它们是两种不同的命题：

| | **持续体（continuant）** | **发生体（occurrent）** |
|---|---|---|
| 覆盖类型 | 人、地、官（槽位）、书、时、制、物 | 事（纪事/事件）、轶闻、除授（任命）、议（言论） |
| 同一性是什么 | **一个历史个体被各书用不同称谓指称**（一名多身） | **一次发生被各书用不同叙述复述**（一事多述） |
| 判定逻辑 | **词表身份**：称谓全集相交 + 时空/层级约束 | **事件核身份**：时空坐标 × 参与者 × 行动骨架的核重合 |
| 典型例子 | 「明太祖=朱元璋」——同一肉身 | 「土木之变=丁丑国难」——同一发生，三个名字毫无交集 |

### 2.2 本体论依据

CIDOC-CRM（文化遗产信息交换国际标准）明确区分：
- **Endurant**（持续体）：在时间中持续存在的实体（人、地、机构）
- **Perdurant**（发生体）：在时空中展开的过程（事件、活动）

CRM 的 P1 属性 "has identified by" 明确宣称：「个体身份与标识符的根本本体区分，实践上专用于处理历史名称歧义与多标识符调和」。

**结论**：身份判定必须区分两类逻辑，不能用同一套机制处理。

## 3. 身份判定范式：槽位束 × 选择性驱动阶梯

### 3.1 通用范式（每个类型必答的四问）

```
类型 T 的身份范式 = {
  ① 指称束 slots：[主键槽, 辅键槽…, 画像锚槽]   # 书侧必须产出的字段
  ② 唯一半径 radius：每个槽在什么论域内唯一      # 全局/朝代/上级/本卷
  ③ 升级触发 escalate：主键命中 >1 候选组时，取下一个槽求交，仍 >1 再取…
  ④ 否决 veto：哪个槽取值相悖时一票否决（不许升到底就并）
}
```

### 3.2 选择性驱动阶梯

**伸缩性不靠拍脑袋定阈值，靠实测选择性**：

运行时统计「该槽的取值在已对齐的 canonical 组里出现几次」：
- 出现 1 次 = 一步定（张居正→全局唯一，单字段就是身份）
- 出现 ≥2 次 = 键退化，自动进下一槽

**字段用量 = f(键的选择性)**，冲突驱动加深。

### 3.3 数学基础：Fellegi-Sunter 记录链接

每字段权重 = log₂(m/u)：
- **m-概率**：真实匹配时字段一致的概率（可靠性）
- **u-概率**：随机撞键的概率（机会一致性）

**u-概率恰好就是"唯一半径"的频率版**：
- u 低（稀有值）→ 权重高 → 一步定
- u 高（常见值）→ 权重低 → 需多字段

**结论**：配置里的置信度只该当冷启动先验，u 应该从库内键频实测。

## 4. 各类型身份公式

### 4.1 人（person）

**身份**：生物个体（一个肉身，多个名字）

| 阶梯 | 槽位 | 唯一半径 | 置信度先验 |
|---|---|---|---|
| L0 主键 | 庙号（一朝一帝）；本名选择性=1 时 | 全局 | 0.95 |
| L1 升级 | 本名 × 年代窗 | 朝代 | 0.85 |
| L2 升级 | × 籍贯 | 地域 | 0.80 |
| L3 升级 | × 主职/师承/亲属 | 关系网 | 0.75 |
| L4 画像 | 关系画像（指向已对齐 canonical 的边集合） | 结构 | 0.70 |
| 否决 | 年代窗互斥；籍贯相悖 | — | — |

**特殊处理**：
- 字/号/谥号/封爵 = 称谓槽，独立索引
- 括注同位语（如「朝廷（朱元璋）」）= 身份 witness，收割进 ent_slots

### 4.2 官（official）

**关键区分**：
- **职名槽位**（持续体）：「户部尚书」作为吏部→户部→尚书的职位
- **除授**（发生体）：「郁新任户部尚书」作为人×槽×reign 的三元组

**职名槽位身份**：

| 阶梯 | 槽位 | 唯一半径 | 置信度先验 |
|---|---|---|---|
| L0 主键 | 职名全局唯一时（六部尚书） | 全局 | 0.95 |
| L1 升级 | 职名 × 上级机构链 | 机构 | 0.85 |
| L2 升级 | × 朝代/南京北京 | 时空 | 0.80 |
| 否决 | 上级机构组不同 | — | — |

**除授**：不建 node，建边（person_uid, office_slot_uid, reign, status）

**结论**：629 条 official conflict 的根源是把职名槽位和除授混在一个池里。

### 4.3 地（place）

**身份**：地点本身，不是名字。「京师」在洪武指应天、永乐后指顺天——名字是**时段函数**。

| 阶梯 | 槽位 | 唯一半径 | 置信度先验 |
|---|---|---|---|
| L0 主键 | 同上级下的县名（府内县名唯一） | 上级 | 0.95 |
| L1 升级 | 名 × 隶属链 | 层级 | 0.85 |
| L2 升级 | 改名链（古今名表） | 词表 | 0.80 |
| L3 升级 | 事件锚（同一事发生两地 ⇒ 同一地） | 关系 | 0.75 |
| 否决 | 隶属链分叉（苏州府≠沧州） | — | — |

**CHGIS/TGAZ 范式**：{地名 n, 年份 yr, 类型 ftyp, 上级 p} 四分面——直接抄成地的范式。

**Registry 反哺**：dlz（明史地理志）+ myt（一统志）本身就是地理词表的权威载体。

### 4.4 事（event）

**身份**：一次发生的复述重合。事件核 = (year 或 reign+干支, place canonical, 关键 participant canonical ≥2, action category)。

| 阶梯 | 槽位 | 唯一半径 | 置信度先验 |
|---|---|---|---|
| L0 主键 | 专名大事（靖难、土木之变） | 全局 | 0.95 |
| L1 升级 | 年 × 地 × 核心参与者≥2 × 行动类，四取三 | 核重合 | 0.85 |
| 否决 | 年份冲突、主角冲突 | — | — |

**ACE/ERE 事件共指定义**：「两个事件提及是否指向现实中同一事件」，特征就是事件类型+核心参与者+时间+地点。

### 4.5 轶闻（anecdote）

**身份最弱**：同一母题的变奏（铁冠道人条各书转引）。

**两级设计**：
- 有明确参与者（who_ent_ids 指向已对齐人物组）+ 有时空锚 ⇒ 按事核弱合并（骨架同即并，允许细节差异）
- 纯掌故无参与者/无锚 ⇒ **不做 canonical 合并，只建 `variant_of`/`cites` 软边**

**ACE 提及类型学区分**：
- **可辨识指称**（named/nominal/pronoun）⇒ 进共指链
- **转述/使用性提及（quotative mention）** ⇒ 不进共指链

**判据**：该记录有没有给出可锚定时空的坐标（年/地/具名主角任一），有则进事核流，纯掌故无锚则永远只建 variant_of 软边。

### 4.6 其余类型

| 类型 | 身份公式 | 特殊处理 |
|---|---|---|
| **书（work）** | 题名（明代书目重名极少）；冲突时 × 作者组 → × 类目 | 题名全局唯一时一步定 |
| **时（era）** | （dynasty, reign) 已完备；干支/公元补 year | shz {dynasty, reign, year} 是范式 |
| **制（system）** | 制名（一条鞭法）；冲突时 × 朝代 → × 创制 reign/创制人 → EVO 根 | EVO 链视为一个持续的制，各阶段是版本 |
| **物（object）** | 名 × 类；冲突时 × 产地/属地组 | 属地冲突 ⇒ 否决 |
| **议（opinion）** | 不并（软链）；(言说者组×评的对象×所引书) 对齐才连 cites/关于 边 | 只连不并 |

## 5. 证据流与 registry 反哺

### 5.1 证据流分类

**生成性证据**（能独立造候选）：
- 称谓键（庙号/谥号/字/号/别称）
- 关系三元组（人×职×时、人×年号桥）
- 共现画像（event/evt/chr/ming 的 who/when/where）
- 隶属链（省—府—县的上级 canonical 序列）

**否决性证据**（不产生候选，但防误并）：
- reign/年代窗互斥
- 籍贯相悖
- 隶属链分叉

### 5.2 Registry 反哺

语料本身埋着词典书：
- **zgz/mhd**：职官制的 registry（机构/职名/品级）
- **dlz/myt**：地名的 registry（古今地名/隶属关系）
- **两志卷首**：庙谥年号的 registry

**联邦的反哺设计**：从词典书派生全局 `place_registry / office_registry / title_registry`，人物别名表因此有了外部权威源，而不是 13 本书互相指认。

## 6. 实现架构

### 6.1 四段引擎

1. **收割（harvest）**：从 records 抽 `ent_slots(uid, kind, value, source_layer, evidence_ref)` ——称谓、别称、隶属、时空锚，全部结构化进表。
2. **流生成（generate）**：每条 key_stream 独立生成候选（持续体按键、发生体按**核重合**）——关系第一次获得**造候选的权力**，不再只是放大器。
3. **合议（adjudicate）**：候选按 (证据流数 × 强度 − 否决) 定置信；**迭代轮**：并查集先并强证据 → 组对齐后邻域可比 → 事件核/画像流产生新候选 → 收敛。
4. **分流（route）**：strict 身份 ⇒ canonical 合并；轶闻/议论 ⇒ `assoc_edges(from,to,kind∈variant_of,cites,about)` 新表，**永不进 members**（保护合并图纯净）。

### 6.2 关键修正

1. **纯并查集是已知病灶**：集体 ER 文献的结论——传递闭包合并会放大错误。否决器的正确形态是把年代窗互斥等变成 **cannot-link 约束**参与聚类，而不是事后扣分。
2. **置信不该手拍常量**：FS 框架里 m/u 双概率应由数据估（EM 是常规做法）；配置里的 stream_confidence 只该当冷启动先验，跑起来后用库内实测撞键频率持续校正。
3. **别名应带时段限定**：维基数据的实践——名称声明带 qualifier（使用起讫时间）与 rank（preferred/normal/deprecated）。ent_slots 表该从一开始就带时间戳列。

### 6.3 代码支持 vs 缺口

| 能力 | 现状 | 动作 |
|---|---|---|
| 全量幂等重建 + 裁决重放 | ✅ 已支持 | 不动 |
| 配置驱动泛化 | ✅ 有 name_rules | ➕ identity_policies.json 新配置 |
| 称谓槽 | ❌ 13 书 ent payload 零结构 | ➕ harvest.py + ent_slots 表 |
| 候选流 | ⚠️ 只有名字键一流 | ➕ designator/event_core/relation_profile 三个生成器 |
| 官/除授混池 | ❌ official 当普通 node | 改：槽位键 = (上级组×职名×朝代)；appt 三元组转为边 |
| 发生体身份 | ❌ 完全不存在 | 新流：who/when/where 对齐核匹配 |
| 软关联 | ❌ 只能并进 members | ➕ assoc_edges 表 + assoc 新查询 |
| 否决器 | ❌ 只有 cap（误用） | 改 disambiguate：年代窗互斥检查 |
| 权威词表 | ⚠️ 有 enum 库无地名/职名表 | 从 dlz/myt/mhd/zgz 派生 registry |
| 已知 bug | [:5] 截断 / cap 键错位 / LOAD_ORDER 硬编码 | 顺手修 |

## 7. 实施计划

### 7.1 源数据库补充（书侧契约）

**ent 层必带结构化称谓槽**：
```json
{
  "normalized": "朱元璋",
  "type": "person",
  "aliases": [
    {"value": "国瑞", "kind": "字"},
    {"value": "明太祖", "kind": "庙号"},
    {"value": "太祖高皇帝", "kind": "谥号"}
  ],
  "native_place": "濠州钟离",
  "era_window": {"start": "洪武", "end": "洪武"}
}
```

**括注同位语是资产，禁止清洗**：「朝廷（朱元璋）」「巡抚（忠介谥）」保留。

**关系层三件套必带**：凡 appt/ming/event 类记录，`*_ent_ids` + 时间锚（reign 或 year）+ 空间锚，缺一不得出货。

### 7.2 新数据库设计

**新增表**：
- `ent_slots(uid, kind, value, source_layer, evidence_ref, t_start, t_end)`：身份槽位表
- `assoc_edges(from_uid, to_uid, kind, evidence_ref)`：软关联表（variant_of/cites/about）
- `place_registry / office_registry / title_registry`：权威词表（从词典书派生）

**配置**：
- `identity_policies.json`：per type {slots, radius, escalate, veto}

**不改**：
- 现有 nodes/edges/canonical/members 表结构（派生物，全量重建）
- 现有 member_overrides / override_log（人工裁决重放机制保留）

### 7.3 ELT 方法论

**Extract（抽取）**：
- 从 records 抽 ent_slots（称谓、别称、隶属、时空锚）
- 从 appt/ming/event 抽关系三元组
- 从括注文本抽身份 witness

**Load（装载）**：
- ent_slots 表：INSERT OR REPLACE（幂等）
- assoc_edges 表：INSERT OR REPLACE（幂等）

**Transform（变换）**：
1. harvest：抽 ent_slots
2. generate：三条流生成候选（designator/event_core/relation_profile）
3. adjudicate：带约束的凝聚聚类（cannot-link = 否决器）
4. route：strict 身份 → canonical；软关联 → assoc_edges

**重放**：member_overrides 在 T3 后重放（现有机制保留）

### 7.4 新书范式

**出货前必须能填齐本类型范式的 ①**，且**带 *_ent_ids 的锚槽不许留裸文本**。

**验收清单**（以人为例）：
- [ ] ent 层有 normalized + type
- [ ] ent 层有 aliases 数组（至少一个称谓槽）
- [ ] ent 层有 era_window（至少 reign）
- [ ] appt/ming/event 层有 *_ent_ids + reign/year
- [ ] 括注同位语未被清洗

## 8. 实践示例

### 8.1 抽样数据

选 kzz（困知记）、shz（食货志）、zgz（职官志）三书，展示：
- 如何从现有 records 抽 ent_slots
- 如何用 slot-ladder 判定身份
- 如何生成候选并合议

### 8.2 示例 1：明太祖 = 朱元璋

**现有数据**：
- kzz:01:ENT-0465（明太祖）
- kzz:01:ENT-0570（朱元璋）
- kzz:05:ENT-1011（太祖高皇帝）

**收割 ent_slots**：
```
uid: kzz:01:ENT-0465
kind: 庙号, value: 太祖, t_start: null, t_end: null

uid: kzz:01:ENT-0570
kind: 本名, value: 朱元璋, t_start: null, t_end: null

uid: kzz:05:ENT-1011
kind: 谥号, value: 太祖高皇帝, t_start: null, t_end: null
```

**括注收割**：
- kzz/ming 01:MING-0001 的 who.text = "朝廷（朱元璋）" → 收割 (ENT-0570, 括注, 朱元璋)

**候选生成**：
- designator 流：庙号"太祖"在明朝唯一 → 一步定 → 候选 (ENT-0465, ENT-1011)
- 括注流：ENT-0570 的括注 witness → 候选 (ENT-0570, ENT-0465)

**合议**：
- 三个 ent 的称谓槽交集 = {太祖} → 合并为一个 canonical

**结果**：
```
canonical: canon-00987 (repr_label: 朱元璋)
members:
  - kzz:01:ENT-0465 (method: designator_miaohao, confidence: 0.95, status: auto)
  - kzz:01:ENT-0570 (method: gloss_witness, confidence: 0.80, status: auto)
  - kzz:05:ENT-1011 (method: designator_shihao, confidence: 0.90, status: auto)
```

### 8.3 示例 2：户部尚书（槽位 vs 除授）

**现有数据**：
- shz/appt APPT-01002：person=郁新, office=户部尚书, reign=永乐

**收割**：
- office_slot: (户部尚书, 户部, 明) → canonical: office-00123
- appointment: (person-郁新, office-00123, 永乐, 现任) → assoc_edge

**结果**：
- official node 不再存在（拆分为 office_slot + appointment edge）
- 629 条 official conflict 消失（因为不再合并除授）

### 8.4 示例 3：土木之变（事件核）

**假设数据**：
- kzz/event EVT-0001：year=正统十四年, place=土木堡, participants=[英宗, 王振]
- wzz/event EVT-0023：year=1449, place=土木堡, participants=[英宗, 王振]

**收割 ent_slots**：
```
EVT-0001:
  kind: 年, value: 正统十四年
  kind: 地, value: 土木堡
  kind: 参与者, value: 英宗
  kind: 参与者, value: 王振

EVT-0023:
  kind: 年, value: 1449 (→ 正统十四年)
  kind: 地, value: 土木堡
  kind: 参与者, value: 英宗
  kind: 参与者, value: 王振
```

**候选生成**：
- event_core 流：四要素全等 → 候选 (EVT-0001, EVT-0023)

**合议**：
- 核重合度 = 4/4 = 1.0 → 合并

**结果**：
```
canonical: event-00001 (repr_label: 土木之变)
members:
  - kzz:event:EVT-0001 (method: event_core, confidence: 0.95, status: auto)
  - wzz:event:EVT-0023 (method: event_core, confidence: 0.95, status: auto)
```

## 9. 总结

本方法论的核心贡献：
1. **本体论区分**：持续体 vs 发生体，两类身份逻辑
2. **槽位束范式**：每类型定义主键/辅键/否决，选择性驱动阶梯
