> 关联：`docs/跨书合并-数据库设计.md` §11 偏差台账（A1/A3/A4/A6）、`docs/新书开工流程.md` §3。

## 0. 为什么是两条契约，而不是一个"大 JSON"

一本书同时承载三种语义，混在一张表里就是当前混乱的根源（`book_meta` 空壳、`_item_registry.json` 四套 schema、
`items` 平表）。本契约把「书目身份」与「结构位置」各自独立成文件，与既有知识层正交：

| 域 | 文件 | 回答 | 契约 | 状态 |
|---|---|---|---|---|
| 著录域 Bibliographic | `book.meta.json` | 这是**哪一本书**、哪个版本、藏在哪 | **C8（本文件 §1）** | 新增 |
| 结构域 Structural | `spine.json` | 内容在原书**哪里**，到哪一级 | **C9（本文件 §3）** | 新增 |
| 底座指纹 | `_item_registry.json` | 条级**原文全文** | C3（既有） | 不动 |
| 知识域 | `_layers/<layer_key>/*.json` | 原书**说了什么** | C4/C6（既有） | 不动 |

三域唯一交点是**锚点**：`spine` 节点用 `item_id + start/end` 指向 `_item_registry.json`，
知识层继续用 `item_id`（现状不变）。除锚点外互不引用。

> **例外（已执行）**：盘上 18 本里有 17 本已经有 `书籍json/<书>_校对版.json`，book→卷→条 树与条级全文就地在那儿。
> 这批书**不另建 `spine.json`**，改为就地补 8 个机采字段——见 **§6b**。

**两条防冗余铁律**（贯穿全部字段设计）：

1. **不抄原文**。`spine.json` 只存偏移量，禁止出现 `text` 字段——原文唯一源是 C3 指纹库。
2. **不存可计算量**。字符数、节点计数、卷数等凡能由 `start/end`、`nodes`、`items` 求出的，一律不落字段。

## 1. C8 —— `book.meta.json` 字段设计

**位置**：`<book>-kb/book.meta.json`（工程目录根，与 `_item_registry.json` 同级）。
**入库**：是（这是身份数据，必须可 diff）。**份数**：一本书一份。
**结构**：五块 `ident / work / expression / manifestation / governance`（FRBR 三层 + 一本书四处 id 空间 + 治理元数据）。

### 1.1 可得性四级（每个字段都要标，这是本契约的核心机制）

| 级 | 含义 | 取值要求 |
|---|---|---|
| **A** | 机采：仓内现成文件可直接读出 | 必填，采集器写入 |
| **B** | 散文：信息存在但未结构化（`registry.md` 的 `底本=`、`01` 表的「文献性质」） | 一次性抽取 + 人工确认 |
| **C** | 人工登记：书志学知识，仓内无源（藏地、成书年、梗概） | 人工填，或 `null` + `null_basis` |
| **D** | 来源物理不可得：该数字化底本本身不含此维度（txt 转录本无叶数） | **必须 `null` + `null_basis`，禁止臆造** |

> `null_basis` 约定：凡 D 级字段值为 `null`，同块必须给 `"<字段>_basis"` 一句理由。
> 理由不是形式——它区分"我没查"和"这个底本没有"，后者是可交付的诚实结论。
> 沿用工厂"如实报告缺口"纪律到 schema 层。

### 1.3 最小可用集

新书开工时必须先有：`book_id, title, repo_dir, board_id, creator.name, creator.dynasty, genre,
punctuation, base_kind, digitization.format, digitization.file, availability, confidence, updated`（14 项，全 A 级）。
其余允许 `null` + `null_basis`，但 **D/C 不许伪装成 A**——`availability` 会当场戳穿。

## 3. C9 —— `spine.json` 字段设计

**位置**：`<book>-kb/spine.json`（工程目录根）。**生成**：`build_spine.py`（派生节点）+ 目录/卷首证据（source 节点）。
**入库**：派生物**不入 git**（同 `_layers/`），只入 `source` 节点的证据表 `spine.source.json` 才入 git——
见 §3.5，这是"可重跑"与"人工判定不可丢"的折中。

### 3.1 六级 ladder 与现状

| kind | 中文 | 代码 | 现状（实测） | 默认可派生 |
|---|---|---|---|---|
| `book` | 书 | — | 隐含 | ✔ |
| `juan` | 卷 | `j` | **13/13 可得**（`volumes` 表 116 行，缺 6 书） | ✔ 目录/`item_id` 前缀 |
| `pian` | 篇 | `p` | 仅 `minghuidian.section`(去重 199)、`mingyitongzhi.region`(17) | 需证据 |
| `zhang` | 章 | `z` | `yhb` epub toc 39 章；`qubian` 旁挂 25 章——**经 §3.4b 同构核对，其中 20 章名即「卷一…卷二十」、72「节」即 72 条，在蘧编不构成独立章层** | 需证据 |
| `duan` | 段 | `d` | **0 处立契约**，只以 `\n\n` 混在 `original` 串里 | ✔ 派生 |
| `ju` | 句 | `s` | **全库 0** | ✔ 派生（开关见 §4.1） |

> 注意：`篇/章` 与工厂 B 的"条目标题"（`heading_kind`）不是同一物——B 的 heading 是**条**的标题，
> 对应现有 `item_id` 层，不新建 kind；`zhang` 是标题的**上一级聚合**（如"卷三 宗肃"下的类目）。

### 3.2 sid 文法（稳定、可读、可排序）

```
sid    ::= <book_id> [ ":" <seg> ( "/" <seg> )* ]
seg    ::= <K><no>
K      ::= j | p | z | d | s          （卷/篇/章/段/句）
no     ::= 两位零填充序号（同 parent 内连续递增，不跳号）
```

示例：`yhb:j03` → `yhb:j03/z02` → `yhb:j03/z02/d01` → `yhb:j03/z02/d01/s03`。

- 序号是**同 parent 内的相对序**，不是全局序，故上层插节点不重编下层 id。
- `sid` 不含偏移量 → 文本改动不影响 id 稳定（可重算而非重命名）。
- 卷的"卷首/补遗/附录"不另立 kind：仍 `kind=juan`，`no` 依全书正序连续编号，原文卷名放 `title`
  （如 `title:"补遗卷一"`）。这样 `no` 与 `item_id` 前缀保持一一对应（§4.3）。

### 3.2b `kind` 是角色不是深度（"节/门/类"往哪放）

六级阶梯 `书→卷→篇→章→段→句` 是**角色词表**，不是固定层数。古籍真实名目远多于此
（节、门、类、部、汇考、外纪、补遗……），若为每个名目立一个 kind，词表会失控。定规：

1. **kind 封闭为六级**（`spine_kinds`），书中名目写进 `title`，不新增 kind。
2. **允许同 kind 嵌套**：`…/z01/z02` 合法（如方志 卷→门→类 中的两级聚合），
   层级深浅由 parent 链决定，不由 kind 决定。
3. **沿 parent 链的 kind 次序必须非递减**（`book < juan < pian < zhang < duan < ju`），
   即禁止 `卷` 在 `章` 之下、`段` 包含 `卷` 这类倒挂（S13，可机器校验）。
4. `pian` 用于**卷与章之间**的聚合层（"上/下"、"外纪"、"内篇"）；判据是**它在链上的位置**，不是它的名字。
5. **"节"通常不是 spine 节点**。蘧编实测其 72 "节" 与 `item_id` 层一一对应（§3.4b），
   即"节"就是"条"——而条已由 C2/C3 登记，重列即第二份真源。凡候选层与条数相等，先怀疑它是条。

### 3.3 文件骨架

```jsonc
{
  "spine_version": "1",
  "book_id": "yhb",
  "declared_depth": { "juan": true, "pian": false, "zhang": true, "duan": true, "ju": true },
  "recipe": {
    "axis": "primary",
    "structure_json": "structure.json",
    "registry": "_item_registry.json",
    "registry_hash": "sha256:…",
    "offset_unit": "char",
    "generator": "build_spine.py",
    "generated_at": "2026-10-16"
  },
  "nodes": [ /* §3.4 */ ]
}
```

| 字段 | 中文 | 必填 | 说明 |
|---|---|---|---|
| `declared_depth` | **交付深度**（决策，非数据） | ✔ | Phase ② 用户拍板"这本书切到哪一级"。闸门用它比对实产：声明 true 而 nodes 无该 kind → WARN。**不要求全书到句** |
| `recipe.structure_json` | 派生规则出处 | ✔ | 工厂 B 的 `structure.json`（卷/标题/段落**识别正则**）。C9 存结果不重存规则 |
| `recipe.registry_hash` | 指纹库快照哈希 | ✔ | **失效闸**：与当前 `_item_registry.json` 实算哈希不符 → 本 spine 作废必须重算。这是偏移安全的唯一硬保证 |
| `recipe.offset_unit` | 偏移单位 | ✔ | 恒为 `char`（字符数，非字节），语言无关 |

### 3.4 节点两态（按 kind 判别，无交叉空列）

**聚合态**（`kind ∈ book/juan/pian/zhang`）——覆盖一批条，不存偏移：

| 字段 | 必填 | 说明 |
|---|---|---|
| `sid` / `parent` / `kind` / `no` | ✔ | 见 §3.2；root 的 `parent=null` |
| `title` | | 原书所载题名（`"卷三 宗肃"`），无则 null |
| `origin` | ✔ | `source`（此级在**所用文本中已有明确标记**：原书目录、卷首标题、或整理本所加）\| `derived`（本管线按规则切出）。注意"source"不等于"古人原书就有"——整理本的章节同样是 source，靠 `evidence` 说明是谁的结构 |
| `evidence` | `origin=source` 时必填 | 出处：`目录著录` / `卷首标题` / `序跋所述` / `蘧编_结构化.json 章标题（整理本）`。**防臆造结构**——说得出证据才算文本里有此级 |
| `first_item` / `last_item` | ✔ | 覆盖的 `item_id` 闭区间（同卷内条号连续，故用区间不用数组） |

### 3.4b 同构识别：一棵树不许写成两棵（实测逼出来的规则）

蘧编盘上同时存在**两份结构表达**：`_item_registry.json` 的 `item_id` 前缀（去重 23 个），
与旁挂 `_source/蘧编_结构化.json` 的 25 章 / 72 节。初判读很容易得出"两套切分轴"的结论——
**逐条核对后它们是同一棵树**：

| 核对项 | 实测 |
|---|---|
| 章名 | 25 章中 **20 章名即"卷一…卷二十"** |
| 章下节数 vs registry 对应前缀条数 | **20 / 20 全等，0 例外**（卷一 40 节 = `01-001`…`01-040`；卷二 6 节 = 6 条） |
| "节"是什么 | **"节"即"条"** = `item_id` 层，依 §3.1 不进 spine 节点 |
| 余下 5 章 | 序 / 前言 / 后记（一）/ 后记（二）/ 附录 = registry 前缀 `00`（2 条）/`21`（2 条）/`22`（1 条），按 §3.2 记作 `juan` 节点（卷首卷尾不另立 kind） |

所以 C9 定规 **`spine_isomorphism`（S15）**：派生前必须做同构识别——候选节点 `title` 与既有卷名一致、
且其子节点数与该卷条数相等 ⇒ 判为**同一结构，只登记一次**。

> 为什么这条值一条规则：一棵树写成两棵，所有下游计数直接翻倍，而且**没有任何一层自洽校验能发现**——
> 两份都各自完整、各自无悬空父节点。它是 A 族坑（"全绿但答不了"）的结构版。
> 蘧编若真按两轴装载，卷数会从 23 变 48、章数凭空多出 25。

**并行切分轴仍然保留**，但要说清它不是为蘧编开的：真正的双轨（如方志的"门类"轴与"卷"轴同时切同一文本、
且互不对应）一旦出现，第二轴另存 `spine-<axis>.json`，`recipe.axis` 标轴名，装载主键 `(book_id, axis, sid)`；
`spine_single_tree`（S12）保证**同一轴内**一个 `item_id` 只被一条路径覆盖。
蘧编**不是** S12 的例证——契约里写明此点，防止后来者拿它当"该开第二轴"的理由。

**容器态**（`kind ∈ duan/ju`）——落在某一条内，带偏移：

| 字段 | 必填 | 说明 |
|---|---|---|
| `sid` / `parent` / `kind` / `no` | ✔ | — |
| `title` | | 恒 null（段句无题名） |
| `origin` | ✔ | 多数为 `derived` |
| `rule` | `origin=derived` 时必填 | 派生规则 id：`blank-line`（空行分段）\| `punct-cjk`（`。！？` 断句）\| `json-para-align`（旁挂结构化文件经 S14 对齐落进 original）\| `manual` |
| `item_id` | ✔ | 所在条，回指 `_item_registry.json` 键 |
| `start` / `end` | ✔ | **半开区间 `[start,end)`，字符偏移，指入 `original` 串**（不指 `norm`，指 `norm` 会因归一失配） |

### 3.5 校验规则（S 族护栏的机器真源）

| # | 规则 | 违反等级 |
|---|---|---|
| S1 | root（`kind=book`）恰一个；`sid` 书内唯一 | ERR |
| S2 | 除 root 外每个 `parent` 必须存在于 nodes | ERR |
| S3 | 同 `parent` 子节点 `no` 连续递增、不跳号不重号 | ERR |
| S4 | `duan/ju` 必须有 `item_id`，且 `0 ≤ start < end ≤ len(original)` | ERR |
| S5 | **重算校验**：`registry_hash` 一致时，按 `rule` 重切 `original` 必须逐字符复现全部 `start/end` | ERR |
| S6 | 同 parent 下区间不得重叠、必须按 `no` 递增 | ERR |
| S7 | 聚合节点 `first_item/last_item` 的卷前缀必须等于其 `juan` 祖先的 `no` | ERR |
| S8 | spine 禁止出现 `text`/`original`/`chars` 字段（原文只在 C3，计数可算） | ERR |
| S9 | `kind=juan` 节点集合必须 ⊇ `items` 表出现过的 volume 值 | WARN |
| S10 | `declared_depth` 声明 true 而未产出该 kind | WARN |
| S11 | `origin=source` 而 `evidence` 缺失 | ERR |
| S12 | 同轴内一个 `item_id` 不得被两个兄弟分支同时覆盖（并行切分必须换 `axis` 另存文件） | ERR |
| S13 | 沿 parent 链 `kind` 次序非递减（`book<juan<pian<zhang<duan<ju`），同 kind 允许嵌套 | ERR |
| S14 | **旁挂对齐**：分段信息只在别处时，须以忽略空白的定位落进 `original` 区间；每段落位、不重叠；**未覆盖的字符只能是在别处已登记的文本**（如 `title` 所载条标题），且必须列出未覆盖区间及其归属 | ERR |
| S15 | **同构识别**：候选节点与既有卷节点同名且子节点数=该卷条数 ⇒ 判同一结构，只登记一次 | ERR |

> S5 是本契约最有价值的一条：它把"偏移量对不对"从人工抽查变成确定性重算。
> 前提是 C3 的"指纹库只读"——S5 与 `registry_hash` 一起构成闭环。

### 3.6 C9 落库映射

| C9 物 | 落点 | 层级 | 说明 |
|---|---|---|---|
| `spine.json` nodes | 新表 `spine(book_id, axis, sid, parent_sid, kind, no, title, origin, evidence, rule, item_id, start_offset, end_offset, first_item, last_item)`，主键 `(book_id, axis, sid)` | **Tier1 忠实装载** | 不进 Tier2：spine 不参与消歧，`build_nodes` 不许读它。`axis` 支撑 §3.4b 的并行切分轴 |

## 4. 跨契约硬约束（C8 ⇄ C9 ⇄ C3/C2）

这四条是两条契约真正的耦合点，也是零散设计时最容易漏的：

### 4.1 标点形态 → 句级派生开关

`expression.punctuation == "原本无"` 时，`declared_depth.ju` **必须为 false**，且任何 `rule=punct-cjk`
的 `ju` 节点视为 ERR。理由：无句读的刻本里"句"是现代人切的，不是原书结构；把它当原书结构
会在下游产生"古人这样断句"的假事实。段同理：派生段属整理段，靠 `origin=derived` + `rule` 显式区分。

### 4.2 著录卷数 ⇄ 实测卷数（是信号，不是冗余）

`expression.juan_declared`（书志所载，C8）与 `spine` 里 `kind=juan` 的节点计数（实测，C9）**是两个不同事实**：

| 书 | `juan_declared`（著录，源 `GVOLS.total`） | spine 实测 | 差异含义 |
|---|---|---|---|
| `wzz` 五杂俎 | 16 | 12（`items` 卷号仅 05–16，缺 01–04；`volumes` 表 16 行） | **有 4 卷从未装载**，是缺口不是错 |
| `yhb` 万历野获编 | 34（30 正 + 4 补遗） | 33（已到 1–32、34，缺卷 33） | 缺 1 卷。注：`Summary/01` 记「20/34 卷」与此冲突，属 P1 待归一 #4 |
| `mhd` 明会典 | 180 | 装填 108（按部门选卷、非连续） | 在建进度差，且成品按部门聚合不按卷打包 |
| `mhd` 明会典 | 180 | registry 去重 volume=180 | 底座完备，缺的是打包 |

闸门报 **INFO**（不报 ERR），并把差值登记为可查询缺口——这正是把 `GVOLS.total` 单点真相
拆成"著录/实测"两源的做法。**关键纪律：`juan_declared` 的唯一权威源仍是 `GVOLS[bid].total`，
不得在别处再存第三份卷数**（当前 `01` 表散文、`book_meta.note` 散文即为此病）。

### 4.3 `item_id` 前缀 = 卷节点 `no`

C2 规定 `item_id = NN-NNN`（卷-序）。故 S7 可直接机器校验：条的 `NN` 必须落在其 `juan` 祖先的 `no` 上。
这是把 C2、C3、C9 三条契约焊在一起的唯一接缝，也是防止"卷名对不上条号"的闸。

### 4.4 `registry_hash` = C3 与 C9 的契约

C3 说指纹库"只入不出、执行期只读"。C9 的偏移量安全性完全依赖这一点，故 C9 必须持 C3 的哈希。
反向红利：任何对指纹库的修正（异体字/缺字归一）都会使受影响书的全部 spine 立即作废重算，
不会留下"改了指纹库但 spine 还指着旧偏移"的隐性错——这恰是 A 族坑（#50 型"全绿但答不了"）的结构版。

## 5. 与工厂 B `structure.json` 的分工（避免重复设计）

| | 工厂 B `structure.json` | C9 `spine.json` |
|---|---|---|
| 是什么 | **解析规则**：`toc_anchor / body_anchor / volume_pattern / heading_kind / heading_pattern`（正则） | **解析结果**：节点树 + 偏移 |
| 谁写 | 六组启发式问询的答案翻译（人工/AI 判定） | `build_spine.py` 依规则执行 |
| 何时定 | 工厂 B 探底阶段 / Phase ① | Phase ③ 实例化后、底座切完即生成 |
| 可变性 | 规则改了要重生成 spine | 纯派生物，随时可重算 |

**故 `spine.json.recipe.structure_json` 只存路径引用，不重存任何正则。**
《先进遗风》的经验（`heading_kind: none` → 改"空行段落 = 条"）说明：当规则是"无标题连排"时，
`zhang/pian` 应声明 false，`duan` 的 `rule` 是 `blank-line` 且 `origin=derived`——
这正是 §4.1 开关要处理的形态，两者天然衔接。
