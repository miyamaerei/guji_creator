# 跨书合并：数据库设计

> 承接《跨书合并方案》与《跨书合并-ELT设计》。本文把「总库长什么样」落到具体表结构。
> 状态：**设计待拍板**，schema 已落 `tools/kb-federation/schema.sql`（纯 SQLite，可建空库）。
>
> 用户核心诉求两点都覆盖：① **不只是人物**——所有的层都要进库、都要能跨书对齐；
> ② **要考虑以后新书的层**——第 7 本起的新书、以及任何新层（C13…）零 DDL 接入。

---

## 1. 一个关键澄清：库里只有「一个节点类型」

动手前先厘清层库的一个事实：**GEO（地理）、REG（典章）不是「层」**，它们只是枚举分类组；
真正承载数据的是 `ent`——地名在 ent（`type=place`）、典章散落在 rule/struct 里。

更进一步：层库里所有「人 / 书名 / 名物 / 地点 / 机构 / 概念」都归一进 **ent 这一个节点**，
只靠 `type` 区分。这意味着跨书对齐的「统一对象」只有 **ent**，关系层和引用层都是指向 ent 的边。

**这反而让「所有的层」好设计了**：

| 层扮演的角色 | 落到的表 | 说明 |
|---|---|---|
| 节点（可被跨书对齐的对象） | `nodes` | 当前仅 `ent`；未来新 node 层自动落入 |
| 边（关系 / 引用，指向 ent） | `edges` | REL/APPT/EVT/CIT/LIT/OBJ/CUS/NAM/MING/MEM/CHR |
| 注释（挂在条目上的知识，不跨书对齐） | `records`（JSON） | rule/proc/struct/trl/opn，靠 JSON 查询 |
| 卷级档案（不占 ID 命名空间） | `volumes` | V1 卷阅读模式 |
| 目录（不存数据） | `books`/`layer_catalog`/`layer_fields` | V2/V3 治理组件驱动管线，不入库 |

**铁律延续**：`records` 是「所有的层」的统一落点——新增任何层都不会改它的结构（payload 存 JSON）。
真正会随层变化的，是 `layer_catalog` / `layer_fields` 这两张**目录表**里的行，不是 DDL。

## 2. 三层存储架构

```
┌──────────────────────────────────────────────────────────────┐
│ Tier 0  联邦目录（扩展点）                                      │
│   books · layer_catalog · layer_fields                         │
│   → 新书 / 新层只插这里，不改 schema                          │
└───────────────┬──────────────────────────────────────────────┘
                │ 声明「有哪些层、各层字段语义」
┌───────────────▼──────────────────────────────────────────────┐
│ Tier 1  忠实装载（无损真源）                                    │
│   items（指针，不抄正文）· records（所有层记录的 JSON）         │
│   → 复合主键 (book_id, layer_key, local_id) 隔离，撞号自然消解  │
└───────────────┬──────────────────────────────────────────────┘
                │ T 阶段按目录抽取
┌───────────────▼──────────────────────────────────────────────┐
│ Tier 2  派生图谱（可重建，不入 git）                            │
│   nodes（ent 等节点）· edges（解析后的关系边）                  │
│   canonical · members（去歧义合并结果）                         │
│   candidate_links · pending_refs（待决引用）                    │
│   enum_registry · enum_values · enum_drift（枚举校验）          │
│   volumes · load_runs · federation_meta · fts_nodes(可选)       │
└──────────────────────────────────────────────────────────────┘
```

设计原则（五条）：

1. **不重写 ID**：全部表主键带 `book_id`，复合主键隔离，撞号（实测 2847 个）无需改源数据。
2. **原文只存指针**：`items.fingerprint_ref` 指向 `_item_registry`，正文绝不进总库。
3. **零依赖 SQLite**：纯标准库 `sqlite3`，单文件，守项目铁律。
4. **目录驱动扩展**：schema 固定；新书/新层只插目录表，T 阶段自动识别 node/edge/enum。
5. **一切可重跑**：Tier 1 先删后插幂等；Tier 2 全部可重建（丢了对账重跑即可，不入 git）。

## 3. 层分类总表（22 项 → 四类）

> 来源：`Skills/00-book-knowledge-factory/references/layer-library.md` v11。
> `kind` 决定它被 T 阶段怎么处理；新层照此填 `layer_catalog.kind` 即可。

| 层库编号 | 层名 | layer_key | kind | 落点 / 说明 |
|---|---|---|---|---|
| L0 | 底座 | base | profile(特) | → `items`（条目锚点，非知识层） |
| L1 | 实体 | ent | **node** | → `nodes`（THE 跨书对齐枢纽，type 区分人/地/书/物/机构/概念） |
| L2 | 规则 | rule | annotation | → `records`（JSON，按 item_id 查） |
| L3 | 流程 | proc | annotation | → `records` |
| L4 | 结构化 | struct | annotation | → `records`（LGR/TME/DOC/ACT/FRD 五维） |
| L5 | 事件 | evt | **edge** | → `edges`：who→ent、where→ent(place)、ref_events→evt |
| C1 | 职官任职 | appt | **edge** | → `edges`：person/office/institution→ent |
| C2 | 文献资产 | lit | **edge** | → `edges`：author/work→ent(type=book) |
| C3 | 人物关系 | rel | **edge** | → `edges`：person_a/b→ent，predicate=relation_type |
| C4 | 名录谱牒 | nam | **edge** | → `edges`：entries 内人物→ent |
| C5 | 古今翻译 | trl | annotation | → `records`（item 级译文） |
| C6 | 引书索引 | cit | **edge** | → `edges`：cited_work→ent(type=book) |
| C7 | 名物 | obj | **edge** | → `edges`：name→ent(type=object/animal/plant/food) |
| C8 | 方言风俗 | cus | **edge** | → `edges`：region→ent(type=place) |
| C9 | 作者论说 | opn | annotation | → `records`（topic 可能指 ent，可扩展字段 role） |
| C10 | 明代纪事 | ming | **edge** | → `edges`：who→ent，ref_events→evt |
| C11 | 奏疏谕旨 | mem | **edge** | → `edges`：actor/target→ent |
| C12 | 年谱纪年 | chr | **edge** | → `edges`：ref_events/ref_appts→evt/appt |
| V1 | 卷阅读模式 | vol | profile | → `volumes`（卷级，不占 ID） |
| V2 | 人工校验闭环 | — | 治理 | 不入数据表，驱动管线（待核清单/同名异人） |
| V3 | 枚举校准 | — | 治理 | 不入数据表，驱动枚举回溯 |
| 跨层索引 | _kg_join | join | derived | 可由 `records` 重建，不单独存 |

**统一结论**：
- **node 层**：目前只有 `ent`。但 `nodes` 表用 `layer_key` 列而非硬编码，未来任一 `kind='node'` 的层（比如某新书自建「机构层」「地点层」）直接落入，无需改表。
- **edge 层**：11 个（evt/appt/lit/rel/nam/cit/obj/cus/opn/ming/mem/chr）。它们本身存 `records`，T 阶段据 `layer_fields` 里 `role='node_ref'` 的字段把名字/ID 解析成 `edges` 的 `subject_uid/object_uid`。
- **annotation 层**：rule/proc/struct/trl/opn，全部留在 `records` 的 JSON 里，按 `item_id`/`payload` 查询。它们不参与跨书对齐（「书 A 的一条规则」一般不等于「书 B 的一条规则」）。

## 4. 扩展性机制：新书 / 新层零 DDL

这是用户「还要考虑以后新书的层」诉求的直接回答。

### 4.1 接入一本新书（第 7 本起）

```
1. INSERT INTO books(book_id, name, source_root, ...)          -- 新书级命名空间
2. 跑该书 loader：
     - 遍历各层 → 填 layer_catalog(book_id, layer_key, kind, id_prefix, ...)
     - 遍历各层字段 → 填 layer_fields(role=node_ref|enum|attr, ref_layer, enum_group)
     - 逐条 → records(book_id, layer_key, local_id, payload)
     - 条目 → items(指针)
3. 跑 T 阶段：据 layer_catalog.kind 自动抽 nodes/edges，无需任何新代码
```

**全程不碰 `CREATE TABLE`**。书级命名空间由契约线 C2 强制带前缀（`book_id:`），天然无撞号。

### 4.2 接入一个新层（比如未来的 C13「职官迁转轨迹层」）

```
1. 在 layer_catalog 插一行：kind='edge', id_prefix='TRANSFER-'
2. 在 layer_fields 插若干行：
     ('book','transfer','person',  'node_ref','ent')   -- 指向人物节点
     ('book','transfer','from_office','node_ref','ent')-- 指向机构节点
     ('book','transfer','type',    'enum', 'TRANSFER_TYPE')
3. 该层记录照常进 records；T 阶段自动按 node_ref 字段抽出 edges
```

**不需要为新层写特判逻辑**——`layer_fields.role` 告诉 T 阶段「这个字段是实体引用，去解析成边」，
`enum_group` 告诉它「这个值要送去做枚举漂移校验」。这是「目录驱动」的核心：
**schema 描述数据，目录描述结构，结构变了改目录、不改 schema。**

### 4.3 为什么 edges 不按层拆表

有人会想把 `rel_edges` / `appt_edges` 拆开。不这么做，原因：
- 边是高度同构的（subject→predicate→object），差异只在 `predicate` 取值与字段名；
- 拆表会让「跨层关系查询」（如「这个人出现在哪些关系里」）变成 UNION；
- 字段差异由 `layer_fields` + `payload`（JSON 留全量）兜底，查询时按需取。

如果将来某层确实需要专属索引（如时间范围查询），那是**可选的派生表**，且可重建、不破坏统一模型。

## 5. 去歧义合并如何落到各表（T0–T3 → 表）

呼应《ELT设计》的算法，明确每张表的职责：

| 步骤 | 做什么 | 落到的表 |
|---|---|---|
| T0 层 key 归一 | events→evt、ents→ent（映射表）；未登记层报 WARN（反制 #27） | 读 `layer_catalog`（映射在 loader 里） |
| T1 名字→ID | REL/APPT 里的「名字」经 ent_keys 解析成本书 ENT id | 写 `edges.subject_uid/object_uid`；解析不到写 `pending_refs` + `edges.*_pending` |
| T2 候选生成 | 精确（normalized+type 一致）+ 别名（alias_index 交叉） | 写 `candidate_links`（method=exact/alias, conf） |
| T3 关系消歧 | 并查集 + 关系一致性迭代传播 + 约束剪枝 | 写 `canonical` + `members`（method/conf/status）；冲突的标 `conflict` |
| 人工确认 | 专家锁定高置信合并、解除误并 | `canonical.status='locked'`、`members.status='locked'` |

**「去歧义」的硬闸门 = `members.status`**：auto 是机器并、locked 是人工锁、conflict 是约束违背待核、
pending 是引用都没解析出来。物理上**任何层的源数据一行不动**，合并只产生链接。

**跨书对齐的查询**（呼应「用关系识别同实体」）：
```
cross_search("王守仁")
  → members 找到 canonical_id
  → 列出所有 member uid（各书 ent 记录）+ 各自出处/置信
  → 沿 edges 找该 canonical 下节点的关系网（需经两次对齐：人对齐 + 关系另一端对齐）
```

## 6. 枚举与校验（#27 的收口）

- `enum_registry` / `enum_values`：从 `Skills/00-…/references/enum-library.md` 一次性导入（F 阶段），派生可重建。
- `enum_drift`：T 阶段扫 `records` 里 `role='enum'` 的字段值，凡不在 `enum_values` 的记一行（对应坑 #27 的「执行期被就地吸收」）。
- 这样「枚举漂移」从「交付后人工读 Markdown」变成「入库即查、按书按层统计」——正是契约线要的「校验前置」在合并场景的体现。

## 7. 索引 / 全文检索

- `nodes(label)` / `nodes(type)` / `edges(subject_uid,object_uid,predicate)`：跨书查人/查关系的主索引。
- `fts_nodes`（FTS5，可选）：实体名/别名全文检索；**仅当 Python 的 sqlite3 编译含 FTS5 时由 loader 建**，缺失则跳过，不影响其余表。它是派生索引，不入 git。

---

## 8. 幂等 / 版本 / 回写禁令

- **幂等**：Tier 1 装载 `BEGIN; DELETE FROM records WHERE book_id=?; 批量 INSERT; COMMIT`；Tier 2 全部 `DELETE WHERE book_id=?` 后重算。重跑结果一致（守「一切可重跑」）。
- **版本**：`federation_meta.schema_version` 记联邦 schema 版本；`books.schema_version` 记本书产物版本；`load_runs` 记每次装载的运行日志与条数。
- **回写禁令**：联邦库**只读六本书**，绝不回写 `_layers/` / `_kg_enums.py`。`members` 的合并只是链接，如需把对齐结果反哺源书，走 V2 人工校验闭环（专家确认后回写），不自动。

## 9. 落地顺序对应表

| 阶段 | 做啥 | 涉及表 |
|---|---|---|
| F0-a | 撞号体检脚本固化（2847 撞号） | 复用 `kb_mcp` adapters 扫描 |
| F0-b | 建空库 + 导 enum | `schema.sql` 全表 + `enum_registry`/`enum_values` |
| F1 | 单书 loader 试点（先进遗风） | `books`/`layer_catalog`/`layer_fields`/`items`/`records` |
| F2 | 全量装载六书 | 同上（六行 books + 各自 catalog） |
| F3 | T0–T3 去歧义 | `nodes`/`edges`/`canonical`/`members`/`candidate_links`/`pending_refs` + `enum_drift` | ✅ 已落地 |
| F4 | 查询 MCP / 跨书图谱接口 | 视图 + 可选 `fts_nodes` |

> F3 已于 2026-10-11 落地（见《ELT设计》§3.1、§7）：名字解析为「配置驱动归一化 + 两级接入 +
> 置信度」；`members` 每行带 method+confidence+status，`person`/`official` 等同名异人/泛称
> 风险类型按 `name_rules.json:type_confidence_cap` 封顶，避免误并；查询端按置信度呈现。

> 不先做 T 的原因不变：L（Tier 1）一旦有 bug，T 的对账全是空中楼阁。
> 先让六本书安全地躺在同一个库里互不踩踏，再谈把它们连起来。

## 10. 边界与未决

- **`opn.topic`** 若未来频繁跨书对齐，可把该字段在 `layer_fields` 标 `role='node_ref'`，自动升级为边——示例目录驱动的灵活性。
- **机构（institution）** 目前靠 ent(type=institution) 承载；若某书机构自成体系要独立命名空间，建一个 `kind='node'` 的层即可，无需改表。
- **neo4j** 仍只作导出目标（图遍历性能需求时），主库保持 SQLite。
- **总库是否入 git**：建议 `tools/kb-federation/kb.sqlite` **不入库**（Tier 1/2 全可重建，撞号脚本 + schema + loader 入 git 即可）。
