# 跨书合并方案：古籍联邦知识库（Federated KB）

> 提出：2026-10-11，用户提议「不同书的结果如何合并，需要一个总数据库存储」。
> 状态：**方案待拍板**，尚未写任何代码。
> 一句话定位：**不做大一统本体，做联邦库**——每本书保持自治，总库只负责「隔离、归一、对齐」。

---

## 1. 核心判断：为什么是联邦，不是统一

把六本书硬并成一套 ID、一套 schema，有三条路走不通：

| 障碍 | 实测 | 后果 |
|---|---|---|
| **ID 撞号** | 14302 个 ID 中 **2847 个出现在 ≥2 本书**，ENT 占 2448 | 直接合并会把不同书的不同实体并成一个 |
| **join 结构四态** | `{rows}` / 顶层 list / `{entries}` / `{records:{}}` / `{fingerprints,layers}` | 没有统一入口可直读 |
| **容器键不一** | `events` vs `evts`、`ents`；蘧编另有 `mems`/`chrs` | 层归属需要映射表 |
| **实体类型不统一** | 水东有 `institution`，五杂俎有 `animal`/`plant`/`food` | 类型维度无法直接对齐 |

但**更关键的是代价**：重写 ID 要改所有层产物与全部交叉引用，改完六本书的产物就不再是「可重跑的原文派生物」而成了「被总库污染过的副本」。这违反项目两条铁律——**原文只在指纹库**与**一切可重跑**。

所以：**每本书继续自治，总库在它们之上加一层**。书内 ID 原样保留，总库用复合命名空间隔离。

## 2. 架构：四层

```
┌─ L3 查询层 ────────────────────────────────────────────┐
│  federation-mcp / CLI                                  │
│  cross_search · entity_lookup · timeline · drift       │
└────────────────────────┬───────────────────────────────┘
                         │ 读
┌─ L2 统一存储 ──────────┴───────────────────────────────┐
│  kb.sqlite（单文件，纯标准库，不入库）                  │
│  books · items · layer_records · entities              │
│  entity_alias · entity_links · enum_values             │
└────────────────────────▲───────────────────────────────┘
                         │ 写（幂等）
┌─ L1 装载层 ────────────┴───────────────────────────────┐
│  loaders/kezuozhuiyu.py · wuzazu.py · …                │
│  每书一个适配器，只读原产物 → 归一 → 入库               │
└────────────────────────▲───────────────────────────────┘
                         │ 只读
┌─ L0 书域（现状不动）───┴───────────────────────────────┐
│  kezuozhuiyu-kb/  wuzazu-kb/  shuidongriji-kb/  …      │
└────────────────────────────────────────────────────────┘
```

**L0 不动**是前提。总库对六本书**只读**，任何情况下不回写。

## 3. 四个关键设计决策

### 决策 1：ID 不改，用复合命名空间

```
全局 uid = "{book_id}:{local_id}"
  例：kzz:ENT-0001   wzz:ENT-0001   （互不干扰）
```

- **书内引用保持原样**（`ENT-0001` 仍指本书的实体），零改动、零风险。
- 总库用 `(book_id, local_id)` 复合主键，撞号自然消解。
- **新书（第 7 本起）例外**：由契约线 C2 强制 ID 带书级前缀（如 `XJF-ENT-0001`），天然无撞号。
  → 这正是契约线「把问题挡在写入前」的兑现点，存量撞号则靠本方案兜底。

> 不做 `KZZ-ENT-0001` 这种**改写式**前缀：改一个 ID 要同步改所有引用它的层记录，风险远大于收益。

### 决策 2：每书一个 loader 适配器

六本书的 join 有五种形态，但**只有入口不同，语义相同**（条目 ↔ 各层记录 ↔ 实体）。
每书一个 loader，职责单一：

```python
def load(conn, book_id) -> LoadReport:
    # 1. 读该书 join + 各层产物（只读）
    # 2. 容器键按 layer_map 归一
    # 3. 幂等写：BEGIN; DELETE FROM ... WHERE book_id=?; INSERT ...; COMMIT
    # 4. 回报告：条目数 / 各层记录数 / 未登记层 / 未注册枚举值
```

**幂等靠「先删后插」而非增量合并**——重跑结果永远一致，符合「一切可重跑」铁律。

### 决策 3：层 key 归一表，不硬编码

```json
{
  "events": "evt", "evts": "evt",
  "ents": "ent", "mems": "mem", "chrs": "chr",
  "appts": "appt", "rels": "rel", "trls": "trl",
  "lits": "lit", "nams": "nam", "cits": "cit",
  "objs": "obj", "cuss": "cus", "mings": "ming",
  "opns": "opn", "geos": "geo", "regs": "reg"
}
```

遇到表外键（未来新书的自定义层）→ **登记进 `layer_registry` 表并报 WARN**，不静默丢弃、不硬编码。
这条是对 #27（枚举执行期被就地吸收）的直接反制：**未知的东西必须出声**。

### 决策 4：原文不进总库

```
items 表只存：uid / book_id / item_id / volume / title / fingerprint
              ↑ 指针，不是正文
```

项目铁律：原文只在 `_item_registry.json` 存一份。总库若抄正文，就出现第二份真相源，且必然过期。

- 要正文 → 拿 `(book_id, item_id)` 回原书指纹库取。
- 要全文检索 → 建 **FTS5 派生表**，但明确标注「可重建、不入 git」，与 `_layers/` 同级待遇。

## 4. 存储选型：SQLite

| 选项 | 判断 |
|---|---|
| **SQLite**（推荐） | 量级 ~3400 条目 / ~14k ID / 实体 ~6000，单文件、零第三方依赖（项目铁律）、事务幂等、支持 FTS5 |
| **Neo4j** | 只在要做「跨书人物关系网络遍历」时才有必要；届时作**导出目标**，不作为主库 |
| **纯 JSON 大文件** | 排除——正是现状问题的根源（无约束、无索引、易漂移） |

不引入 ORM 与任何第三方库，`sqlite3` 是标准库。

## 5. Schema 草案

```sql
-- 书级登记（唯一需人工维护的表）
CREATE TABLE books (
  book_id      TEXT PRIMARY KEY,   -- kzz / wzz / sdr / xgg / qb / xjf
  name         TEXT NOT NULL,      -- 客座赘语
  author       TEXT, dynasty TEXT,
  root_dir     TEXT NOT NULL,      -- kezuozhuiyu-kb
  item_total   INT, enum_source TEXT,   -- 单点 _kg_enums.py？还是无单点
  loaded_at    TEXT, source_sha TEXT    -- 产物指纹，用于判断是否需要重跑
);

-- 条目（原文不入库，只存指针）
CREATE TABLE items (
  uid TEXT PRIMARY KEY,            -- book_id:item_id
  book_id TEXT, item_id TEXT, volume TEXT, title TEXT,
  layer_count INT,
  FOREIGN KEY(book_id) REFERENCES books(book_id)
);

-- 各层记录：一张宽表 + payload JSON，避免每层建表
CREATE TABLE layer_records (
  uid TEXT PRIMARY KEY,            -- book_id:local_id
  book_id TEXT, layer_key TEXT, local_id TEXT,
  item_uid TEXT,                   -- 归属条目
  payload  TEXT,                   -- 原记录 JSON 原样保留
  PRIMARY KEY(book_id, local_id)
);

-- 实体（书域，未对齐）
CREATE TABLE entities (
  uid TEXT PRIMARY KEY,            -- book_id:ENT-0001
  book_id TEXT, local_id TEXT,
  normalized TEXT, type TEXT, count INT, first_source TEXT
);

-- 别名索引（跨书对齐的关键线索）
CREATE TABLE entity_alias (
  book_id TEXT, alias TEXT, ent_uid TEXT
);

-- 跨书对齐（本方案最有价值的产物）
CREATE TABLE entity_links (
  canonical_uid TEXT,              -- 归一后的代表 uid
  member_uid    TEXT,              -- 成员 uid
  method TEXT,                     -- exact / alias / manual
  confidence REAL,
  status TEXT                      -- auto / confirmed / rejected
);

-- 枚举取值（把存量线的 drift 体检搬进库里）
CREATE TABLE enum_values (
  book_id TEXT, layer_key TEXT, field TEXT, value TEXT, count INT
);
```

`payload JSON 原样保留`是刻意的：**归一只做索引列，不丢原始信息**。将来 schema 演进不必重跑六本书。

## 6. 跨书对齐：合并的真正价值

合并本身只是搬运，**跨书对齐才是收益所在**——「宋濂在《先进遗风》是 ENT-001，在《水东日记》是 ENT-xxx，在五杂俎里又出现 3 次」。

三阶段，**严格分离自动与人工**：

| 阶段 | 方法 | 产物 |
|---|---|---|
| **A. 精确匹配** | `normalized + type` 完全一致 | `status=auto`, confidence=1.0 |
| **B. 别名匹配** | 交叉 `alias_index`（如「刘忠宣」→ 刘大夏） | `status=auto`, confidence=0.9 |
| **C. 人工确认** | 落 `pending-review` 区（复用现有机制） | `status=confirmed/rejected` |

**明确不做模糊匹配**。古籍重名极多（「王通」「李贤」各有多人），模糊匹配的错误会静默污染全库，且极难回滚。宁可漏，不可错——这与「未知的东西必须出声」是同一条原则。

**时间轴**（可选增益）：蘧编 C12 年谱纪年层有精确纪年（嘉靖三十八年己未 1559），可作跨书时间锚点。设计 `year_start / year_end` 可选字段，有则填，无则空，**不强制**。

## 8. 边界：明确不做

- ❌ **不改任何一本书的产物**（只读，绝不回写）
- ❌ **不重写 ID**（复合命名空间已解决）
- ❌ **不自动合并实体**（只给候选，人工确认）
- ❌ **不把原文搬进总库**（铁律）
- ❌ **不为存量补 `_kg_enums.py`**（那是存量线 P1.5 的事，与本方案解耦）
- ❌ **不引入第三方依赖**

## 9. 与现有两条 MCP 线的关系

```
book-mcp（契约线）  ──► 规定新书格式 ──► 第 7 本起 ID 自带书级前缀
                                            │
                                            ▼
                                    kb-federation（本方案）
                                            ▲
                                            │
kb-mcp（存量线）    ──► 体检六本存量 ──► 撞号/漂移数据可作 loader 输入
```

三条线**职责不重叠**：契约线管未来、存量线管过去、联邦线管「把过去和未来装到一起」。
联邦线**不替代**前两条，也不重复它们的解析——枚举与层定义仍从 line 的 `Skills/00-…/references/` 读。
