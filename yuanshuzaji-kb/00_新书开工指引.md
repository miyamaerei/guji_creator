## 3. 执行（四段式管线）

```
build_base.py 切分 → _extract\NN_卷名.txt + _item_registry.json（指纹库）
   ↓
装填源数据：_src\_<layer>_ai_NN.py（9 层：ent/appt/evt/lit/reg/nam/opn/cus/geo）
   ↓
打包：build_ent_keys → build_appts → build_events → build_lits → build_regs
      → build_nams → build_opns → build_cuss → build_geos → build_kg_join
   ↓
校验：validate_layers.py  → 验收闸门 ERR=0 / GAP=0
```

**执行纪律**（lgs/政学录血泪 + 宛署实测）：
- 源数据（_src 的 .py）**一次 Write 写全文件**——多次 Write 是整体覆盖不是追加（曾 55→5 条）。
- 写完全部源文件**逐文件条数对账**（期望 vs 磁盘），不一致即拦截，再打包。
- **条数口径 = 155 条 = 165 标题 − 10 无正文 ○ 分组**（○山川/经费上/经费下/人物/恩泽/志遗一~五，其后直接 △ 子目不计数；标题 165 全覆盖用于交叉校验，一个不能丢）。
- 卷文件 glob 字典序 ≠ 卷序（中文数字文件名）——build_base.py 用 CN 数组显式映射。
- 志遗卷 72 个 △ 诗文作者标题 = 一作者一条（题名+诗文全文）→ LIT 为主 + NAM 作者名录 + APPT 明示官职。
- 卷三职官单一 ○ 标题下含知县/丞/簿/史四段题名表 → 仍一条（03-001），NAM entries 数组化 + APPT 逐人拆条。
- 打包参数：`python run_all.py '--volumes=NN'`（**单引号整体传参**，防 01→1 截断）。

## 4. 用 MCP 处理问题

| 需求 | 工具 | 命令 |

## 5. 移交 + 联邦库并入

1. **备份**：`kb.sqlite` → `kb.sqlite.bak_YYYYMMDD_<book>`。
2. **存量线**（kb-mcp）：`kb_mcp\registry.py` 登记 book（enum_backend=flat、enum_path=`_kg_enums.py`、globs `_layers/*/*.json`）；`adapters.py` 按需扩展 `_TYPE_FIELDS`/路径。
3. **联邦线**（kb-federation）：写 `adapters\ysz_adapter.py`（book_id=ysz；`_layers\<key>\<key>_NN.json` 子目录形态；ent 按 ent_id 跨卷去重；**id_key 与层产物实际字段名一致**——xzl 曾误用 evt_id 实为 event_id 致 50 折叠）；注册 BOOK_REGISTRY；跑 `load → transform → refs`。
4. **裁决**：`fed_conflicts` 拉清单 → 批量 lock/reject → `replay_overrides` 重放；审计留 `override_log`。
5. **学习回路**：`registry.md` 状态更新；`pending-review` 新值提案。

## 6. 枚举入库（走评审，双写）

新枚举值（如宛署 REG 增量 民政救济/宫禁内府）入库流程：
1. 先入 `pending-review.md`（附证据：条数/分布）。
2. 评审三条件：**跨书复用 + 归并优先 + 用户确认**。
3. 双写：`enum-library.md` 加段 + 顶部版本 +1；`enum-changelog.md` 追加版本条目。缺一即野分支。
4. 入库后复跑 `drift` 验证护栏恢复。
