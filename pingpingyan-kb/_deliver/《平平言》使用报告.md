# 《平平言》使用报告

> 生成日期：2026-10-13 ｜ 适用读者：后续接手者 / 需要查询这套知识资产的人
> 一句话：清·方大湜《平平言》（官箴书，四卷 284 条）→ 一套可查询、可溯源、可重跑的 5 层知识库。

---

## 1. 项目定位

本项目为清代官箴书《平平言》（巴陵方大湜菊人著，四卷正文 + 序/凡例/跋）的数字化知识工程。从 EPUB 原文出发，按用户锁定口径（规则型 7 层方案裁剪为 5 层：实体 / 规则 / 结构化四维 / 制度 / 论说），逐条产出机器可读、可交叉引用的结构化知识：

```
EPUB/原文 → 条目切分 284 → 实体标注 → 规则层 → 结构化四维 → 制度层 → 论说层 → 跨层索引
```

所有层遵循同一口径：**AI 逐条判定、代码只验缺漏、条粒度、original 指纹注入、每卷独立 JSON + 全局归一、枚举封闭治理、全文本内生词典**。白话文仅作对照引用源（用户口径，不建翻译层）；序/凡例/跋归 00 卷不入条目库。

## 4. 怎么使用

### 4.1 快速查询（不跑代码）
- **一行看全某条**：打开 `_deliver\跨层索引_kg_join_flat.csv`，按 item_id 过滤 → 五层 ID 平铺一列 + layer_count。
- **查实体**：`_global\ent_keys.json` → normalized/ent_id；`_global\alias_index.json` 支持"词形 → 实体 ID"反查；实体详情在 `_deliver\ent_归一汇总.json`。
- **查规则/结构/制度/论说**：对应 `_deliver\<层>_归一汇总.json`（含 item_id / evidence / original / 枚举类型）。

### 4.2 全文回查（溯源）
任何一条记录的 `item_id` → `_item_registry.json` 对应条目 `original` 原文；`evidence` 字段逐字命中原文词形（GAP 纪律）；引用字段（如 OPN 的 evidence_refs）→ 对应实体名。

### 4.3 可重跑管线（改了数据后全量重建）
```powershell
cd E:\git\ToolBox\guji\pingpingyan-kb
python run_all.py --skip-baseline          # 全卷五层打包 + kg_join + 校验（支持 --volumes 单卷）
python build_kg_join.py                    # 跨层索引全量重建（284 条）
python validate_layers.py                  # 全量校验（284 全覆盖闸门，不带 --skip-baseline）
python _kg_aggregate_deliver.py            # 重新聚合 _deliver/
```
每层跑完核对 `_validate\验证缺漏清单.txt` 问题数 0。

### 4.4 扩展指南
- **加实体词条**：编辑 `_src\_ents_ai_<卷>.py`（词条 text/evidence 必须逐字命中原文词形）→ `python run_all.py --volumes <卷>`。
- **加规则/结构/制度/论说**：编辑对应 `_src` 源文件，按 schemas.md 字段编写 → 重跑对应打包器。
- **新枚举值**：`_kg_enums.py` 单点修改 + version+1，重跑受影响层；跨书新值须走工厂 pending-review 决议。

## 5. 关键设计（为什么要这样做）

1. **original 不手抄**：AI 源数据只写条号/解读，打包器从指纹库注入原文 → 杜绝手抄漂移。
2. **条粒度锚点**：item_id（NN-NNN）是所有层的共同主键；跨层索引 layer_count 直接告诉你该条贯通了几层。
3. **枚举单点治理**：类型/模态全部收进 `_kg_enums.py`，新增必须 version+1 回填存量。
4. **修复并入打包器**：kg_join 浅拷贝串数据、struct 占位 target 等 P0 修复已并入生成器，重跑不丢。
5. **实体主键全局顺序**：ENT-0001 起跨卷去重复用（如"汪龍莊"跨卷共用主键），alias_index 反查。
6. **结构化四维封闭**：ACT/FRD/LGR/TME 各 *_TYPES 封闭枚举，新值走 pending 决议。
