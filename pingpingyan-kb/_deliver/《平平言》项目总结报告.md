# 《平平言》项目总结报告

> 生成日期：2026-10-13 ｜ 项目：《平平言》数字化知识工程
> 一句话：从 EPUB 原文到一套 5 层可溯源、可重跑、可交叉引用的官箴书知识资产（284 条目 / 1160 条层记录）。

## 0. 项目概述

清·方大湜《平平言》数字化工程，按用户锁定口径推进：

- **AI 逐条判定 + 代码只验缺漏**（判定与验证严格分工）
- **条粒度**（按条目切分 284 条；序/凡例/跋归 00 卷，用户否决纳入条目库）
- **original 指纹注入 + 引用关联**（AI 源数据不手抄原文，GAP 纪律逐字命中）
- **每卷独立 JSON + 全局归一**（先分卷产出，再归一并验证）
- **枚举顶层封闭 + 动态回填**（`_kg_enums.py` 单点，V1.0）
- **词典全文本内生**（用户明确否决外部词典抓取）

用户拍板：规则型 7 层方案裁剪为 **5 层**（实体 / 规则 / 结构化四维 / 制度 / 论说），**不建** L3流程/L5事件/DOC/REL/CIT/TRL；白话文仅作对照引用源；实体主键全局顺序（ENT-0001 起）。最终形成**底座 + 5 层知识资产**：实体层 → 规则层 → 结构化四维层 → 制度层 → 论说层 → 跨层索引。

## 2. 反思结论

### 反思一（多卷装填节奏）
核心结论：按卷分批装填 + 每卷独立打包验证（--volumes 单卷跑）比一次性全量装填更稳：问题在卷内即暴露（卷一 3 类问题、卷二词形纪律），避免全量失败定位困难；`--skip-baseline` 用于中间态，收尾必须不带该参数做 284 全覆盖闸门。

### 反思二（跨层索引覆盖检查）
核心结论：**不能只信 validate 绿灯**——kg_join 每卷 build 是重建全文件（非增量），多卷参数在 PowerShell 下会被拆参（`01,02,03,04` → 解析异常返回 0 条），收尾必须：缺省模式跑 `build_kg_join.py` → 回读 JSON 抽查 by_vol / layer_count 分布 / 0 空条目率。

## 3. 根因分析：为什么"重复很多次无用读取"

诚实复盘，重复读取有 3 类根因：

1. **上下文压缩后的 schema 重读（半可控）**：长任务中 SKILL.md/schemas 被压缩，续做须先 Read 再构造字段；改进：schema 关键字段（键名/枚举/ID 规则）固化进 summary 与报告。
2. **PowerShell 参数语义（失误）**：逗号分隔参数被 PowerShell 拆成数组传给原生 exe，`--volumes 01,02,03,04` 静默变成非法值（0 条回填而非报错）；改进：多卷参数用引号包裹或走缺省模式，回读产物核对条数。
3. **产物覆盖回归导致的重复验证（半可控）**：kg_join 每卷重建全文件，部分装填期先跑的卷被后跑卷覆盖；改进：修复并入生成器（缺省=全卷）、验证写 .py 脚本重定向到文件再读、收尾一次全量重建。

## 4. 方法论沉淀（下次遇到任务的处理原则）

1. **一次探查**：开工前读完全部输入 + schema 样例 + 统计；连续两次读取不再改变计划即停止探查。
2. **先锁 schema 再写数据**：字段口径、枚举、ID 规则一次性定死；打包器注入指纹/关联/校验。
3. **AI 判定与代码验证严格分工**：判定逐条人工（AI）；代码只验缺漏。
4. **所有生成器正式化**：build_ 前缀 + 可重跑 + 幂等；修复并入生成器。
5. **验证一次到位**：校验脚本写文件输出；收尾校验必须跑 284 全覆盖闸门（不带 --skip-baseline）。
6. **枚举单点治理**：新增枚举值 version+1 并回溯存量（registerVersion 模式）；键位中英/繁简逐字对照 `_kg_enums.py`。
7. **词形 GAP 纪律**：text/evidence 必须逐字命中指纹库 original，不得用通称/变体。
8. **交付按层聚合**：每层一组（归一汇总 + 验证清单 + 跨层索引）；回读 JSON 抽查 layer_count 与空条目率，不轻信绿灯。
9. **每轮任务建 task 清单**：阶段可见、完成可核。
10. **如实报告缺口**：哪里缺、缺什么、补什么方案，不静默降级。
