## 1. 项目定位

本项目为〔一本书〕——《〔书名〕》（〔体裁/性质简介〕）——的〔目标：通读/抽取/建库〕数字化知识工程。从〔原始格式〕出发，逐层产出机器可读、可交叉引用的结构化知识：

```
〔原始格式〕 → EPUB/章节 → 实体标注 → 规则层 → 流程层 → 结构化层 → 事件层 → 跨层索引
```

所有层遵循同一口径：**AI 逐条判定、代码只验缺漏、条粒度、original 指纹注入、每卷独立 JSON + 全局归一、枚举封闭治理、全文本内生词典**。

## 4. 怎么使用

### 4.1 快速查询（不跑代码）
- **一行看全某条**：打开 `_kg_join_flat.csv`，按 item_id 过滤 → 各层 ID 平铺一列。
- **查实体**：`〔实体_主键表.json〕` → entities[]（normalized/type/count/first_source/surfaces/ent_id）；alias_index 支持"词形 → 实体 ID"反查。
- **查规则/事件/流程/结构**：对应层 `归一_汇总.json`（字段清单按实际）。

### 4.2 全文回查（溯源）
任何一条规则/流程/事件/结构的 `original` 字段 = 指纹库原文；`item_id` → 章节对应条目；引用字段 → 对应层 ID。

### 4.3 可重跑管线（改了数据后全量重建）
```powershell
〔按实际列出 build_ 脚本顺序，每层跑完核对"验证缺漏清单.txt"问题数 0 与归一汇总总数，支持 --volumes 单卷重跑〕
```

### 4.4 扩展指南
- **加实体词条**：〔标注脚本 LEX 词典（词条必须出现在原文）→ 重跑管线；新增枚举类型需枚举文件 version+1 并回填存量〕
- **加规则/流程/结构/事件**：〔对应源数据文件，按 schema 编写（original 不手抄，交打包器注入）→ 重跑对应打包器〕
- **解读词形 join**：〔主键表 alias_index 手工加映射（不动标注）〕
- **新枚举值**：〔枚举文件单点修改 + version+1，重跑受影响层〕

## 5. 关键设计（为什么要这样做）

1. **original 不手抄**：AI 源数据只写条号/解读，打包器从指纹库注入原文 → 杜绝手抄漂移。
2. **条粒度锚点**：item_id（NN-NNN）是所有层的共同主键；引用字段让层间可跳转。
3. **枚举单点治理**：类型/模态/机制全部收进枚举文件，新增必须 version+1 回填存量。
4. **修复并入打包器**：P0 修复写进生成器，重跑不丢。
5. **跨层索引一行全看**：layer_count 直接告诉你该条贯通了几层。
