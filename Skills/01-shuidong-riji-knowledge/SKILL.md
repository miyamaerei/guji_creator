## 1. 执行流程总览

按序执行，每阶段收尾对照工厂 checklists：

```
查卷阅读模式(volume-profile) → 底座（38卷拆分 + 指纹库） → 启用层逐层抽取（按卷模式分配优先级；AI 判定 + 词典规则候选 + 代码验证） → 跨层整合 → 交付
```

## 1.1 实现效率（如何减少重复性工作，用户强调最重要）

> 全书 13.3 万字符、38 卷、8 层并行，重复工作四来源：重复读原文 / 重复建实体 / 重复写记录 / 重复验证。对策总纲：**一次做好，处处复用**。详见 `references/execution-efficiency.md`（十要点 + 每卷自检清单 + 反模式）。核心十要点：

1. **底座只做一次**：条目切分 + 指纹库一次完成，8 层共用；AI 源数据只写条号+解读，永不手抄原文（original 打包器注入）
2. **实体先查后建**（最重要）：执行任一卷前查已建 ENT 主键表，已存在直接引用 ID，不存在才新建；alias_index 随卷累积——避免高频实体（御史/尚书/指挥等）重复建 ID
3. **词典+规则先行**：复用明朝职官词典作候选，AI 只判边界；按卷模式决定层优先级，不无差别全层扫
4. **层间复用**：先做 L1 全量标注，其他层引用 ENT ID；NAM 题名→APPT 任职、REL 从事件带出，共享证据
5. **生成器正式化**：build_ 前缀 + 幂等 + 可重跑（run_all.py / --volumes NN），修复并入生成器不落散文件
6. **枚举单点**：_kg_enums.py 一个文件管全部枚举，新增值 version+1 回溯存量
7. **验证脚本化**：一套验证脚本每卷跑一次，问题数=0 才进下一卷；先试点 1 卷跑通固化，再铺开
8. **卷序流水线**：强信号卷优先（制度 05/06/30、名录 17/29、谱牒 18）；卷内按模式先抽强信号层
9. **示例条目当模板**：schemas.md 示例 A~E（五种形态）直接对照书写
10. **分步交付防返工**：--volumes 按卷执行，用户确认一卷口径再铺开其余

## 2. 底座（公共地基，先做）

1. 输入文件：`assets/sources/水东日记.txt`（UTF-8 文本，约 13.3 万字符；随本技能存放的相对路径）；处理路径：直接拆分（无需 OCR/转码）
2. 章节划分：38 卷 + 卷 00（四库提要+版本说明）；每卷一个 XHTML/MD，命名 `NN_卷名.xhtml`
3. 条目切分：每条记事/引文为一条（含整卷抄录的圣旨/碑文/长文各算一条）；→ `_extract\NN_卷名.txt`（格式 `条N|正文`），预计 350–500 条
4. 指纹库 `_item_registry.json`：key=`NN-NNN`，value=original/norm；norm 归一规则：异体/缺字（□、〔〕注）保留原样但记 norm 归一、全角空格与换行折叠、去除卷首卷尾装饰行
5. 全部条目建 task 清单（阶段可见、完成可核）
6. **卷阅读模式先行**：执行任一卷前，先查 `references/volume-profile.md` 该卷的阅读模式（制度优先/人物优先/文献优先/谱牒优先/名录优先/文事优先/均衡全层），按模式分配该卷的抽取优先级与方式（详见 §8.3）

## 2.1 卷阅读模式索引（VOL 机制，用户提出）

- 定义：38 卷逐卷标注"主导内容类型 / 次要类型 / 阅读模式"，作为卷级启发式处理指引（不是条目级数据层，不占 ID 命名空间）
- 数据：固化于 `references/volume-profile.md`（2026-10-10 抽样判定，38 卷标注表 + 7 种阅读模式的处理指引）
- 阅读模式枚举（封闭 + 兜底）：`制度优先` / `人物优先` / `文献优先` / `谱牒优先` / `名录优先` / `文事优先` / `均衡全层`
- 使用：执行某卷前查模式 → 按其"处理重点"分配层优先级；卷完成后对照"主导/次要类型"检查覆盖缺口；发现与卷内实际不符 → 以实际为准回填修正本表（registerVersion）

## 3. 实体层方案（L1，确认启用）

- 实体类型枚举（从本书文本归纳，封闭 + 兜底 `unknown`）：
  `person`(人物) / `official`(职官名) / `institution`(机构衙门) / `place`(地名) / `era`(年号朝代) / `posthumous`(谥号) / `work`(书名文献名) / `unknown`
- 种子词典规则（全文本内生，词条必须出现在原文，否则自动剔除）：
  - 职官词典：御史/尚书/侍郎/给事中/都督/巡抚/知府/同知/翰林/编修/检讨/郎中/主事/布政/按察等（从密度信号归纳）

  - 正则辅助：`〔人名〕为/任/授/擢/迁/除〔官职〕` 模式标注
- 归一规则：异体/同义/复合词形（如"户部尚书致仕丹阳沈固"→沈固=person、户部尚书=official、丹阳=place）用 alias_index 手工映射，不动标注
- 主键表：ENT-001..N + alias_index（词形 → ent_id 反查）
- 每卷 JSON + 全局归一 `归一_汇总.json` + 标注总报告

- 文献类型枚举（封闭+兜底）：`诏敕圣旨` / `碑文` / `奏议` / `书启` / `诗` / `记` / `题跋` / `序` / `祭文` / `其他`

## 8. 人物关系网络方案（自定义，确认启用）

- ID 前缀：`REL-`（Relation）
- 定义：人物-人物二元关系（含方向性与证据）
- schema 槽位：rel_id / item_id / person_a(含 ent_ids) / person_b(含 ent_ids) / relation_type(关系类型枚举) / direction(单向/双向/未明) / evidence(关系证据摘要) / original(打包器注入)
- 关系类型枚举（封闭+兜底）：`同僚` / `师生` / `姻亲` / `同乡` / `同科` / `举荐` / `弹劾` / `恩怨` / `上下级` / `父子亲属` / `敌对` / `其他`
- 执行注意：只建文本有直接证据的关系；推测关系不建，宁缺毋滥

## 8.1 名录谱牒维度方案（NAM 结构分类，自定义，确认启用）

- ID 前缀：`NAM-`（Name roster / Genealogy）
- 定义：承接书中的表格式名录与谱牒内容——官员题名、同僚题名、迁谪录、族谱家谱话题
- 名录类型枚举（封闭+兜底）：`官员题名` / `同僚题名` / `迁谪录` / `谱牒`(族谱家谱) / `题名记` / `其他`
- schema 槽位：nam_id / item_id / name(名录名) / category(类型枚举) / scope(范围：机构/地域/官职/科名) / entries(名录条目数组，见下) / ent_ids(涉及实体) / original(打包器注入)
- **entries 条目结构**（表格式名录四元组）：`{ "seq": 序号, "person": 人名, "courtesy_name": 字(无则"未明"), "hometown": 籍贯(无则"未明"), "office": 官职(无则"未明") }`——对应"六科旧僚题名"的姓名/字/邑里/官位结构
- 典型样本：卷十七"都御史题名"（天顺/景泰末年，按左/右/副/佥都御史分列）、"两广方岳郡守题名"（按都司/都指挥使/同知/佥事分列）、"御史迁谪录"；卷二十九"六科旧僚题名"（序文+按科分列）
- 执行注意：表格式名录整体为一条 NAM 记录（entries 数组化）；书信/叙事中仅提及族谱而无完整谱牒表者，建 NAM 记录登记话题（entries 空数组 + evidence 注明），不强行展开

## 8.2 古今翻译层方案（TRL 自定义，确认启用）

- ID 前缀：`TRL-`（Translation）
- 定义：全书条目古文 → 现代汉语译文，供理解、检索与图谱注释使用
- schema 槽位：trl_id / item_id / translation(现代译文全文) / style(翻译风格枚举) / note(翻译说明：难点/异文/专名处理) / confidence / original(打包器注入)
- 翻译风格枚举（封闭+兜底）：`直译`（贴近原文句序）/ `意译`（按现代语序重述）/ `注释性翻译`（直译+括注专名/典故，**默认风格，参照余光中风格**）
- **翻译风格基准（用户指定：参考余光中风格）**：遵循 `references/translation-style.md` 七条规范——译原意不译原字 / 主从改并联（长句拆短句）/ 白以为常文以应变 / 精简防冗余 / 善用四字格 / 忌翻译体公式 / 专名保留+括注（忠实与可读的妥协）；交付前对照该文件 §3 校验清单自查
- 翻译规范（与风格基准配套）：专名（人名/职官/机构/地名/年号）保留原词，首次出现可括注今释；职官名遵循明史职官术语（如"都御史"不译作"都察院院长"）；缺字/异体按 norm 归一后再译；长文（圣旨/碑文/长记）分句群翻译并保留分段；诏敕圣旨等格式文献如需保留原文格式，在 note 说明偏离理由
- 交付形态：每卷译文 JSON（TRL 记录）+ 全书记译文本（现代文版本，卷为单位的 .md/.txt）
- 执行方式：与各层同步逐条翻译；支持 `--volumes` 按卷分步；翻译质量由 AI 逐条完成，代码只验覆盖（条目数=翻译数）
