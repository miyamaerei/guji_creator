# 执行效率手册：如何减少重复性工作（《水东日记》38 卷实现）

> 本手册回答"全文很长，如何减少重复性工作"。核心一句话：**一次做好，处处复用——底座做一次、实体建一次、生成器跑一套、验证过一遍，其余全部引用与复用，不重复造。** 执行任一卷前通读本手册；与 volume-profile.md（卷模式）配套使用。

## 0. 重复工作的四个来源（先诊断再防）

| 来源 | 症状 | 对策 |
|---|---|---|
| 重复读原文 | 每层各读一遍全文，翻译又读一遍 | 底座 `_item_registry.json` 一次切好，各层从指纹库取 original；AI 源数据只写条号+解读，永不重抄 |
| 重复建实体 | 同一人物/职官/机构跨卷出现（御史 115 / 尚书 98 / 指挥 81……），每卷重标一遍 | 实体主键**先查后建**，全局唯一；alias_index 随卷累积 |
| 重复写记录 | 每卷手写同类 JSON，字段/枚举凭记忆 | 示例条目当模板 + build_ 生成器统一产出 + 枚举单点文件 |
| 重复验证 | 每卷人工核对格式/引用/覆盖 | 验证脚本一次写好，每卷只跑一条命令 |

## 1. 十要点（按执行顺序）

### ① 底座只做一次，全程共享
- 条目切分 + `_item_registry.json`（original/norm）一次性完成，**全部 8 层从同一指纹库注入原文**。
- AI 源数据只写条号 + 解读字段，不手抄原文——省一半书写量，且杜绝漂移（修正以指纹库为准）。

### ② 实体主键先查后建（最重要的一条）
- 执行任一卷前，先查已建 ENT 主键表（`_ent_keys` / alias_index）：同一人/机构/职官是否已存在。
- **已存在 → 直接引用 ENT ID；不存在 → 才新建**。避免"叶盛""都御史"这类高频实体出现几十个重复 ID。
- alias_index 随卷累积：新词形映射到旧 ID，不动旧标注（如"毘陵胡公"→"胡濙"）。

### ③ 词典 + 规则先行，AI 只判边界
- 复用明朝职官词典与高频术语表作候选提示（ming-officials-kg 词典可作种子），AI 复核候选、补漏判——把"全文逐字识别"降为"候选确认"。
- 卷阅读模式（volume-profile.md）决定哪些层优先，不无差别全层扫（制度卷先 REG，名录卷先 NAM）。

### ④ 层间复用判定结果
- **先做 L1 实体全量标注**，APPT/REG/NAM/REL 全部引用 ENT ID，不再重复标。
- NAM 题名条目 → APPT 任职直接提取（共享证据，见试点 D）；REL 关系从 APPT/事件中带出；TRL 译文与各层抽取同步产出，不单独重读原文。

### ⑤ 生成器正式化：build_ 前缀 + 幂等
- 所有产出走打包器（build_base / build_ent_keys / build_appt / build_event / build_reg / build_lit / build_rel / build_nam / build_trl / build_kg_join），**可重跑、幂等**。
- 修复并入生成器，不手工改散文件；全量重跑 = `python run_all.py` 一条命令；单卷 = `--volumes NN`。

### ⑥ 枚举单点治理
- `_kg_enums.py` 一个文件管全部枚举（实体类型/任职状态/事件类型/制度/文献/关系/名录/翻译风格/ID 前缀）。
- 新增值 version+1 回溯存量；各卷不各自定义枚举，杜绝口径漂移。

### ⑦ 验证脚本化，先跑通再铺开
- 一套验证脚本（覆盖/格式/引用/枚举/对齐），每卷完成只跑一次，**"验证缺漏清单"问题数 = 0 才进下一卷**。
- 先试点 1 卷（建议卷一，均衡全层）跑通全流程、固化生成器，再按卷推进。

### ⑧ 卷序与流水线
- 卷间互不依赖（仅实体主键累积）→ 按"主键表滚动共享"流水线推进；强信号卷优先（制度 05/06/30、名录 17/29、谱牒 18），最易核验、最易暴露生成器缺陷。
- 同一卷内：按卷模式先抽强信号层，弱信号层最后补。

### ⑨ 示例条目当模板
- schemas.md 示例 A~E（制度条/事件条/文献条/名录条/关系条五种形态）是每卷书写的直接对照，字段/枚举不必每次重想。

### ⑩ 分步交付防返工
- `--volumes` 按卷分步执行，每卷交付前对照 volume-profile.md 检查覆盖缺口。
- 用户确认一卷口径后再铺开其余，避免全量做完才发现口径要改（工厂坑#8 粒度返工教训）。

## 2. 每卷执行自检清单（开卷前 → 收卷后）

**开卷前**
- [ ] 已查 volume-profile.md 该卷阅读模式 → 确定本卷层优先级
- [ ] 已查实体主键表 → 本卷预计新实体清单（避免重复建）
- [ ] 已确认本卷强信号层（按模式）与生成器可用

**收卷后**
- [ ] 各层源数据只含条号+解读（无手抄原文）
- [ ] 打包器重跑通过，注入 original/norm/ID
- [ ] 验证脚本"验证缺漏清单"问题数 = 0
- [ ] 新实体已并入主键表与 alias_index（供后续卷复用）
- [ ] 对照卷模式主导/次要类型检查覆盖缺口（如名录卷 NAM 全覆盖）
- [ ] TRL 按余光中风格七条规范自查（translation-style.md §3）

## 3. 反模式（避免）

- ❌ 每卷从头重新标注实体 → ✅ 先查后建
- ❌ 每层独立重读原文 → ✅ 指纹库注入
- ❌ 手写散文件再修 → ✅ 修复并入生成器重跑
- ❌ 各卷自己定义枚举 → ✅ 单点文件 + version
- ❌ 一卷做完全部层再进下一卷（无流水线）→ ✅ 按卷模式分优先层滚动推进
- ❌ 全量做完才给用户看 → ✅ 分卷交付、先确认口径
