# 《水东日记》实例 schema 与 ID 规范

> 本实例（shuidong-riji-knowledge）启用层 schema。写源数据、打包器、验证脚本时对照本文。
> 已锁定启用层：L1 实体 / APPT 职官任职 / L5 事件 / REG 典章制度 / LIT 文献资产 / REL 人物关系 + 跨层索引。
> 未启用层（L2 规则、L3 流程）无任何 schema 残留。

## 1. 全局约定



* **条粒度主键**：`item_id = NN-NNN`（卷 - 序，如 `01-001`），全书唯一，是所有层的共同锚点。

* **ID 命名空间**（每层唯一前缀，禁止跨层占用）：



| 层    | 前缀         | 示例        |
| ---- | ---------- | --------- |
| 实体主键 | `ENT-`     | ENT-001   |
| 职官任职 | `APPT-`    | APPT-001  |
| 事件   | `SDJ-E-`   | SDJ-E-001 |
| 典章制度 | `REG-`     | REG-001   |
| 文献资产 | `LIT-`     | LIT-001   |
| 人物关系 | `REL-`     | REL-001   |
| 名录谱牒 | `NAM-`     | NAM-001   |
| 古今翻译 | `TRL-`     | TRL-001   |
| 跨层索引 | `_kg_join` | —         |

> SDJ-E 命名空间只属事件层；其他层只引用事件 ID，不占用。



* **original 不手抄**：AI 源数据只写条号与解读字段；打包器从 `_item_registry.json` 注入 `original`/`norm`。

* **判定方式**：词典 + 规则先行候选 → AI 逐条判定 → 人工校验闭环；代码只验缺漏，不代行判定。

## 2. 底座 schema

### `_item_registry.json`（指纹库）



```
{
  "01-001": { "original": "原文全文", "norm": "归一化后的原文" }
}
```



* `norm`：异体字 / 缺字 / 标点归一；比对与检索用。

* 章节文件：每卷一个 XHTML/MD，命名 `NN_卷名.xhtml`；卷 00 为四库提要 + 版本说明。

## 3. L1 实体层 schema

### 实体类型枚举（封闭 + 兜底）

`person`(人物) / `official`(职官名) / `institution`(机构衙门) / `place`(地名) / `era`(年号朝代) / `posthumous`(谥号) / `work`(书名文献名) / `unknown`(类型待定)

### 每卷标注 JSON



```
{
  "volume": "01",
  "annotations": [
    {
      "id": "ENT-001", "item_id": "01-001", "text": "礼部尚书",
      "type": "official", "start": 24, "end": 28,
      "normalized": "礼部尚书", "confidence": 0.97, "source": "原文片段"
    }
  ]
}
```



* `start/end`：在原文中的字符偏移，用于定位与去重。

### 归一汇总 + 主键表



```
{
  "normalized_inventory": [
    { "normalized": "礼部尚书", "type": "official", "count": 1, "first_source": "01-001", "surfaces": ["礼部尚书"] }
  ],
  "entities": [
    { "ent_id": "ENT-001", "normalized": "礼部尚书", "type": "official", "count": 1, "first_source": "01-001", "surfaces": ["礼部尚书"] }
  ],
  "alias_index": { "礼部尚书": "ENT-001" }
}
```



* `alias_index`：词形 → ent\_id 反查；复合解读词形（如 "户部尚书致仕丹阳沈固"→ 沈固 = person / 户部尚书 = official / 丹阳 = place）手工加映射，不动标注。

* 种子词典：全文本内生（词条必须出现在原文，否则自动剔除）；职官词典（御史 / 尚书 / 侍郎 / 给事中 / 都督 / 巡抚 / 知府 / 同知 / 翰林等）+ 人物词典（叶盛 / 三杨 / 王振 / 姚铣 / 季聪 / 徐元玉等）+ 正则辅助（`〔人名〕为/任/授/擢/迁/除〔官职〕`）。

## 4. APPT 职官任职维度 schema（自定义）

### 任职状态枚举（封闭 + 兜底）

`现任` / `致仕` / `升迁` / `贬谪` / `罢黜` / `兼领` / `暂代` / `追赠` / `未明`



```
{
  "appointment_id": "APPT-001", "item_id": "01-004",
  "person": { "text": "汪澄", "person_ent_ids": ["ENT-010"] },
  "office": { "text": "巡按御史", "official_ent_ids": ["ENT-005"] },
  "institution": { "text": "福建（巡按）", "ent_ids": ["ENT-020"] },
  "when": "正统十三年", "status": "现任",
  "evidence": "巡按御史汪澄将至延平",
  "original": "（打包器注入）", "confidence": 0.92
}
```



* 词典 + 规则先行：任职动词词典（授 / 擢 / 迁 / 改 / 除 / 罢 / 谪 / 致仕 / 兼 / 领 / 督 / 巡抚 / 提督 / 坐 / 贬）+ 官职词典 → 正则候选 → AI 复核。

* 一条目多个任职 → 拆多条记录共享 item\_id；时间未明写 `"未明"`。

## 5. L5 事件层 schema

### 事件类型枚举（封闭 + 兜底）

`朝政` / `政变` / `军事` / `边事` / `人事任免` / `弹劾` / `礼仪` / `科举` / `文事` / `建言` / `灾异` / `轶事` / `祭祀` / `经济` / `其他`



```
{
  "event_id": "SDJ-E-001", "item_id": "01-001",
  "type": "礼仪",
  "who": { "text": "礼部鸿胪寺及科道导驾等官", "who_ent_ids": ["ENT-003","ENT-004"] },
  "action": "导驾陞奉天殿受朝",
  "what": "冬至正旦节早朝仪节：入左掖门→中左门→华盖殿→奉天殿受朝",
  "when": "冬至正旦节早", "where": "左掖门→中左门→华盖殿→奉天殿"
}
```



* 未明字段必须显式写 `"未明"`，不省略。

* 执行方式：试点 1 卷验收（卷一首卷）→ 全量；未建模条目如实单列缺口。

## 8.1 NAM 名录谱牒维度 schema（结构分类，自定义）

### 名录类型枚举（封闭 + 兜底）

`官员题名` / `同僚题名` / `迁谪录` / `谱牒` / `题名记` / `其他`



```
{
  "nam_id": "NAM-001", "item_id": "17-002",
  "name": "都御史题名（天顺、景泰末年）",
  "category": "官员题名",
  "scope": "都察院·都御史（左/右/副/佥都御史）",
  "entries": [
    { "seq": 1, "person": "杨善", "courtesy_name": "未明", "hometown": "未明", "office": "左都御史（天顺）" },
    { "seq": 2, "person": "萧维祯", "courtesy_name": "未明", "hometown": "未明", "office": "左都御史（天顺）" },
    { "seq": 58, "person": "李实", "courtesy_name": "未明", "hometown": "未明", "office": "右都御史（景泰末年）" }
  ],
  "ent_ids": ["ENT-xxx"],
  "original": "（打包器注入）", "confidence": 0.95
}
```



* 表格式名录整体为一条 NAM 记录，`entries` 数组化（姓名 / 字 / 籍贯 / 官职四元组，对应六科旧僚题名结构）。

* 分列小标题（如 "左都御史"" 右都御史 ""佥都御史"）作为每行的 `office` 上下文。

* 书信 / 叙事中仅提及族谱而无完整谱牒表者：建 NAM 记录登记话题，`entries` 为空数组，`evidence` 注明；不强行展开。

## 8.2 TRL 古今翻译层 schema（自定义）

### 翻译风格枚举（封闭 + 兜底）

`直译`（贴近原文句序）/ `意译`（按现代语序重述）/ `注释性翻译`（直译 + 括注专名 / 典故，**默认风格，参照余光中风格**）

### 翻译风格基准（用户指定：参考余光中风格）



* 执行 TRL 必读 `references/translation-style.md`：七条规范（译原意不译原字 / 主从改并联 / 白以为常文以应变 / 精简防冗余 / 善用四字格 / 忌翻译体公式 / 专名保留 + 括注）+ 校验清单，交付前逐条自查。



```
{
  "trl_id": "TRL-001", "item_id": "01-001",
  "translation": "冬至、正旦两节清晨，礼部、鸿胪寺以及六科给事中、都察院御史等导驾官员最先进入左掖门，至中左门站立等候。天将亮时，趋步走进华盖殿前穿廊：礼部尚书行祭祀礼、复命，礼毕，引导圣驾升奉天殿受朝。曾记毗陵胡公（礼部尚书胡濙）奏尚书事（“尚”音“上”），其奏疏结尾“行礼毕，请上位看马”两句，大声直说，不算奏事。",
  "style": "注释性翻译",
  "note": "余光中风格：长句拆并联短句；毗陵胡公括注今释；科道=六科给事中与都察院御史；【尚音为上】为原书注音，译文括注",
  "confidence": 0.93,
  "original": "（打包器注入）"
}
```



* 专名（人名 / 职官 / 机构 / 地名 / 年号）保留原词，首次出现可括注今释；职官名遵循明史职官术语。

* 缺字 / 异体按 norm 归一后再译；长文（圣旨 / 碑文 / 长记）分句群翻译并保留分段；诏敕圣旨如需保留原文格式，在 note 说明偏离理由。

* 交付：每卷译文 JSON（TRL 记录）+ 全书记译文本（现代文版本，卷为单位）。

* 翻译质量由 AI 逐条完成；代码只验覆盖（条目数 = 翻译数）。

## 9. 跨层索引 schema



```
{
  "item_id": "01-004",
  "volume": "01", "source": "原文",
  "ents": ["ENT-010","ENT-005","ENT-012"],
  "appts": ["APPT-001"], "events": ["SDJ-E-002"],
  "regs": [], "lits": [], "rels": ["REL-001"],
  "nams": [], "trls": ["TRL-004"],
  "layer_count": 5
}
```



* 扁平 CSV 同字段平铺一行，`layer_count` = 贯通层数（ents/appts/events/regs/lits/rels/nams/trls 非空计数；TRL 全量逐条，通常计入）。

## 10. 枚举治理（registerVersion 模式）



* 所有枚举（实体类型 / 任职状态 / 事件类型 / 制度类型 / 文献类型 / 关系类型 /**名录类型**/**翻译风格**/ID 前缀）收进单文件 `_kg_enums.py`。

* 枚举值带 `version`；**新增值必须 version+1 并回溯全部存量数据**，不允许静默扩容。

* 口径漂移检测：注释 / 文档中的枚举数与代码一致，验证脚本比对。

## 12. 试点结论



* 三示例条目字段 / 枚举 / ID 无硬伤，schema 可执行。

* 发现口径 1 条：复合词形归一（"户部尚书致仕丹阳沈固" 型）依赖 alias\_index 手工映射 —— 已确认映射入主键表，不动标注。
