## 1. 执行流程总览

按序执行，每阶段收尾对照 checklists（工厂 references/checklists.md F–I 段）：

```
底座（拆分 + 指纹库） → 实体层 → 职官任职 APPT → 事件 EVT → 人物关系 REL
  → 文献资产 LIT → 古今翻译 TRL → 奏疏谕旨 MEM → 年谱纪年 CHR
  → 跨层整合 → 交付（使用报告 + 项目总结报告）
```

## 2. 底座（公共地基，先做）

1. **输入文件**：`assets/sources/蘧编_结构化.json`（已整理：章=序/前言/卷一~二十/后记/附录；节=年条/日期条；段=正文）。处理路径：直接按 JSON 结构切分（无需转码/OCR）。
2. **章节划分**：22 个章号 00–22 —— 00=序+前言（2 条，不入层）；01–20=卷一~卷二十（71 条，**入层**）；21=后记一+后记二（2 条，不入层）；22=附录校记（1 条，不入层）。
3. **条目切分**：卷 01–20 内每个「节」=1 条（节标题即年号纪年/日期）；序/前言/后记/附录整章各 1 条。→ `_extract\NN_卷名.txt`（格式 `条N|正文`），预计 **76 条**。
4. **指纹库 `_item_registry.json`**：key=`NN-NNN`（卷-序，如 `01-001`），value 含 `original`（节标题+全部正文段合并）/`norm`（OCR 括注归一：`（X）`括注保留原文、`☐`缺字标"□"、异体字按《通用规范汉字表》归一）。全部层的 original 注入源。
5. **入层规则**：卷 00/21/22（现代编者序/前言/后记/校记）入指纹库但**不入知识层**（layer_count=0，无 TRL），同《水东日记》卷 00 惯例。
6. 全部 76 条建 task 清单（阶段可见、完成可核）。

## 3. 实体层方案（确认启用）

- **实体类型枚举**：从基准库 `../00-book-knowledge-factory/references/enum-library.md` 1.1 拉取快照（18 值规范全集），本书高频子集：person/official/institution/place/era/work/posthumous + 兜底 unknown；执行期按 V3 流程校准（不报错终止，pending 收集）。
- **种子词典规则（候选生成）**：全文本内生（词条必须出现在原文，否则自动剔除）；命名模式 + 词典（人名/职官名/地名/年号/谥号）→ 正则候选 → **AI 逐条复核修正**。
- **归一规则**：异体/同义/复合词形（如"先少师公"→叶朝荣〔叶向高父〕）；复合解读词形用 alias_index 手工映射（不动标注）。
- **主键表**：ENT-001..N + alias_index（词形 → ent_id；先查后建、幂等累积）。
- **provenance**：每标注带 source（卷-条号）与 confidence；新建实体带 first_source。
- **同名异人**：跨卷同名自动收集入待核清单（V2），**人工核前不强行合并**（宁建勿并）。
- 每卷 JSON + 全局归一 + 标注总报告。

## 4. 职官任职层方案（C1 APPT）

- **触发词表（候选生成）**：任职动词词典——`受业于/为/任/授/擢/迁/改/除/罢/谪/致仕/兼/领/督/巡抚/提督/考满/会推/入阁/升/降/起复/赠/荫/廷推/点用/推补` + 官职词典（督学/邑令/首辅/尚书/侍郎/给谏/大司徒/别驾/经略……）→ 正则候选 → **AI 复核**。
- **schema 要点**：appointment_id / item_id / person（含 person_ent_ids）/ office（含 official_ent_ids）/ institution（含 ent_ids）/ when（年号纪年，未明写"未明"）/ status / evidence / original。
- **任职状态枚举**：基准库 `APPT_STATUS` 12 值（现任/致仕/升迁/贬谪/罢黜/兼领/暂代/追赠/未明 + 起复/世袭/举荐）。
- **执行注意**：一条目多任职拆多条共享 item_id；"会推/考满/荫子"等铨选事件登记任职变动链（升/迁/改/降）；追赠（"赠太师"）、荫子（"荫一子尚宝司丞"）按对应状态登记。

## 5. 事件层方案（L5 EVT）

- **五元组**：event_id / item_id / type / who（含 who_ent_ids）/ action / what / when / where；未明显式写"未明"。
- **事件类型枚举**：继承基准库事件类型子库 `../00-book-knowledge-factory/references/enum-library.md` §1.3 **顶层规范全集**（朝政/政变/军事/军政/边事/人事任免/弹劾/礼仪/科举/文事/建言/灾异/轶事/祭祀/经济/司法/神异传说/疾疫/御灾赈济/缉捕防盗/巡查监察/其他）+ 兜底"其他"。本书为史书/年谱 → **只继承顶层**，不引入《新官轨范》行政过程 43 子类型。执行期未匹配值 → pending 收集 → 决议 → registerVersion+1 回溯（V3）。
- **执行方式**：规则引擎（事件动词+类型语义）产候选 → AI 复核修正 → 试点 1 卷（卷 01）验收 → 全量；未建模条目如实单列缺口。
- **与 MEM/CHR 分工**：EVT 建模"发生了什么"（事件本体）；MEM 建模"君臣怎么互动"（奏疏-谕旨往来链）；CHR 是"该年主导"总览并引用 EVT。

## 6. 人物关系层方案（C3 REL）

- **触发词/句式**：`座师/门人/同年/同官/姻/亲/同乡/同里/故交/弟子/门生/师生` → 候选 → **AI 复核**。
- **schema 要点**：rel_id / item_id / person_a（含 ent_ids）/ person_b（含 ent_ids）/ relation_type / direction（单向/双向/未明）/ evidence / original。
- **关系类型枚举**：基准库 `REL_TYPES` 12 值（同僚/师生/姻亲/同乡/同科/举荐/弹劾/恩怨/上下级/父子亲属/敌对/其他）。
- **执行注意**：**宁缺毋滥**——只建文本有直接证据的关系，推测关系不建；叶向高本人为枢纽（"余"），与家人/师友/同官/门生/言官关系优先登记。

## 7. 文献资产层方案（C2 LIT）

- **触发信号**：整篇抄录的谕旨（"得旨：……"全文）、奏疏、婚牍、祭文、序文（《光庙实录》序）、《神惠记》等。
- **schema 要点**：lit_id / item_id / title（无题取首句）/ author（含 author_ent_ids，佚名"未明"）/ type / content_location / original。
- **文献类型枚举**：基准库 `LIT_TYPES` 11 值（诏敕圣旨/碑文/奏议/书启/诗/记/题跋/序/祭文/其他 + 集）。
- **执行注意**：与 MEM 分工——LIT 收"整篇抄录的文献文本"，MEM 收"君臣往来互动链"；谕旨若为完整抄录可两条联注（LIT 文献 + MEM 互动）；仅转述不抄全文的"得旨"归 MEM 不归 LIT。

## 8. 古今翻译层方案（C5 TRL）

- **schema 要点**：trl_id / item_id / translation / style / note / confidence / original。
- **翻译风格枚举**：基准库 `TRL_STYLES` 3 值（直译/意译/注释性翻译），默认**注释性翻译**。
- **风格基准**：固化余光中风格（见 `references/translation-style.md`）：译原意不译原字 / 主从改并联 / 白以为常文以应变 / 精简防冗余 / 善用四字格 / 忌翻译体公式 / 专名保留+括注（职官术语符合明史口径）。
- **执行注意**：AI 逐条翻译（代码只验覆盖：条目数=翻译数）；长文（谕旨/奏疏）分句群翻译保留分段；专名保留原词+括注；缺字/异体按 norm 归一后译；卷 00/21/22 不入层不译。

## 9. 奏疏谕旨互动层方案（自定义 MEM）

- **定义**：君臣互动链登记——臣下上疏/具揭/条陈与皇帝谕旨/批答/传谕的往来记录（issue → response → result）。本书最大内容特征（后记："所记十九皆求去之疏，慰留之谕"）。
- **触发词表（候选生成）**：臣方——`疏辞/再疏/三疏/具疏/具揭/疏请/条陈/乞休/乞罢/求去/引罪`；君方——`得旨/奉旨/奉圣旨/上传/上谕/圣谕/传谕/批出/留中/不报/允/不允` → 正则候选 → **AI 复核**。
- **schema 要点**：mem_id / item_id / actor（含 actor_ent_ids，上疏之臣）/ target（含 target_ent_ids，皇帝）/ type / issue（议题要点，AI 解读）/ response（皇帝批答要点，AI 解读）/ result / original。
- **ID 前缀**：`MEM-`（全局唯一，只属本层）。
- **枚举**：
  - 互动类型 MEM_TYPES：上疏 / 具揭 / 条陈 / 谕旨 / 批答 / 传谕 / 面奏（封闭+兜底）
  - 结果 MEM_RESULTS：允准 / 不准 / 留中 / 改拟 / 慰留 / 未报（封闭+兜底）
- **执行注意**：一条 MEM = 一次往来（臣方动作 + 君方回应）；一条目多往来拆多条共享 item_id（如卷 15 叶向高连疏乞休、皇帝连旨慰留，逐次登记）；长段谕旨全文另归 LIT；"上传/传谕/圣谕"若为皇帝主动下发（非回应）也登记（actor=皇帝方向标记）。

## 10. 年谱纪年索引层方案（自定义 CHR）

- **定义**：按年（节）一条总览——该年（或日期节）的纪年信息、主导内容类型、要点概括与跨层引用。编年体天然时间轴。
- **schema 要点**：chr_id / item_id / era（年号+干支）/ year（公元，未明"未明"）/ age（"余X岁"，未明"未明"）/ category（主导类型）/ summary（AI 要点概括，非原文）/ ref_events（引用 EVT ID 数组）/ ref_appts（引用 APPT ID 数组）/ first_person（是否第一人称亲历）/ original。
- **ID 前缀**：`CHR-`（全局唯一，只属本层）。
- **枚举**：主导类型 CHR_CATEGORIES（本书归纳，封闭+兜底）：幼年行迹 / 科举应试 / 宦途任职 / 朝政事务 / 乞休辞官 / 家居闲适 / 营建修造 / 家事姻亲 / 病逝后事 / 其他。
- **执行注意**：71 个年条各 1 条 CHR（日期节并入所在年条或独立登记，取"节"维度一一对应）；category 取该节主导事件类型（与 EVT 顶层语义对齐，但为本书阶段的概括词）；summary 只写要点不抄原文；ref_events/ref_appts 在 EVT/APPT 完成后回填。

## 11. 跨层整合
