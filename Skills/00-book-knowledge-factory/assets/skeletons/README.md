# 骨架库（Skeletons）——工程侧错误的预防装置

> 本目录存放**可直接复制进书实例的可执行骨架**。与 `assets/templates/`（文档母版）分工：
> `templates/` 决定实例「长什么样」，`skeletons/` 决定实例「跑起来不出哪类错」。

## 为什么有这个东西

`references/error-taxonomy.md` 把 8 个实例、65 条坑聚成 16 族（A–P）。其中：

| 族 | 条数 | 性质 | 跨书复现 |
|---|---|---|---|
| A 「校验通过」≠「数据可用」 | 9 | 工程侧 | ✅ 跨 5 本 |
| B 键名/ID/编号没有单一来源 | 8 | 工程侧 | ✅ 跨 4 本 |
| G 写盘幂等性与原子性缺失 | 5 | 工程侧 | ✅ 跨 4 本 |
| P 流程与语境失配 | 8 | 工程侧/方法侧 | ✅ 跨 4 本 |
| **合计** | **30 / 65 ≈ 46%** | | |

**这 46% 的坑与「做的是哪本书」完全无关**——无论《明史·职官志》《五杂俎》还是《明会典》，
都会重新踩一遍。所以它们不该留给每个实例各自再发现，而应当在**骨架层面被一次性消除**。

本目录就是那个骨架。

## 用法（Phase ③ 实例化时）

1. **复制** `packer_skeleton.py` → 实例 `scripts/_common.py`（可改名）。
2. **填** `LAYER_SPECS`：只列本书**实际启用**的层，形如
   `("structs", "structs", "structs")` —— 目录名 / 索引槽位名 / 记录键名三者一致。
3. **接**：每个 `build_*.py` 的结尾调用 `run_guardrails(name, errs, gap)`。
4. **接填充率**：凡新增扩展字段（如 `seal`/`powers`/`assess`），必须在打包器里
   登记进 `FieldCoverage(fields=[...])`，并把填充率表列入交付清单。
5. **不删护栏**：如某护栏确实不适用于本书，须在实例 `SKILL.md` 写明理由——
   **静默删掉护栏等同于把坑重新埋回去**。
6. **跑自检**：`python self_test.py` 应输出 `PASS 24 / FAIL 0`（退出码 0）。
   这是「护栏真的会响」的证据——护栏本身也可能是坏的（见下）。

## 自检（`self_test.py`）

骨架**自身也是代码，也会坏**。本目录的 `self_test.py` 对四项护栏逐条做功能验证——
验证的是「**护栏遇到坏数据时真的会响**」，而不是「函数能被 import」：

```
python self_test.py     # 期望：PASS 24 / FAIL 0，退出码 0
```

覆盖：B 族 5 项（命名漂移捕获 / 重复 ID 捕获 + ENT- 豁免 / ID 按全局序号不撞号 /
子节点保留已有 ID / 子节点缺 ID 派生）、A 族 4 项（填充率逐字段 / 零填充标记 /
零填充触发断言 / 已解释零填充放行）、G 族 4 项（增量合并不截断 / 原子写盘 /
按卷落盘不覆盖 / 同卷重跑幂等）、P 族 8 项（语域锚定正反例 / cn2int 量纲与纪年 /
漂移率越界 / 枚举收集不中断 / 探查终止正反例）、交付装置 1 项（问句验收表）。

**首轮自检抓出骨架自身 4 个真缺陷**（已修，留档以免重犯）：

| # | 缺陷 | 症状 | 修法 |
|---|---|---|---|
| 1 | `check_naming_consistency` 直接迭代 `LAYER_SPECS`（dict） | `ValueError: too many values to unpack (expected 3)`——迭代 dict 只拿到 key 字符串 | 改遍历 `.items()` |
| 2 | `assert_unique_ids` 返回类型与文档不符 | 实现返回 `list`，但用 `seen[rid] = rec` 的 dict 结构，调用方按 `.get()` 用会崩 | 返回**去重后的重复 ID 列表**，语义明确 |
| 3 | `merge_shared_json` 当 `new_items` 是 dict 时崩溃 | `AttributeError: 'str' object has no attribute 'get'`——对 dict 也走 `it.get(key_field)` | 分派：dict 直接 `update`；序列才按 `key_field` 取键 |
| 4 | **`cn2int("洪武三年")` 返回 0** | 从串首解析，遇「洪」非数字字立即 break → 0。而本函数的主要用途恰恰是解析纪年串 | 先剥尾部量词，再用 `re.search(r"[〇零一二三四五六七八九十百千万]+$", core)` **从尾部取连续数字串**，跳过「洪武」这类年号前缀 |

> 教训（与 #45/#56 同型）：**「写了装置」不等于「装置有效」**。护栏不跑自检，
> 就会成为下一批静默失败——而且是最贵的一批，因为它伪装成已解决的问题。

## 三条最重要的纪律（骨架背后的原理）

1. **没有报错 ≠ 有数据。**
   排查顺序固定为：**① 回填器是否真的被调用 → ② 解析覆盖面是否漏组 → ③ 最后才接受「原文没有」**。
   填充率 0 直接判失败，不允许沉默通过。

2. **命名四处同源，ID 分配权归打包器。**
   目录名 / 文件名前缀 / 索引槽位名 / schema 键名共用一个常量表；
   源数据只写**槽位**，永不手写业务 ID。

3. **先有问句清单，才有字段设计。**
   ERR=0 / GAP=0 / 0 空条目测的是**层内自洽**，不是**用户要查的东西在不在**。
   Phase ② 就产出「用户会拿这本书查什么」的问句清单并逐问标注承载层，
   交付时逐问实测作答——这是 A 族的唯一根治手段。
