## 1. 执行流程总览

按序执行，每阶段收尾对照 checklists：

```
底座（拆分 + 指纹库） → 启用层逐层抽取（AI 判定 + 代码验证） → 跨层整合 → 交付
```

## 2. 底座（公共地基，先做）

1. 输入文件：`assets/sources/<书名>.<ext>`（**源文件随实例存放，相对路径引用**；记录底本/版本/来源与转换方式）。**以该文件为唯一权威来源**——外部资料只作内容性质/学术定位辅助，不作条目抽取依据（版本差异坑，见工厂 pitfalls.md #11）
2. 章节划分：〔N 章 + 版本说明卷，命名规则；**卷号按汉字卷名直接映射**（序/前言/后记/附录=00/21/…），不按文件读取顺序——pitfalls.md #24〕
3. 条目切分：〔条的定义与边界〕→ `_extract\NN_卷名.txt`（格式 `条N|正文`），预计〔N〕条
4. 指纹库 `_item_registry.json`：key=`NN-NNN`，value=original/norm；norm 归一规则：〔异体/缺字/标点〕
5. 全部条目建 task 清单（阶段可见、完成可核）
6. **业务 ID 由打包器自动分配**：AI 源数据只写卷内顺序槽位，不手写业务 ID；打包器按「卷号 × 段容量 +1」段位分配，段容量按"卷条数 × 单层最大扩展系数"预留（默认 500）——pitfalls.md #13/#22
7. **写盘与并行纪律**：写文件一律「临时文件 + rename 落盘」；共享汇总文件统一增量合并语义（`--volumes` 只重算请求卷、合并写回，不覆盖共享文件）——pitfalls.md #12/#14；验证脚本写文件输出，不依赖 stdout——pitfalls.md #6

## 3. 实体层方案（确认启用时执行）

- 实体类型枚举（**继承基准库 `../00-book-knowledge-factory/references/enum-library.md` §1.1 规范值快照** + 本书归纳增量，封闭 + 兜底"类型待定"）：〔类型清单 + 判定依据〕
- 种子词典规则：全文本内生（词条必须出现在原文，否则自动剔除）
- 归一规则：〔异体/同义/复合词形〕
- 主键表：ENT-001..N + alias_index（词形 → ent_id；复合解读词形手工映射）
- 每卷 JSON + 全局归一 + 标注总报告

## 8. 跨层整合

- ID 对齐审计点：〔实体主键唯一 / 引用槽位合法 / item_id 全回填 / target 用 ID / 枚举口径一致〕
- 跨层索引：`_kg_join.json` + `_kg_join_flat.csv`（每行 = 一条目，layer_count 贯通层数）
- 枚举治理：枚举单点文件 + registerVersion（新增值 version+1 回溯存量）；校验用**「收集-报告-暂存」**模式，未匹配值入 pending 表不中断，收尾统一决议——pitfalls.md #15

## 8.5 治理组件（推荐默认启用）

- **V2 人工校验闭环**：同名异人/存疑判定自动收集入"待核清单"CSV（含 provenance），人工核前不强行合并（宁建勿并），核后回写。
- **V3 枚举校准**：执行期未匹配枚举值 → 收集-报告-暂存 → 收尾决议（新增/归并/改名）→ registerVersion+1 → 回溯存量；新增值必须有实例证据。

## 9. 管线与验证

- 源数据文件：〔_rules_ai_NN.py / _proc_ai_NN.py / _struct_ai_NN.py / _event_ai_NN.py / 标注源〕
- 打包器（build_ 前缀、可重跑、幂等）：〔annotate / build_ent_keys / build_rules / build_proc / build_struct / build_event / build_kg_join / 公共基座 + 枚举单点〕
- **键名约定**：各层产物顶层键统一 `records`；打包器内建源数据键名映射表（SRC_KEY），源数据键名与打包容器键分处声明——pitfalls.md #19/#23；CSV 计数按逻辑行（csv.reader/pandas），不数物理行——pitfalls.md #18
- 验证：每层"验证缺漏清单.txt"问题数 = 0；验证脚本写文件输出，不依赖 stdout；区分结构性错误 ERR 与执行缺口 GAP
- 重跑命令：〔PowerShell / bash 示例，含 --volumes 单卷重跑〕
