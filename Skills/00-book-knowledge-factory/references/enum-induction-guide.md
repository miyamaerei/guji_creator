# 枚举归纳方法论与树状结构设计（Enum Induction Guide）

> 版本：v2（2026-10-11 清过期副本与硬编码数字，值与流程不变；v1 2026-10-10 用户决策：所有枚举从"每本书封闭归纳"升级为"基准值 + 新书归纳"，枚举值过多时树状管理）。
> 适用范围：工厂 Phase ② 反思锁层时的枚举设计、实例执行期的枚举动态回填、跨书枚举库的维护。
> 三件套分工：
>
> | 文件 | 装什么 |
> | --- | --- |
> | `enum-library.md` | **当前生效的规范值**（权威源）——纯值表，不写历史 |
> | `enum-changelog.md` | **变更历史**（为什么改、证据、待办）——只增不改 |
> | 本文件 | **方法论**（流程、判定标准、树状设计、清单）——不管具体值 |
>
> 参考来源：《新官轨范》（11 类实体 / 7 类规则 / 43 事件）、《水东日记》（8 类实体 / 15 事件 / 12 关系 / 6 名录，执行期 5 次枚举中断教训 + V3 校准机制）、《五杂俎》（实例化初版）、《客座赘语》（全卷执行期增量，v4）四实例实践 + 用户"枚举顶层封闭加动态回填"偏好。

## 0. 总原则

1. **基准值继承**：每个枚举先继承跨书基准库（`enum-library.md`）的规范值全集，不再从零归纳。
2. **新书归纳增量**：只归纳"本书文本中出现、基准库没有"的增量值；增量必须有实例证据。
3. **顶层封闭 + 动态回填**：规范值顶层封闭；新增值 registerVersion+1 并回溯存量。
4. **树状管理**：枚举值多（≥15 或存在天然层级）时按树组织——顶层大类（封闭）→ 子类 → 叶子值，父类计数 = 子类求和。
5. **兜底保留**：每枚举必有兜底值（其他 / unknown / 未明），拒识优于乱识。
6. **归并优先于新增**：新词形先查 `enum-library.md` 的别名与归并映射表，查不到才走决议。

## 1. 归纳流程（7 步）

```
① 继承基准 → ② 探查定域 → ③ 抽样候选 → ④ 全量收集 → ⑤ 批处理决议 → ⑥ 回填回溯 → ⑦ 入库更新
```

### ① 继承基准（开工前）

* 从 `enum-library.md` 拉取该枚举的规范值全集 + 别名映射 + 使用说明，固化进实例 `_kg_enums.py` / `references/schemas.md`（自包含快照，标注"基准库 vX 快照"）。
* 按本书粒度选择层级：粗粒度主题类书只继承顶层大类；细粒度流程 / 政书另引入对应子树（如事件层引入行政过程子类）。
* 语义有分支的枚举（如 NAM 的"题名录" vs "名号称谓"）**在本步就选定分支**，不要等到执行期才发现装错语义。

### ② 探查定域（工厂 Phase ① 结构性探查同步做）

* 密度信号统计：按枚举维度的触发词（实体 = 人物/地名/书名词频，事件 = 叙事先导词，规则 = 模态触发词）估算"本书该枚举可能出现的候选域"。
* 定域产出：该枚举"大概率会用基准值、可能出新值"的方向清单（如笔记书 → 事件新增"神异传说/异闻"域）。

### ③ 抽样候选（反思阶段）

* 首卷 + 中卷 + 尾卷 + 每卷首条抽样，AI 识别文本中出现的**未匹配基准值的候选**（词 / 短语 / 概念）。
* 候选登记：`pending 表`（候选值 / 出现条目 / 抽样证据 / 初步判定：新增 or 归并）。
* 抽样判定先行：候选与基准值同义 / 近义 → 直接归并（别名映射）；语义独立 → 标记"建议新增"待全量确认。

### ④ 全量收集（执行期）

* 打包器收集未匹配值入 pending 表，**不报错终止**（收集 - 报告 - 暂存，替代报错终止——水东日记 5 次中断教训）。
* 每卷 / 每片结束输出该枚举的使用分布（值 → 条数），供决议。
* **漂移预警**：实际值种数 > 定义值数 × 1.5 → 判为枚举漂移，须提前进入决议，不得拖到收尾（见 `pitfalls.md` #27）。

### ⑤ 批处理决议（收尾统一）

* 逐候选判定（标准见 §2），三种结果：
  * **新增**：语义独立、文本成体系（出现 ≥2 条或集中于某主题卷）、能写出"使用说明（语义 + 正反例）"。
  * **归并**：与基准值同义 / 近义 → 别名映射到基准值，不新增。
  * **暂存**：单点偶发、证据不足 → 归兜底值，记录待核。
* 决议记录：新增值 / 归并映射 / 理由 / 实例证据（写入 `enum-changelog.md`）。

### ⑥ 回填回溯

* 新增值：旧数据按映射批量改（dry-run 预览 → commit 留痕）；新增值 version+1 后**回溯全部存量**。
* 归并值：存量按别名映射改回基准值（如五杂俎 政事→朝政）。
* 走实例侧升级流程见 `increment-upgrade.md`。

### ⑦ 入库更新（双写，缺一即为野分支）

* 改 `enum-library.md`：加规范值 + 使用说明 + 别名，顶部版本行 +1。
* 追加 `enum-changelog.md`：新版本条目（变更摘要 / 证据 / 归并映射 / 待办）。
* 同步实例 `_kg_enums.py` 快照 + 注释 / 文档口径一致（验证脚本比对）。

## 2. 新增 vs 归并判定标准

| 判定 | 条件（全满足才新增） | 反例 |
|---|---|---|
| 新增 | 语义与基准值不同构；文本中成体系（≥2 条或多卷出现）；能写"使用说明（语义 + 正反例）"；有实例证据 | 与基准值近义（如"军务"→"军事"）、单点偶发、说不清语义边界 |
| 归并 | 与基准值同义 / 近义，只是词形不同 → 别名映射 | 强行合并语义不同的值 |
| 兜底 | 无法归类或证据不足 → 兜底值 + 待核清单 | 可归类的值用兜底掩盖 |

> 判定主体：AI 逐条判定（代码只收集、不代判）；人工校验闭环兜底（待核清单）。

## 3. 树状结构设计（枚举值多时启用）

### 3.1 何时启用树

* 规范值 ≥15 个；或存在天然层级（大类 - 子类 - 叶子）；或跨实例需要按父类汇总统计。

### 3.2 树形规则

```
根（枚举名）
├── 层 1：顶层大类（封闭，跨书基准，如事件=朝政/军事/司法…）
│   ├── 层 2：子类（按需，如司法 > 审囚/放告/词讼受理）
│   │   └── 层 3：叶子值（细粒度，如审囚 > 尸伤处置? 视书而定）
└── 兜底：其他 / unknown（永远存在）
```

* **深度 ≤3 层**：超过 3 层说明大类粒度不当，重组（提升子类为顶层或合并大类）。
* **新增挂枝**：新值挂在最近父类下（不直接进顶层）；顶层新增需特别决议（影响面大）。
* **归并是叶子操作**：叶子别名指向目标节点（跨树引用用"路径"标识，如 `司法 > 审囚`）。
* **统计按父汇总**：枚举使用分布按树聚合，父类计数 = 直接子类求和；跨层对齐（如事件"司法"父类计数 = 审囚 + 放告 +…）。
* **快照继承子树**：实例继承"根→需要的子树"（含父路径），不强制全树。

> 现成的树状实例见 `enum-library.md` §1.3 事件（27 顶层 + 43 子类型）、§1.6 名物、§1.11 文献（四部树）、§1.17 地理。**本文件不再复制树的副本**——副本必然过期。

### 3.3 树的机器表示（`_kg_enums.py` 建议）

```
EVENT_TYPES = {
  "朝政": {}, "军事": {"军务": "别名"},
  "司法": {"children": {"审囚": {}, "放告": {}}, "aliases": {"刑罚": "司法"}},
  "其他": {},
}
```

* 节点 = dict（children / aliases / usage_note / version）；校验脚本按树遍历，父类计数 = 子类求和，别名不在计数中重复。

## 4. 各枚举归纳要点（按层）

> 具体规范值一律查 `enum-library.md` 对应小节——**本表不抄值、不写数字**，避免两处口径打架。

| 枚举 | 归纳重点 | 库位置 |
|---|---|---|
| 实体类型 | 词形归一（office→official、org→institution、book→work、artifact→object）；新书新增本书特有的实体域 | §1.1 |
| 规则类型 / 模态 | 基准 7 类封闭；新书按本书规范句形态微调 | §1.2 |
| 事件类型 | 双层树（顶层主题类 + 行政过程子类）；**笔记 / 类书只继承顶层**，政书 / 官箴书才加子类 | §1.3 |
| 关系类型 | 近义归并（上下级≈主从）；只建有直接证据的关系 | §1.4 |
| 名录类型 | **先定分支**：表格式题名录 vs 名号称谓；两分支语义不同，装错即整体返工 | §1.5 |
| 名物类别 | 物部考据体才有；按本书名物形态归纳 | §1.6 |
| 方言风俗类型 | 方志 / 笔记体才有；只收风俗语义，制度性内容归制度层 | §1.7 |
| 论说立场 | 笔记议论体才有 | §1.8 |
| 涉明类型 | 明人著作 / 涉明内容多的书才有 | §1.9 |
| 任职状态 | 任职动词词典先行 → AI 复核 | §1.10 |
| 文献类型 | 按经史子集四部归位，一部之内不再细分文体层级 | §1.11 |
| 制度类型 | 与事件类型共享概念词干（命名对齐，防混用） | §1.12 |
| 翻译风格 | 风格基准另固化（如余光中七条） | §1.13 |
| 卷阅读模式 | 按书定制（模式反映本书内容形态），基准值可复用组合 | §1.14 |
| 引书索引 | 引书密集体才有：引用方式 × 引用目的两组 | §1.15 |
| 年谱纪年 | 年谱 / 编年体书才有；多线并存时用组合值 | §1.16 |
| 地理古迹 | 含地理 / 方志 / 古迹内容的书可用；子类开放登记 | §1.17 |

## 5. 操作清单（执行枚举归纳时逐项对照）

* [ ] 该枚举已继承基准库规范值（自包含快照 + 版本标注）
* [ ] 语义有分支的枚举已选定分支（如 NAM 的题名录 / 名号称谓）
* [ ] 结构性探查已定域（该枚举在本书的候选方向）
* [ ] 抽样已识别未匹配候选，pending 表已建
* [ ] 全量收集不报错终止（收集 - 报告 - 暂存）
* [ ] 每卷 / 片结束输出枚举使用分布；种数 > 定义 × 1.5 已触发漂移预警
* [ ] 决议：新增 / 归并 / 暂存均有理由与实例证据
* [ ] registerVersion+1 已回溯存量（dry-run → commit）
* [ ] **入库双写**：`enum-library.md` 改值 + `enum-changelog.md` 追加版本条目
* [ ] 枚举库（权威源）+ 实例快照 + 注释文档口径一致（验证脚本比对）
* [ ] 树状枚举：父类计数 = 子类求和；深度 ≤3；兜底存在
