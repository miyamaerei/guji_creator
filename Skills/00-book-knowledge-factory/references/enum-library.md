# 通用枚举基准库（Enum Library）

> **库版本：v8**（2026-10-13）｜变更历史、证据与待办 → `enum-changelog.md`
> **定位**：所有枚举的**跨书基准值权威源**。本文件只存"当前生效的规范值"，不存历史、不存理由。
> **用法**：实例化时按启用层拉取规范值快照（值 + 别名 + 使用说明一并带走）；新候选值先入 `pending-review.md`，评审通过才可入库——入库须**双写**（改本文件 + 追加 `enum-changelog.md` 版本条目）。归纳流程、新增/归并判定标准、树状设计见 `enum-induction-guide.md`。

## 0. 读法

- 格式：`规范值（别名：各书历史值）——使用说明`。**别名是回填通道**，不占规范值名额。
- 树状：`顶层 ─ 子类`（顶层封闭、子类开放登记，深度 ≤3）；实例按需继承子树。
- 兜底值（其他 / unknown / 未明）**永远存在且永远最后**；拒识优于乱识。
- 每段末尾一行「来源」只标出处与入库版本；证据与归并理由一律查 `enum-changelog.md`，不在本文件展开。

## 1. 枚举基准值总表（树状）

### 1.1 实体类型 ENTITY_TYPES（20 值）
```
person 人物
official 职官（别名：office）
institution 机构（别名：org）
place 地名
era 年号朝代
work 文献书名（别名：book）
object 名物（别名：artifact）——物部考据对象
animal 动物
plant 植物
food 饮食
doc 文书
system 制度
behavior 行为
punishment 刑罚
time 时间
quantity 数量
posthumous 谥号
star 星象（别名：astronomy）——星宿/天象名实体：北斗、南斗、天枢等
event 事件名——事件专名实体：靖难、土木之难等；与 EVT 层分工：本值是"实体名"，EVT 层是"事件分类"
unknown 类型待定（兜底）
```
来源：新官 11 + 水东 8 + 五杂俎 10 合并归一；v4 新增 `star` `event`。未立值：疣痣类（证据不足，暂归 unknown 观察）。

### 1.2 规则类型 RULE_TYPES（7 值）+ 模态 RULE_MODALS（7 值）
```
禁止型(prohibit) / 义务型(obligation) / 允许型(allow) / 程序型(procedure)
/ 时限型(deadline) / 处罚型(penalty) / 优先级型(priority)
```
使用说明：规范值键位**中英皆可**（实例按政书/官箴书惯例选中文键或英文键，同一实例内统一）；kb-mcp 等工具比对时按"中英键位差异 = 命名口径差，非数据漂移"处理（lgs/xzl/fqh 先例：实例用中文键报"库外 100%"实为键位差异）。
来源：新官 7+7（封闭全）；v7 补键位说明（源自福惠全书 rules 层 534 条中文键）。

### 1.3 事件类型 EVENT_TYPES（27 顶层 + 43 子类型，树状）

**机制**：顶层封闭 + 动态回填——未匹配值 → pending 收集（不报错终止）→ 决议（新增/归并/改名）→ registerVersion+1 → 回溯存量。**双层粒度**：新书一律继承顶层全集；子类型**按需继承**（史书/笔记/类书只取顶层；官箴书/政书/流程体与行政过程同档时才引入 §1.3.2）。

### 1.23 员额解读形态 COUNT_FORMS（5 值，v8 新段）

> **并列职官员额的置信度机制**：古籍员额表述有歧义（"左、右侍郎二人"是左1+右1 共2，还是合计2？），本枚举把句式形态显式化并绑定置信度，**把歧义变成可验证的标注**。

```
P1 并列带各   —— `左、右X各N人`（含"各"）；语义 = N × 并列项数；count_confidence 0.95
P2 并列不带各 —— `左、右X N人`（不含"各"）；语义 = N（本身即合计）；count_confidence 0.90
P3 合称共享   —— `各A、B N人`（无并列前缀、含「、」且含"各"）；真歧义（共N 或 各N）；count_confidence 0.60，verify_needed=True
P4 单纯       —— 无并列无合称（"尚书一人"）；字面值；count_confidence 1.00
未明          —— 无法归类；字面值；count_confidence 0.30，verify_needed=True
```

使用说明：
- **判定优先级纪律（必守）**：**先判并列前缀型（P1/P2），再判合称共享型（P3）**。顺序写反会把 `左、右侍郎各一人`（应为 P1）误收进 P3，致最常见句式落到低置信桶（v3 首跑即撞此坑）。
- 并列前缀 = `左、右` / `右、左` / `正、副` / `副、正` / `东、西` / `南、北` / `内、外` 等。
- `verify_needed=True` ⟺ `count_form ∈ {P3, 未明}` 或 `count_confidence < 0.8`；此类记录自动进 `verify_needs_review.csv`（人工复核入口）。
- 配套字段：`count_form` / `count_confidence` / `verify_needed` / `verify_reason` / `count_evidence`（判定依据原文）/ `office_parts`（原子职官数组，**原始层不拆**，视图层展开）。
- **关键实证**：原文自身用「各」字的有无区分"各N"与"共N"——同书 `每属部设郎中、员外郎、主事各一人`（各一人=各1）vs `各郎中、员外郎一人`（一人，含糊）。故 P1/P2 可高置信判定。

来源：《明史·职官志》实例（2026-10-13，用户 m00284 发现歧义后设计；实测 P1 55 / P2 11 / P3 4 真歧义 / P4 1247，装置 ERR 0，用户确认入库）。**凡含"并列职官+员额"的古籍（职官志/会典/政书/题名录）通用**。

## 2. 实例接入

1. **取快照**：按本书启用层，从本库拉取对应枚举的规范值 + 别名 + 使用说明 + 树结构，固化进 `_kg_enums.py` / `references/schemas.md`，并标注"基准库 vX 快照"。事件层按 §1.3 粒度规则决定只取顶层或加子类型层。
2. **收增量**：执行期未匹配值 → pending 收集（不中断）→ 决议 → registerVersion+1 → 回溯存量。**候选新值先入 `pending-review.md`，评审通过才入本库**（流程见 `enum-induction-guide.md`）。
3. **回写库**：入库必须双写——改本文件对应段（含使用说明）+ 在 `enum-changelog.md` 追加版本条目；归并只更新别名映射，不新增规范值。
