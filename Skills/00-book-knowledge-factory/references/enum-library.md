# 通用枚举基准库（Enum Library）

> 库版本：v3（2026-10-10 建 v1；2026-10-10 回写《蘧编》执行期增量至 v2；2026-10-11 并入事件类型子库至 v3——原独立文件 event-type-library.md 废止，明细见 §1.3）。合并《新官轨范》《水东日记》《五杂俎》《蘧编》四实例全部枚举（后续实例按 §2 接入）。
> 定位：所有枚举的**跨书基准值权威源**。每实例枚举 = 继承本库规范值快照 + 新书归纳增量（流程见 `enum-induction-guide.md`）；值多时按树组织（顶层大类封闭 → 子类 → 叶子，深度 ≤3）。
> 新枚举候选先进 `pending-review.md` 待评审区，评审通过才入本库（版本行+1）。

## 0. 机制

- **基准值继承**：新书直接用规范值（含使用说明），不再从零归纳；出现未匹配值 → pending 收集（不中断）→ 决议（新增/归并/暂存）→ registerVersion+1 → 回溯存量 → 更新本库。
- **别名映射**：各书历史值 → 规范值（回填通道），不新增规范值。
- **兜底**：每枚举保留兜底值（其他/unknown/未明）。
- **树状管理**：值 ≥15 或有天然层级时按树组织；父类计数 = 子类求和；实例按需继承子树。

### 1.3 事件类型 EVENT_TYPES（23 顶层 + 43 子类型，树状；原 event-type-library.md 全文并入）

**机制**：顶层封闭 + 动态回填——新书出现未匹配值 → pending 收集（不报错终止）→ 决议（新增/归并/改名，新增必须有实例证据）→ registerVersion+1 → 回溯存量（dry-run 再 commit）。别名映射是"各书历史值 → 规范值"的回填通道，新书直接用规范值不再自造别名。**双层粒度**：新书继承顶层全集；子类型**按需继承**（史书/笔记/类书只继承顶层；官箴书/政书/流程体与行政过程同档时引入 §1.3.2）。每值带"语义+正反例"使用说明；兜底"其他"永远保留。

## 2. 实例接入

1. 实例化反思阶段：按本书启用层，从本库拉取对应枚举规范值快照（含使用说明/别名/树结构），固化进 `_kg_enums.py` / `references/schemas.md`；事件层按 §1.3 粒度规则决定只继承顶层或加子类型层。
2. 新书归纳增量：执行期按 `enum-induction-guide.md` 流程收集-决议-回填；**候选新增值先入 `pending-review.md` 待评审区，评审通过才入本库**。
3. 库维护：新增值 registerVersion+1 并更新本文件对应表行 + 使用说明；归并更新别名映射。
