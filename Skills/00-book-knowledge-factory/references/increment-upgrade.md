# 实例增量升级流程（Increment Upgrade）

> 工厂对**已交付实例**的唯一变更通道。用户直接改实例（加层/改枚举/改 schema）而不走本流程，会导致：新旧枚举漂移、ID 段位冲突、schemas 与 enums 不同步、实例台账（registry.md）失真——见 `pitfalls.md` #25。
> 实证：01《水东日记》事后追加 NAM/TRL，02《蘧编》、03《五杂俎》事后追加 APPT/TRL——增量是常态，必须有流程。

## 触发情形

| 情形 | 典型说法 |
|---|---|
| 加层 | "给《X》再加一层人物交际网络" |
| 改 schema/枚举 | "事件类型加一个'河防'值" / "MEM 里再加个字段" |
| 修设计缺陷 | "NAM 的 entries 四元组不够用，要加一列" |
| 改交付/口径 | "译文改成逐句对照格式" / "年龄口径统一用虚岁" |

不属增量的情形：执行期数据问题（缺口补录）→ 由实例自身的 `--volumes` 重跑解决；全新一本书 → 走工厂 5 阶段首次实例化。

## 七步流程

1. **接收与证据检验**：明确增量需求；对新增层/新枚举做数据支持检验（抽样 + 密度信号，素材不足判"点不是线"如实回绝）。只议增量部分，不重开全案反思。
2. **确认锁层**：增量方案（层/schema/枚举/口径）交用户拍板；确认结果以**增量条目追加**进实例反思记录，不重写历史。
3. **修改实例规范**：同步改实例的 SKILL.md（锁层表/方案节/资源索引）、`references/schemas.md`（新层 schema + 枚举快照 + 示例条目）、`references/enums.md`（version+1）、模板与风格基准（按需）。
4. **存量与管线衔接**：
   - 新层 ID 前缀唯一、段位与既有层衔接（段容量默认按"卷条数 × 单层最大扩展系数"预留，见坑 #13/#22）；
   - 枚举新增值 registerVersion+1 并**回溯存量**；
   - `build_` 打包器与 `run_all.py` 扩展新层，保持幂等 + `--volumes` 增量合并语义；支持只跑增量层/增量卷。
5. **试点校验**：取 3~5 条真实条目按新 schema 试跑（判定 → 注入 → 校验），通过后才铺开；示例条目写入 `references/schemas.md`。
6. **更新台账**：`references/registry.md` 该实例"最近增量"列 + 状态（摘要），详情追加到 `references/registry-detail.md` 对应实例节。
7. **学习回路（记录强制，入库有门槛）**：候选新层/新坑/新枚举写入 `references/pending-review.md` 待评审区（附证据）；满足三条件（跨书复用潜力 / 归并优先于新增 / 用户确认）才升入对应库正式区（版本行+1 可回滚），**升级的同时把该行改状态 + 填去向并移入 `pending-review-archive.md`**；设计级教训同步母版与检查单。

## 纪律

- 不改已交付历史层的口径，除非用户明确要求重算（重算走生成器全量重跑，不手改产物文件）。
- 增量途中发现既有层设计也错 → 停下，作为独立增量项重新确认，不夹带。
- 每次增量完成后实例仍须满足自包含（执行层材料全在实例内）与无绝对路径检查（见检查单 J）。
