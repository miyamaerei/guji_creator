## 2. 探查发现（Phase ①）

### 2.1 书籍基本信息
- **书名**：《大明一统志》90卷
- **成书**：天顺五年（1461）四月，李贤、彭时、吕原等奉勅撰
- **体裁**：史部地理类·总志之属（官修地理总志）
- **结构**：两京十三布政使司 → 府/直隶州 → 州/县，每府含固定 20 门
- **规模**：90卷 / ~2.27M 字符正文 / ~160–200 府级条目

### 2.2 文件特殊发现
- 源文件 `明一统志.txt` 尾部混入《钦定大清一统志》424卷卷首（约 29K 字符）：乾隆上谕 + 进表 + 凡例 + 目录上·下 + 提要。
- 正文边界标定：`"总志之属,大清一统志"` 标签之前为 明一统志 正文。

### 2.3 密度信号
- 建置沿革：256 处（≈ 府/州条目数）
- 四至八到 + 至京师/南京：~260 处
- 编户 N 里：1198 处
- 粮额 N 石：169 处
- 山川：山【6643、岭【376、河【667、水【937、泉【788、洞【336
- 寺观/祠庙/陵墓/古迹/关梁/亭/井：总计 5000+ 处
- 名宦/流寓/人物/列女/仙释：~750+ 人次
- 引书出处：【郡志】81、【图经】28、【通典】2 等 20+ 种

### 2.4 OCR 警告
- "统" → "綂"（卷二十七，U+7D82）
- 私用区字形  = 隶（直隶）
- 其他缺字/异体保留原文 + norm 标注

## 3. 层设计（Phase ②）

### 3.1 核心设计决策
- **不套用明会典架构**：明一统志是地理总志，不是典章制度，不能复用明会典的父子树六部架构。
- **以 GEO 地理实体树为★骨架**：两京十三布政司 → 府/州 → 县，类比职官志的 ORG 树。
- **建置沿革独立为 EVO 层**：每府/县的历代沿革链（秦→汉→…→明），高研究价值。
- **不建规则/流程/事件层**：本书为记述体，无规范句/步骤链/独立事件叙事。

### 3.2 启用层清单（dyz 型 = 地理总志型）
1. L0 底座
2. L1 实体（ENT）
3. GEO 地理实体层（★骨架）
4. EVO 建置沿革层
5. MTN 山川层
6. PER 人物层
7. SITE 古迹建筑层
8. PROD 物产层（薄层）
9. CIT 引书层
10. 跨层索引

### 3.3 不建层理由
- L2 规则层：无 "不可/不许/务要" 规范句
- L3 流程层：无操作步骤/时序流程
- L4 默认五维：与地理总志无关
- L5 事件层：沿革由 EVO 承载，人物事迹由 PER 承载
- C1 任职层：名宦记载无完整任职时间链
- C5 翻译层：用户未要求
- C8 方言风俗层：风俗/形胜已作为 GEO 字段

见实例 SKILL.md §0.1。预判 11 问"能答"、1 问"需补字段"（物产层因府级稀疏）。

## 5. 教训与待观察项

1. **体裁不同 ≠ 架构可复用**：明一统志与明会典体裁完全不同，必须重新设计层，不能套用会典的父子树六部架构。
2. **文件混入问题**：源文件尾部混入另一本书的卷首，须在底座阶段标定边界，否则会污染知识库。
3. **OCR 变异字**：卷二十七 `綂`（U+7D82）为正则归一增加了复杂度。
4. **府级条目跨卷**：顺天府等跨多卷，GEO 树需用 volume_range 聚合。
5. **物产层薄层风险**：府级土产记载稀疏，PROD 层可能大面积为空，需准备零填充解释。

## 6. 提案（待评审区）

- **dyz 型（地理总志型）**：新方案组合，适用于地理总志/一统志/方志类书籍。建议入 layer-library.md。
- **GEO 地理实体层模板**：可作为 layer-library 的自定义层注册（C18）。
- **EVO 建置沿革层模板**：通用性强，不仅限于地理总志。建议入 layer-library.md。
- **MTN 山川层模板**：通用地理特征层。建议入 layer-library.md。
- **文件混入边界标定**：建议在 pitfalls.md 新增"源文件混入其他书籍"条目。
