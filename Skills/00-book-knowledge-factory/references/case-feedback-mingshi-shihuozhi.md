## 1. 本实例的三条「元教训」

1. **同源异形的书要先问「骨架是什么」**。《职官志》与《食货志》同属《明史》典志体、同用汉字卷名、同走「被正文包围的无句号短行」切分——但一个以**机构**为对象、一个以**制度**为对象。若把 zgz 型的 ORG/RANK/LINE/EVO 四维直接套过来，本书的 REG 制度将无处安放。（这是坑 #0.1「层模板套用」的第 2 次复发。）
2. **「原文有没有」必须先于「结构要不要」**。用户六项需求里，马政与县级税额两项**工程上做得到、原文里没有**。若不先取证就建层，会造出全空的层，而 `ERR=0` 不会报警（A 族形态）。
3. **护栏自身的缺陷最贵**。本实例两次撞在同一位置：`check_naming_consistency` 是 B 族的**核心装置**，它在 #62 中被「修」过一次，而修法本身另有缺陷（#63）；`cn2int` 是 C16 全树的入口，其缺陷会让整棵树变成空气而不报错（#64）。

## 2. 可跨书复用潜力

### 2.1 层方案与结构（可直接复用的设计）

| # | 项 | 说明 |
|---|---|---|
| 1 | **shz 型方案组合** | 正史典志体·食货门 8 层：L0/L1/L2/**REG**/L3/**L4 四维（QUAN·INST·EVO·FISC）**/**C16**/C1/C14/C9 + 索引 |
| 2 | **C16 总账树（LEDGER）** | 5 层结构：总账 → 镇 → 兵种 → 收入类别 → 明细；适用于**任何「逐单位列收支来源」的表格叙事文本**（边镇、漕仓、盐司、海关） |
| 3 | **REG 制度层的 13 属性** | 制度名称/类别/创设沿革/主管部门/征收对象/征收物/税率定额/覆盖范围/文书载体/执行者/目的/弊病改革/史料来源；**可直接作为政书/典志类书籍的制度 schema 基准** |
| 4 | **REG 与 L4-INST 的单点真相源纪律** | REG 是真相源，INST 用 `reg_id` 反指，**REG 不反记 INST**（防第四次刻画） |
| 5 | **`agencies[].cross_kb` / `cross_id` 跨库联动机制** | 制度的主管部门指向**另一个知识库**（职官志 `ORG-`/`OFF-`），实现书间的实体对齐。这是工厂首个**跨实例引用约定** |
| 6 | **食货四维的分工口径** | QUAN 管「多少」、INST 管「哪类制度」、EVO 管「什么阶段」、FISC 管「哪个环节」——四者边界清晰，可迁移到任何财政/经济类文本 |
| 7 | **三层标记体系（`◆` / `◎` / `○`）+ 无标记子目** | 卷五十三无 `○`；证明「条级标记可以不完全」，判据须能容错 |
| 8 | **QUAN 四元组** | `{item, form, amount, unit}`；`form` 走本色/折色/银/钞/钱/未明——**任何「实物或折银」叙事的通用结构** |
| 9 | **折纳定例可直接建表** | L37 区一条给出 7 组折算比例（钞一锭=米一石 / 金一两=十石 / 银一两=二石 / 绢一疋=一石二斗 / 棉布一疋=一石 / 苎布一疋=七斗 / 棉花一斤=二斗），是**折色换算的标准样本** |
| 10 | **OPN 判据可落代码** | `len(quote) >= 40 and 命中 OPN_CLAIM_MARKERS 18 词` —— 与 fqh 的 OPN 层同源，可统一 |

### 2.2 分层与抽取纪律（判断口径）

| # | 项 | 说明 |
|---|---|---|
| 11 | **叙述句不抽规则** | `初，太祖籍天下户口…` 是沿革叙述，进 REG/TME，**不进 L2**。与职官志坑 #34 同源 |
| 12 | **制度定义句归 REG 不归 L2** | `凡户三等：曰民，曰军，曰匠。` 是分类定义，进 REG。判据：含**命令式/约束式**（禁/不许/毋得/违者）才进 L2；含**分类定义/沿革叙述**进 REG |
| 13 | **不建层的判据是「原文有无」而非「结构能否」** | 马政（太仆寺 0/苑马寺 0/种马 0/俵马 0/牧监 0）与县级税额（无偿付定额，只有公式）**不建** |
| 14 | **不建 L5 事件（第三次刻画）** | 沿革已由 REG / TME / EVO 三处承载，再建是第四次 |
| 15 | **地名随制度出现则不建 GEO** | 地名 367 处但皆附制度语境，不构成独立地理叙事（对照 ysz 型方志杂记**才**建） |
| 16 | **APPT 宁缺毋滥** | 本书不是职官志，任职只在奏议中散见；须**人名 + 官职 + 时间**三者齐备才建 |
| 17 | **`side="未分"` 是合法值** | 13 镇中甘肃(L278)/固原(L279) 无主兵/客兵分列，解析器不得因缺 `主兵`/`客兵` 报错 |
| 18 | **约数后缀优先处理** | `馀 / 有奇 / 余` 必须剥离，且可夹在数字中间（`四百三十馀万束`）。见坑 #64 |

## 5. 对工厂的回馈

1. **新增方案组合「shz 型」**（正史典志体·食货门 8 层），与 zgz 型并列；二者**同源异形**的关系应写进 `layer-library.md` 的「同源异形」说明，警示后来者「同书不同志，骨架可能完全不同」。
2. **C16 总账树候选为自定义层**：其「总账 → 单位 → 分类 → 明细」四层抽象与书目无关，凡「逐单位列收支来源」的表格叙事文本（漕仓、盐司、海关、边镇）皆可复用。
3. **REG 13 属性建议升格为工厂制度 schema 基准**：现有政书实例（lgs/xzl/fqh/ppy）的 REG 层字段远少于本书，本书的 13 属性是**最完整的一版**，可作为其他实例的扩充起点。
4. **跨库联动约定 `cross_kb` / `cross_id`** 是工厂首个书间实体对齐机制，建议写进 `layer-library.md` 的「执行注意」。
5. **#63 与 #64 的元教训**：「把关者的把关者」需要第二次验证——#62 说「写了装置要自检」，#63 补上「自检的输入形状必须与生产一致」，#64 补上「护栏函数的边界样本要覆盖真实入参形态」。三者构成 A6 子型的完整链条。
6. **骨架 `cn2int` 需强化**：中文数字解析是**高频通用护栏**，其边界（量纲前缀 #48 + 约数后缀 #64）应写进 `packer_skeleton.py` 的 docstring 与 `self_test.py` 的正反例。
