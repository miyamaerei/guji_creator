# 检查单（Checklists）

> 每个阶段收尾时对照执行。任何一项未过，不得进入下一阶段或宣称完成。
> 两段式：A~E 为**工厂阶段**（产出书实例 skill）；F~I 为**实例执行阶段**（书实例 skill 被调用后，按其中固化的规范执行）。

---

## 工厂阶段

### A. 定向检查单（工厂 Phase ①）

- [ ] 输入书稿已完整读取（格式问题已解决：OCR/转码/抓取），无"凭印象代替原文"。
- [ ] 口径已确认：研读目标 / 粒度（卷/章/条/段）/ 判定方式（AI 逐条 / 规则引擎+AI 复核）/ 交付形态（JSON/CSV/文档；飞书/落库按需）。
- [ ] 结构性探查完成：目录/序跋/凡例 → 全书结构；首/中/尾卷抽样 → 内容形态；密度信号统计（规范句/人物事件/术语）；条目规模估算。
- [ ] 用户主动提出的结构化方向已记录（事件 Registry、维度、关注点等），无遗漏。
- [ ] 探查只作设计依据，未生成 EPUB/指纹库/任何知识文件，未全文精读。

### B. 引导式反思检查单（工厂 Phase ②）

- [ ] 顺序正确：先问用户想法 → 再给层库参考 → 再让用户想自定义层 → AI 补证据 → 确认锁层。
- [ ] 用户提出的方向已无条件列为候选层，并记录来源（写入实例 skill 反思记录节）。
- [ ] 层库只作引导参考展示，未作为默认执行清单。
- [ ] 用户自定义层（层库之外）已完整开放征询，无压制。
- [ ] 每个候选层有明确的"建的理由 / 不建的理由 / 数据支持检验"——不是凭书类型标签拍脑袋。
- [ ] 数据检验完成：该层所需素材（规范句/时序/事件元组/维度对象）在文本中真实存在；素材不足判"点不是线"，不强行建模。
- [ ] 枚举设计完成：启用层枚举已确认基准值继承方案（工厂 enum-library.md 规范值快照 + 别名映射）；语义有分支的枚举（如 NAM 题名录 / 名号称谓）已选定分支；并明确本书归纳增量流程（新增/归并判定，值多时树状组织——enum-induction-guide.md）。
- [ ] 枚举入库双写已确认：改 `enum-library.md` 规范值时同步在 `enum-changelog.md` 追加版本条目（只改库不写日志 = 野分支）。
- [ ] 候选层清单（标注"用户提出 / 层库参考 / 自定义"）已交用户拍板，可增删调整；确认结果已锁层。
- [ ] **「目标查询问句清单」已产出**（8~12 问），逐问标注承载层 + 预判「能答 / 需补字段 / 原文可能无」，并写入实例 SKILL.md §0.1。**先有问句清单，才有字段设计**——A 族 #50：ERR=0/GAP=0 全绿 ≠ 能回答用户的问题。

### C. 实例化检查单（工厂 Phase ③）

- [ ] 实例 skill 命名符合 `<NN>-<book-slug>-knowledge` 规范（编号为本目录现有最大编号 +1；同书第二套方案加变体段 `-<variant>` 并在 registry 登记差异来源）。
- [ ] 已生成实例骨架（`skill-creator` 技能或手工）；SKILL.md frontmatter 完整（name + description 含该书触发词）。
- [ ] SKILL.md 按 book_skill_template.md 填写：口径、反思记录（**含目标查询问句清单**）、底座方案、**工程侧护栏节**、**仅启用层**方案、跨层整合、管线验证、交付清单、缺口边界。
- [ ] **工程侧护栏已接**：`assets/skeletons/packer_skeleton.py` 已复制为实例 `scripts/_common.py`，`LAYER_SPECS` 已按启用层填写（三元组「目录名/索引槽位名/记录键名」四处同源）。
- [ ] **护栏未被静默删除**：A/B/G/P 四族的装置（填充率体检 / 命名同源校验 / 原子写盘与增量合并 / 语域锚定匹配 / 探查终止条件 / 枚举漂移告警）凡不适用本书者，已在实例写明理由。
- [ ] references/schemas.md 只含启用层的 schema/枚举/ID/触发词；未启用层无任何残留。
- [ ] assets/templates/ 已复制使用报告与项目总结报告母版（实例自包含）。
- [ ] 骨架示例文件（example.py / api_reference.md / example_asset.txt / 空目录）已删除。
- [ ] frontmatter 与目录结构校验通过（name 与目录名一致、references/assets 齐全）。
- [ ] 质量终检：实例内**无绝对路径**（源文件走 `assets/sources/` 相对路径引用）、**无未替换占位符**（〔…〕/example_*）；源文件已随实例存放并记录底本/来源/转换方式；已声明"以该文件为唯一权威来源"。
- [ ] 已在 `references/registry.md` 登记实例（状态/启用层/源文件指针）。
- [ ] 工厂未向用户交付执行命令、中间文件或正式知识产物——唯一产物是实例 skill 本身。

### D. 试点校验检查单（工厂 Phase ④，可选但推荐）

- [ ] 取 3~5 条真实条目按实例 schema 试跑一轮（判定 → 注入 → 校验），字段/枚举/ID 无硬伤。
- [ ] 试跑结果作为"示例条目"写入实例 skill 的 references/schemas.md。
- [ ] 发现的设计缺陷已回改实例 skill 并重新校验；未产出正式知识文件。

### E. 交付 + 学习回路检查单（工厂 Phase ⑤）

- [ ] 交付书实例 skill：完整路径、目录结构、SKILL.md 摘要、调用方式。
- [ ] 已说明实例执行会产出什么（各层 JSON、归一汇总、跨层索引、两份报告）及与工厂的关系。
- [ ] 案例记录已存：探查/反思过程与用户原话 → `case-feedback-<book-slug>.md`；候选新层/新坑/新枚举已写入 `pending-review.md` 待评审区（附证据）。
- [ ] 达到合并门槛（跨书复用/归并优先/用户确认）的候选项已升入对应库正式区（版本行+1，可回滚）；设计级教训已同步母版与检查单。
- [ ] **`pending-review.md` 状态已回填**：凡本轮升级入库的提案，其「状态」列已由「待评审」改为「已升级」并填实「去向」列（库名 + 段号/坑号），**且已移入 `pending-review-archive.md`**。**升级动作执行后不回填 = 计数失真**（2026-10-15 实测：34 行内容早已入库，状态却仍停在「待评审」）；表格行数 ≠ 待办数。**主表的行数必须等于真实在途提案数**。
- [ ] **`registry.md` 只留摘要**：主表单元格不得塞长档案（实测曾出现单行 6,790 字符占全表 44%）；规模数字、联邦库/kb-mcp 结果、执行期修正、遗留项写 `registry-detail.md` 对应节。
- [ ] **新坑已归族**：新入库的每条坑已在 `pitfalls.md` 首部「错误分类总表」与 `error-taxonomy.md` 对应族登记（三处同源：pitfalls 正文 / pitfalls 总表 / error-taxonomy）；**同型坑第 2 次出现时已升级为通用纪律**（而非再记一条症状）。
- [ ] `references/registry.md` 已登记；交付物按环境可用方式交付（本地文件路径或打包视图）。

## 实例执行阶段（书实例 skill 被调用后）

### F. 底座检查单（实例执行第 1 步）

- [ ] 全书已按锁定粒度切分为条目，章节文件齐全（含版本说明卷）。
- [ ] `_extract\NN_卷名.txt`（`条N|正文`）覆盖全部条目，无遗漏。
- [ ] `_item_registry.json`：条目数与全书条目数一致；每条含 original/norm。
- [ ] item_id（NN-NNN）唯一且连续，无跳号/重号。
- [ ] 全部条目已建 task 清单（阶段可见、完成可核）。

### G. 逐层验证检查单（实例执行每层完成时）

对实例启用的每一层：

- [ ] AI 逐条判定完成，源数据只含条号/解读（无手抄原文）。
- [ ] 打包器运行成功，注入 original/norm 与 ID，产出每卷独立 JSON。
- [ ] 全局归一完成：`归一_汇总.json` 总量与分卷合计一致，无重复合并遗漏。
- [ ] 验证脚本已写文件输出（不依赖 stdout 截断），"验证缺漏清单"问题数 = 0。
- [ ] **填充率体检已跑且零填充已解释**：该层每个扩展字段输出「已填 / 总数 / 填充率」；**填充率 = 0 判失败**，须按固定顺序排查——① 回填器是否真被 `build_*` 调用 → ② 解析覆盖面是否漏组（复合句只取首组）→ ③ 最后才接受"原文没有"。`assert_no_silent_zero()` 未抛错（或已在 `zero_explanations` 显式登记原因）。
- [ ] **收尾走 `run_guardrails()`**：命名一致性校验（目录名/文件名前缀/索引槽位名/schema 键名四处同源）通过，输出 `OK <层> ERR=N GAP=M`。
- [ ] 引用槽位合法：规则 subject_ent_ids / 流程 agent_ent_ids 与 events / 结构 ent_ids / 事件 who_ent_ids 全部指向存在的 ID。
- [ ] 枚举值全部在基准库规范值或本书已决议增量内（含兜底类型），无越界值；未匹配值已入 pending 表并完成收尾决议（registerVersion+1 回溯）；**漂移率 `drift_ratio()` 已算**（>1.5 判枚举定义未覆盖本书，须处理）。
- [ ] 状态机字段仅用于显式时序素材；"点不是线"的卷如实标注，不强行建模。
- [ ] 该层缺口（未建模条目/未命中词形）已记录，不并入总量掩盖。

### H. 跨层整合检查单（实例执行收尾）

- [ ] ID 对齐审计完成：实体主键全局唯一（**ENT- 前缀豁免撞号校验**——同实体复用是设计如此）、无空槽位占错命名空间、结构层 item_id 全回填、文本 target 已改 ID 引用、枚举口径文档与代码一致。
- [ ] **子节点 ID 已归位**：树内子节点走同一分配器（`<父ID>#<序号>`），无「两个遍历器各自合成 ID 互相覆盖」；同名对象可按 `org_id`/路径区分。
- [ ] P0 止血项全部并入打包器（重跑不丢）：主键表 + alias_index、引用槽位、item_id 回填。
- [ ] P1 合并完成：枚举集中单点治理（version+1 回溯存量）、打包器公共基座去重。
- [ ] 跨层索引 `_kg_join.json` + `_kg_join_flat.csv` 生成：每行 = 一个条目，layer_count 正确；**各层条数 vs 索引层计数已对账**（防 7 层静默空回填）。
- [ ] 全量重跑一次：启用层验证缺漏清单问题数 = 0，总数与上次一致；**单卷重跑不截断共享文件**（指纹库/索引的条数与全量一致）。

### I. 交付与复盘检查单（实例执行完成）

- [ ] 按层聚合交付（每层一组：归一汇总 + 验证清单 + 卷示例 + 跨层索引），不逐件散交付。
- [ ] **填充率表已随交付给出**，零填充字段附原因（**ERR=0 只证明值合法，不证明有值**）。
- [ ] **目标查询问句验收表已产出**：Phase ② 的问句清单逐问实测作答，标注"能答 / 半答 / 答不了"；"答不了"者已分类为「原文确无」（正常，写明）或「结构缺陷」（须回填修复）。
- [ ] 《使用报告》已产出：快速查询路径、全文溯源方法、可重跑管线命令、扩展指南。
- [ ] 《项目总结报告》已产出：全流程时间线、反思结论、根因分析、方法论沉淀、缺口与建议。
- [ ] 交付物已按环境可用方式交付；说明验证方式、覆盖范围、仍存在的缺口。
- [ ] 数字总表核对：各层总量、ID 范围、校验结果与产物一致；合计/比例已用工具现算。
- [ ] 已复盘"重复读取"四类根因（schema 重读/探查蔓延/覆盖回归/环境噪声），改进已落地或记录。
- [ ] 复盘二：ID 对齐/命名空间/口径漂移 → 断裂点已修复并记录。
- [ ] 方法论沉淀：本次新教训已回写工厂的 methodology.md / pitfalls.md（版本行+1）。**若属 A/B/G/P 四族（工程侧、跨书通用），已一并落到 `assets/skeletons/` 骨架代码**——只写文档不改骨架 = 下一个实例重踩。

## 工程侧护栏检查单（K，跨阶段通用——A/B/G/P 四族）

> 依据：`error-taxonomy.md` 聚出 A/B/G/P 四族合计 **30/65 条 ≈ 46%**，**全部跨 3–5 本复现且与书的内容无关**。
> 这四族已在 `assets/skeletons/packer_skeleton.py` 落地为可复制骨架——**新实例开工即接，不留各自再踩**。
> 本检查单可在 Phase ③（接线时）与实例交付前各跑一次。

**接线检查**

- [ ] 骨架已复制进实例 `scripts/`，`LAYER_SPECS` 按启用层填写（三元组四处同源）。
- [ ] **骨架自检已跑**：`python <骨架目录>/self_test.py` 输出 `PASS n / FAIL 0`（退出码 0）——**护栏自身也是代码，也会坏**。骨架首轮自检即抓出 4 个真缺陷（dict 迭代解包崩 / `assert_unique_ids` 返回类型错 / `merge_shared_json` 传 dict 崩 / **`cn2int("洪武三年")` 返回 0**）。**实例若改动了骨架任何函数，必须重跑自检**（`assets/skeletons/README.md` 有缺陷留档表）。
- [ ] 每个 `build_*.py` 结尾调用 `run_guardrails()`，输出 `OK <层> ERR=N GAP=M`。
- [ ] 各层落盘走 `merge_layer()`（增量语义），共享文件走 `merge_shared_json()`（增量合并，**永不从空字典重建**）。
- [ ] 写盘一律 `atomic_write_*()`（临时文件 + rename）。

**A 族（静默失败）**

- [ ] 凡扩展字段已登记进 `FieldCoverage(fields=[...])`，填充率表与 ERR/GAP **并列交付**。
- [ ] 零填充字段已按固定顺序排查：① 回填器是否真被调用 → ② 解析覆盖面是否漏组 → ③ 原文是否真没有；③ 须显式登记原因。
  > 反例留档：#45 `salary_ref` 431/431 全空而 ERR=0；#56 `_seal_backfill.py` 写完未被调用，`seal` 填充 0 而 ERR=0（**同坑第 2 次复发**）；#55 印信表复合句只取首组，覆盖 57% 不报错。
- [ ] 「某层 0 条 / 覆盖率异常偏低」的指标已逐个给出解释，无沉默通过项。

**B 族（命名即契约）**

- [ ] 目录名 / 文件名前缀 / 索引槽位名 / schema 键名**四处同源**，只由 `LAYER_SPECS` 声明一次；`check_naming_consistency()` 通过。
- [ ] 源数据**只写槽位**，无手写业务 ID；ID 序号取**记录全局序号**（非 `slot`）。
- [ ] 子节点 ID 走 `assign_child_ids()`，**保留已有 ID**（防两个遍历器互相覆盖）；同名对象可按 `org_id`/路径区分。
- [ ] 各层产物顶层键统一 `records`；ID 唯一性校验已跑（**ENT- 豁免**）。

**G 族（幂等/原子）**

- [ ] 单卷重跑（`--volumes NN`）后共享文件条数与全量一致（**不截断**）。
- [ ] 全量重跑两次结果一致（幂等）。
- [ ] 无一次性修复脚本落在正式生成器之外（修复须并入 `build_*` 打包器）。

**P 族（流程与语境）**

- [ ] 判语域一律锚定原文开头（`SemanticGate`），未用全串子串匹配。
  > 反例留档：#47 `"留守司。" in scope_text` 致 `05-051`（卫指挥使司条，正文顺带提及"留守司"）漏填 3 条世官。
- [ ] 数值/单位解析单点函数化（`cn2int()`），无量纲前缀误读。
  > 反例留档：#48「一千四十四石」被读成 1+44 或 1444。
- [ ] 枚举校验用「收集-报告-暂存」不中断；`drift_ratio()` 已算，>1.5 已处理（枚举定义未覆盖本书）。
  > 反例留档：#27 事件类型 23→111 种、名录 **100% 库外**；#15 枚举校验报错终止致 5 次中断。
- [ ] 探查有终止条件，未过度探查（`ProbeTracker` 连续两次结论不变即收口）。
  > #1 是历史最高频的坑。
- [ ] **每次想加 `if` 特例时已追问**："这是『地位排序』问题，还是『包含关系』问题？"——包含关系**排序判据从原理上不适用**，须改显式父→子允许表，或不校验层级只校验「无环 + 节点唯一」。
