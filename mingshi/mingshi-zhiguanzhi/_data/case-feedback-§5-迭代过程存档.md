### 5.6 v3 员额置信度（用户 m00284 发现歧义后补）

用户原话（m00284，逐字）：
> "ok，可以，然后的话，我发现一个问题，   {"office":"左、右侍郎", "count":2, "grade":"正三品", "grade_order":5}, 这个感觉是左侍郎1，右侍郎1，但是不确定，所以需要补一个置信度，方便之后验证。然后都可以，请你入库"

**用户的直觉判断完全正确**，且源文本自身给出了判定依据。

**源文本实测：并列职官员额句式分三型**

| 型 | 句式 | 实测 | 语义 | confidence |
|---|---|---|---|---|
| **P1** | `左、右X各N人`（**带"各"**） | 55（全文）/ 49（装置） | **N × 并列项数** | **0.95** |
| **P2** | `左、右X N人`（**不带"各"**） | 11 / 8 | **N（本身即合计）** | **0.90** |
| **P3** | `各A、B N人`（合称共享） | 4（真歧义） | 疑共 N 亦可能各 N | **0.60 → 待核** |
| P4 | 单纯（"尚书一人"） | 1247 | 字面值 | 1.00 |

实例：P1 = `左、右侍郎各一人`（7 处，**全部带"各"**）/ `左、右都御史各一人` / `左、右佥都御史各二人`；P2 = `左、右司丞四人` / `左、右给事中二人` / `左、右断事二人`；P3 = `各设尚书、侍郎一人` / `各郎中、员外郎一人` / `各道置御史或五人或三、四人` / `各设左、右断事二人`。

**决定性对照（原文自证）**：同书用 `每属部设郎中、员外郎、主事各一人`（**各一人** = 各 1）表述"各1"，而 `各郎中、员外郎一人`（**一人**）表述含糊 —— **原文自身用「各」字的有无区分"各N"与"共N"**。故 P1/P2 可高置信判定，P3 须低置信 + 待核。

其他并列符号：`[东西南北]、[东南西北]…人` = 0 处；`正、副各一人` 类 = 2 处。

**v3 设计**：
- `COUNT_FORMS` 枚举 = `P1 并列带各 / P2 并列不带各 / P3 合称共享 / P4 单纯 / 未明`（封闭 + 兜底）。
- `posts[]` 元素新增 5 字段：`count_form` / `count_confidence` / `verify_needed` / `verify_reason` / `count_evidence`（另加 `office_parts` 原子职官数组）。
- 判决式：`verify_needed=True` ⟺ `count_form ∈ {P3,未明}` 或 `count_confidence < 0.8`；此类记录自动进 `_views/verify_needs_review.csv`。
- `office_parts` 由打包器生成，**原始层不拆**（保持原文可溯），仅在视图层按原子职官展开（`左侍郎 count=1 / 右侍郎 count=1`）。

**v3 实测**（`scripts/_pilot_validate_v3.py` → `_pilot_report_v3.txt`，抽样 1411 条句式 / **ERR 0**）：P4 1247 (88.4%) / P3 107 (7.6%) / P1 49 (3.5%) / P2 8 (0.6%)；语义判定 7/7 PASS；`office_parts` 展开 1411 → 1468 行（差 57 = 并列型拆分增量）；待核 156 条。

**v3 首跑撞到的判定优先级陷阱（重要教训）**：
- 首跑把 `左、右侍郎各一人` 误判为 **P3**（因分类器先判 `、`+`各`），致用户关心的那条记录被标成低置信 —— **恰好把用户提的那条记录判错**。
- **修正**：判定优先级改为 **先判并列前缀型（P1/P2），再判合称共享型（P3）**：`if is_par: P1 if has_ge else P2; elif ("、" in office) and has_ge: P3; else: P4`。修正后 `左、右侍郎` = **P1 / conf=0.95**。
- 教训：**多模式分类器的判定顺序本身是设计的一部分** —— 优先级写反会让最该高置信的常见句式落到低置信桶，且症状隐蔽（分布看起来"正常"，只是某类被系统性误收）。

**口径边界（重要）**：v3 装置是**全文句式批量扫描**，命中含沿革叙述中的非编制句（如 `陕西、贵州、云南三司郎中各二人`、`每属部设郎中、员外郎、主事各一人`）—— 这些在正式抽取时属**沿革行**，归 TME/EVO **不入 RANK**。故 P3 = 107 是**上界**；正式执行时 RANK 层 P3 型预计仅个位数。

### 5.7 v7 取消机构模板容器（用户 m01203 指出设计错误后修正）

用户原话（m01203，逐字）：
> "templates，这个有问题啊，之前不是说，道·府·州·县·儒学·巡检司·驿·税课司·仓·织染杂造局·河泊所闸坝·批验所·递运所·铁冶所·医学·阴阳学·僧纲司 这些应该是org吗？"

**用户的质疑完全正确** —— 这 17 项在 v6 中被作为"通用编制模板"另立 `ORG_TEMPLATES` 容器 + `TPL-` 命名空间 + `_layers/templates/` 独立层，排除在 ORG 树之外，是设计错误。

**根因**：把"**有没有具体实例**"当成了 ORG 的准入判据。正确判据是"**原文是否作为机构陈述**"—— 这 17 项原文（卷04 条37–75）都有品级、有员额、有隶属、有沿革，**是正式机构**；「通用编制」只是其编制可复用的**额外属性**，不是另一种东西。

**三重副作用**（v6 设计的实际代价）：
1. ORG 树缺 17 个节点 → 机构树索引不完整；
2. 这些机构的员额/隶属无处安放（RANK/LINE 只认 ORG 记录）；
3. 多一层独立目录 + 独立 ID 命名空间 → 治理面扩大。

**修正（v7）**：
- **删除**：`ORG_TEMPLATES` 容器 / `TPL-` ID 命名空间（`_kg_enums.py ID_PREFIX` 移除 `tpl`）/ `_layers/templates/` 目录；
- **17 条转为 ORGS 正式节点**（`ORG-2031`–`ORG-2053`）：`道`(道,parent=天子) / `府`(府,parent=天子) / `州`·`县`(州县,parent=府) / `儒学` + 杂职 12 项（杂职,parent=府）；
- **三处同步补齐（缺一即 ERR）**：① ORG `children[]` 加 15 项子机构（**节点字典**形态而非名称字符串）；② **RANK 层**新增 17 条 `rank_type="品级员额"` 记录承接品级员额；③ **LINE 层**新增 17 条边（道/府=跨树边；州/县/儒学/杂职12=树内边）；
- **打包器对残留 `ORG_TEMPLATES` 导出直接报 ERR**（防静默丢数据）。

**v7 首跑撞到的校验器分派陷阱**：
- `validate_layers.py` 原按 `if "posts" in r` 优先分派 RANK → 转正后的 ORG 节点**同时带 `posts[]` 与 `children[]`**，被误判为 RANK，产出 **120 条假 ERR**：`RANK ORG-2038 rank_type 越界: None` / `vacancy_type 越界: None` / `post_status 越界: None` / `selection_route 越界: None`。

- **假 ERR 指纹**：值全为 `None` 且集中于一批新记录 → 是"字段根本不存在"而非"字段值非法"，**先怀疑分派，不要逐条补字段**。

① 回溯 `owning_item` 定语域，跨卷不回；② 回溯落回自身不得兜底；③ 合称/拆名互认（原文「侍郎」vs 节点「左侍郎/右侍郎」，须去左右前缀后比对，否则 6 条尚书/侍郎边全丢）；④ 「兼领之」主语可以是**人**（「命兵部尚书**于谦**兼领之」），判据：标记词前 14 字内含「命/以…」施动句式即跳过；⑤ **未配对的全部留档**——410 处命中 → 16 条边 + 13 条留档，**留档 ≠ 失败**。

**⑥ 本版的方法论收获**

**⑦ 领域模式可复用**：「**保底值 + 实际值**」的两层结构不限于俸禄——任何「按等级有统一标准、个别有特例」的定量制度（赏赐 / 配额 / 赋役 / 驿传供给）都适用，且同样适用于「**没有就不填 null，严禁臆测默认值**」的留白纪律。

**③ 复合句解析坑（本版最大技术发现）**

印信表覆盖率长期只有 ~57% 而**不报任何错**。手查发现 `苑马寺`/`宣慰司`/`招讨司`/`安抚司` 有明确规格却查不到。

根因：原文表格句是**复合句**，一个句子含**多组「机构清单 + 品级 + 规格」**：

```
通政司、大理寺、太常寺、詹事府、京卫、各按察司、各卫，俱正三品，
苑马寺、宣慰司，俱从三品，铜印，方二寸七分，厚六分。
```

解析器按「找**第一个**品级标记 → 之前的都算清单」，于是第二组的清单出现在**第一个标记之后**，被当作规格 token 跳过 —— **静默丢数据**。

修法两条（已入坑库 #55）：
1. 数格式标记个数，≥2 判为复合句 → **按标记切段，逐段独立登记**；
2. **首段可能无标记**（`A、B、王府审理所，俱正六品，…`），须把「spec 词之前、首个标记之前」的 token 作独立首段并入。

实测：归一后唯一机构名 **157 → 235**；顶层 ORG 印信覆盖 **57% → 81.6%**。
**教训：覆盖率提升要当验收指标报出来** —— 静默丢数据不会自己暴露。

**④ 缺口 3｜EVO `owner_orgs[]`（可多值）**

273 条 EVO 只有 101 条能按 `item_id` 关联机构 —— EVO 记录**没有 owner/org/target 字段**。

难点是本书的一种特殊沿革形态：**多机构共处一条总述条**。`01-016`（六部总述条）内有 5 条沿革属六部共有（「洪武元年始置吏、户、礼、兵、刑、工六部，仍隶中书省」／「十三年，罢中书省，仿《周官》六卿之制，升六部秩」／「建文中，改六部尚书为正一品」等），而六部各自的 ORG 节点在**另外 6 条**编制条下（吏部 `01-009` / 户部 `01-019` / 礼部 `01-025` / 兵部 `01-033` / 刑部 `01-041` / 工部 `01-046`）→ `01-016` 自身没有 ORG 节点，纯按 `item_id` 必失败。

**四级归属判定**（宁缺毋滥，判不出即空数组）：① 该 item 下唯一 ORG → 直接归它；② 该 item 下多 ORG → 看沿革文本是否**显式点名**；③a 无 ORG → **个体名优先**（全库同名索引按文本点名匹配，长名优先）；③b 个体名无命中 → **集体机构名展开**（`EVO_COLLECTIVES`）；④ 全库同名兜底。

**三条踩坑纪律（两轮实测，必守）**：

1. **个体名优先于集体名** —— `01-016` 内也有「初，洪武元年置户部」这类**只点名户部**的单条沿革；若先判集体，会把 8 条单独沿革错误挂到六部全体（首跑实测全被吞）。
2. **集体侧须用显式触发形态** —— 原文写 `吏、户、礼、兵、刑、工六部`，是**并列单字**，成员全名「吏部」一次也不出现，故「成员全名 in txt」**永远匹配不上**（实测命中 `[]`）。须显式列：`("六部", [六部成员…], ["吏、户、礼、兵、刑、工", "六部", "六卿", "五部属"])`。
3. **去重按 `name` 而非按 `id`** —— 同名机构在全库有 **74 组多 ID** 实例（「经历司」12 个 /「司务厅」8 个 /「四司」4 个），按 id 去重会得 `['四司','四司','四司','四司']` 同义重复。同名多 ID 时保留**作用域最贴近该 `item_id`** 者。

**结果**：EVO 273 条，**有 owner 169（61.9%），多 owner 4**。实测查询通过 ——「吏部沿革」返回 4 条（`EVO-512` 初置 / `EVO-513` 升秩 / `EVO-515` 升秩 / `EVO-518` 裁并）；「六部共用沿革」返回 4 条且 `owner_orgs` 为六部全体。

**⑥ v12 最重要的一条方法论收获**

**「层级判据」不是「包含关系约束」** —— `LEVEL_RANK` 是机构**地位排序**（谁大谁小），被当成了父子**包含约束**（谁能包含谁）。本实例**三次放宽**同一判据（v5 `{内府,监}` / v8 `{所,司}` / v12 `{院,中枢}`），每次都是「加一条 `if` 特例」。**第三次才确认这是判据本身错了**，不是边界情况。

教训固化：**每次要加特例时，先问「这是地位排序问题，还是包含关系问题」**——若是后者，排序判据从原理上就不适用，加特例只是掩盖，应改用显式的父→子允许表，或干脆不校验层级（只校验「无环 + 节点唯一」）。**层级校验的价值上限是「拦住明显笔误」，不该期待它验证语义正确性。**
