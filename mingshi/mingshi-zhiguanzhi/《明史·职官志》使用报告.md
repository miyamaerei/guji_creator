# 《明史·职官志》使用报告

> 生成日期：2026-10-15 ｜ 适用读者：后续接手者 / 需要查询这套知识资产的人
> 一句话：5 卷 347 行古文原文 → 一套可查询、可溯源、可重跑的 **8 层**（含四维结构）知识库，共 **5105 条**层记录。

---

## 1. 项目定位

本项目为《明史》卷四十八～卷五十二——《明史·职官志》（**典志体官制文献**，非纪传非笔记，为断代正史中"志"的一种）——的抽取式数字化知识工程。从纯文本原文出发，逐层产出机器可读、可交叉引用的结构化知识：

```
合并\职官志.txt → 章节 + 指纹库 → 实体标注 → 规则层 → 流程层 → 结构化层(四维) → 任职层 → 时间沿革层 → 跨层索引
```

所有层遵循同一口径：**AI 逐条判定、代码只验缺漏、条粒度、original 指纹注入、每卷独立 JSON + 全局归一、枚举封闭治理、全文本内生词典**。

## 4. 怎么使用

### 4.1 快速查询（不跑代码）

- **一行看全某条**：打开 `_kg_join_flat.csv`，按 `item_id` 过滤 → 各层 ID 平铺。
- **查机构树**：`_layers/structs/structs_NN.json` 中 `children` 存在者即 ORG 节点；递归 `children[]` 得完整子树。`parent=="天子"` 的边属**跨树边**（不在任何 `children[]` 内），见 §5.3。
- **查某一机构的全部职官编制**：在 RANK 记录中按 `owner` 字段匹配机构名 → `posts[]` 数组，元素含 `office` / `office_parts` / `count` / `grade` / `grade_order` / `count_form` / `count_confidence` / `verify_needed` 及 12 项扩展字段。
- **查某机构的时间沿革**：`_views/timeline/<机构>.json`（若不存在则回 `_layers/tmes/` 按 `target.text` 过滤）。
- **查实体**：`_layers/ents/` 各 JSON 的 `normalized` / `type`；`count` 字段表该实体在全书出现次数。
- **查规则**：`_layers/rules/` 按 `type`（义务型/程序型/禁止型/时限型/优先级型/处罚型/允许型）过滤。

### 4.2 全文回查（溯源）

任何一条层记录的 `original` 字段 = 指纹库原文；`item_id`（`NN-NNN`）→ `_extract/` 对应条目；引用字段（`ent_ids` / `related_evo` / `link_to_bj` 等）→ 对应层 ID。

**注意跨层引用不看 ID 前缀看字段名**：`_layers/` 的六类目录名与槽位键不同（如 `structs` 目录里装 ORG/RANK/LINE/EVO 四维），打包器按 `children → change_type → line_type → posts` 顺序分派（详见 SKILL.md §6 陷阱条）。

### 4.3 可重跑管线（改了数据后全量重建）

```powershell

$env:PYTHONIOENCODING="utf-8"
```

`--volumes NN` 可单卷重跑；**PowerShell 下 `--volumes 01,02,03` 会被拆成 3 个参数致 0 条**，须逐卷调用或走缺省全量。

### 4.4 扩展指南

- **加实体词条**：编辑 `scripts/_ents_ai_NN.py`（`text` 必须**逐字出现在原文**，并列枚举处取并列原字串，见 §5.5）→ 重跑 `build_ent.py`。新增枚举类型需改 `_kg_enums.py` 并 `VERSION+1`。
- **加规则/流程/结构/任职/时间**：编辑对应 `_xx_ai_NN.py`，按 `references/schemas.md` 的 schema 写（`original` **不手抄**，交打包器注入）→ 重跑对应打包器。
- **加机构节点**：`_struct_ai_NN.py` 的 ORGS 加节点 **须三处同步**：① `children[]` 加子节点；② RANK 加 `品级员额` 记录；③ LINE 加边（`parent=="天子"` 为跨树边）。缺一即 ERR。
- **新枚举值**：`scripts/_kg_enums.py` 单点修改 + `VERSION+1`，重跑受影响层。
- **改编制字段**：`norm_posts()` 在 `build_struct.py`，12 项扩展字段的口径见 `references/schemas.md` §6.6。

## 5. 关键设计（为什么要这样做）

### 5.1 original 不手抄
AI 源数据只写条号/解读，打包器从 `_item_registry.json` 注入原文 → 杜绝手抄漂移。

### 5.2 条粒度锚点
`item_id`（`NN-NNN`，N=卷号，NNN=卷内条序）是所有层的共同主键。**317 条**逐卷 53/74/55/75/60，唯一且连续无重号。

### 5.3 树内边 / 跨树边口径（必守）
`ORG.children[]` **只装树内边**；根机构直隶「天子」的边（全书 **104 条**）属**跨树边**，不放进 `children[]`，由 LINE 层承载。校验式：

```
set(children 推出的边) == set(LINE 中 superior != "天子" 的边)
```

不区分这两类即会误报"仅 ORG 有 / 仅 LINE 有"（v2 首跑即撞）。

### 5.4 四维分派顺序（v7 定死，必守）
`validate_layers.py` 分派 structs 记录的判据顺序为 **`children` → `change_type` → `line_type` → `posts`**。转正后的 ORG 节点**同时带 `posts[]` 与 `children[]`**，若按 `posts` 优先分派会被误判为 RANK，产出大批"字段值越界: None"的假 ERR。**假 ERR 指纹**：值全为 `None` 且集中在一批新记录 → 是"字段根本不存在"而非"字段值非法"，先怀疑分派。

### 5.5 GAP 词形纪律（实体层唯一高频坑）
实体 `text` 必须取**原文最小可命中原语**。三类根因：
1. **并列枚举**：原文 `武德、龙骧、豹韬…十七卫` → 取 `武德` 而非 `武德卫`；`左、右都督` → 取 `左`+`右` 或并列原字串，不可造 `左都督`。
2. **纪年裸写**：卷首已领纪年（`洪武三年`），后文只写 `四年/九年` → text 必须去朝代前缀。
3. **词形异形**：`锦衣卫` 原文作 `锦衣`；`承天卫` 作 `承天`；`贵州都司` 作 `贵州`。

### 5.6 员额置信度（本书独有，源自用户发现）
编制行 `左、右侍郎各一人` 一类可有两种解读，故引入 `count_form` 五值与 `count_confidence`：

| 形态 | 语义 | 条数 | 置信度 |
|---|---|---|---|
| **P1** 并列带各（`左、右X各N人`） | N × 项数 | 42 | 0.95 |
| **P2** 并列不带各（`左、右X N人`） | N 即合计 | 0 | 0.90 |
| **P3** 合称共享（`各A、B N人`） | 真歧义 | 1 | 0.60 → 强制 `verify_needed` |
| **P4** 单纯 | 直接取 | 383 | 1.00 |
| 未明 | — | 5 | 0.30 |

**判定优先级纪律**：先判并列前缀型（P1/P2），再判合称共享型（P3）。顺序写反会把 `左、右侍郎各一人` 误收进 P3。

**待核清单**：`_data/struct/verify_needs_review.csv`，当前 **6 条** `verify_needed=true`（其中 1 条 P3 真歧义）。

### 5.7 枚举单点治理
`scripts/_kg_enums.py` 的 `VERSION` 当前 **1.3**。所有枚举（ORG_LEVELS 23 值 / GRADE_ORDER / REIGN_ORDER / COUNT_FORMS / POST_FIELDS 12 项 / LINE_TYPES / EVO_TYPES / TME_CATEGORIES 等）集中于此，新增必须 `VERSION+1`。

`_kg_join.json` 的 `layer_count` 直接告诉你该条贯通了几层：

| 贯通层数 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 条目数 | 18 | 100 | 135 | 44 | 19 | 1 |

**0 空条目**（v7 时仍有 60 条空条目，卷05 补齐后归零）。
