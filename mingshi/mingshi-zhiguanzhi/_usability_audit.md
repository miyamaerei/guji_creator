# 可用性审计：《明史·职官志》知识库能回答什么

> 触发：用户要求「从实用性角度出发，一般人查职官志会查什么信息？列举 10 个比较有价值的问题，并且检查一下目前的结构，能否回答？」
> 方法：只读探针，从 `_layers/` 与 `_views/` 实测查询，逐条给出**证据路径**与**返回样例**。
> 结论：**30 个问句实测 —— 20 个查得到 / 10 个查不到**；其中 3 个缺口是真结构缺陷（已由 v12 修复）。

## 三、三个真缺口与 v12 修复

### 缺口 1｜387 个官职节点无机构归属（1241 的 31%）

**来源**：ENT 372 + RANK 15。样本全来自 `05-006` 京营条：「设副、参、游、佐、坐营、号头、中军、千把总等官」
—— **差遣性军职，本就不属固定机构**（`OFF-1087` 总督京营戎政 / `OFF-1106` 把总 / `OFF-942` 参将 /
`OFF-929` 千总 / `OFF-1024` 巡视科道官 / `OFF-1105` 把司 / `OFF-1107` 把牌），
与「归属未明」混装致查询歧义。

**v12 修复**：新增 `org_binding`（`OFFICIAL_BINDINGS` 6 值）—— 机构 859 / 未明 253 /
差遣军职 112 / 封爵 12 / 土官 10。见 SKILL.md §6.11.3。

### 缺口 2｜内阁官职挂空（用户 m03465 直接指出）

翰林院 ORG-1051（level=院, parent=天子, total_posts=0）；

**用户原话**：「另外我记得内阁应该是属于翰林院的」—— **原文核实：正确**。

### 缺口 3｜EVO 无法归属机构

273 条 EVO 仅 101 条能按 `item_id` 关联机构（机构条目 157 / EVO 涉及条目 81 / 交集 35）。
EVO 键 = `['_vol','change_type','confidence','content','ent_ids','era','id','item_id','related_tme','slot']`
—— **无 owner/org/target 字段**；`ent_ids` 0 填充、`related_tme` 0 填充。

实例：`01-016` 有 5 条 EVO（初置「洪武元年始置吏、户、礼、兵、刑、工六部，仍隶中书省」/
升秩「十三年，罢中书省，仿《周官》六卿之制，升六部秩」/ 改称「二十九年，定为文选、验封、
稽勋、考功四司并五部属，皆称清吏司」/ 升秩「建文中，改六部尚书为正一品」/ 复设「成祖初，悉复旧制」）
**全属六部全体**。

**v12 修复**：新增 `owner_orgs[]` + `owner_org_ids[]`，四级归属判定 + `EVO_COLLECTIVES`。
结果：有 owner 169/273 = 61.9%，多 owner 4。见 SKILL.md §6.11.4。

## 五、方法论结论

1. **工程指标全绿 ≠ 能回答用户问题**。`ERR=0 / GAP=0 / 0 空条目` 测的是**层内自洽**；
   用户问句测的是**跨层可用性**。二者必须分开验收。
2. **问句清单应在实例化早期就产出**（工厂 Phase ② 的「枚举查询问句清单」），
   它是**字段设计的依据**；本实例是执行完毕后才补做审计，故缺口暴露得晚。
3. **「查不到」要分类**：原文确无 / 粒度所限 / 结构缺陷 —— 三者处置完全不同。
   本实例 10 个查不到里 **7 个是原文确无**（正常边界，交付说明中具名标注即可），
   **3 个是结构缺陷**（须修）。
4. **审计发现的最有价值一条**：局部字段名（`org_name=''`）的含义在**结构层面无法解释**，
   必须具名化（`org_binding`）——**空值语义不具名，等于没有这个字段**。
