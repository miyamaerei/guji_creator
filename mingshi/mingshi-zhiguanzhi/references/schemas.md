## 1. 全局约定

- **条粒度主键**：`item_id = NN-NNN`（卷-序，如 `01-001`、`05-124`），全书唯一，是所有层的共同锚点。
- **ID 命名空间**（每层唯一前缀，禁止跨层占用）：

| 层 | 前缀 | 示例 |
|---|---|---|
| 实体主键 | `ENT-` | ENT-0101 |
| 规则 | `ZG-R-` | ZG-R-001 |
| 流程 | `ZG-P-` | ZG-P-001 |
| 结构化 ORG | `ORG-` | ORG-001 |
| 结构化 RANK | `RANK-` | RANK-001 |
| 结构化 LINE | `LINE-` | LINE-001 |
| 结构化 EVO | `EVO-` | EVO-001 |
| 职官任职 | `ZG-APPT-` | ZG-APPT-001 |
| 时间沿革 | `ZG-TME-` | ZG-TME-001 |
| 跨层索引 | `_kg_join` | — |

> **ID 由打包器自动分配**：AI 源数据只写卷内顺序 `slot`，不写业务 ID。段位 = 卷号 × 500 + 顺序（`ENT-` 例外：全局顺序 ENT-0001 起，不分卷段，与 lgs/xzl/ppy 先例一致）。

- **original 不手抄**：AI 源数据只写条号与解读字段；打包器从 `_item_registry.json` 注入 `original`/`norm`。
- **未明字段显式写 `"未明"`**，不省略、不留空串。

## 2. 底座 schema

### `_item_registry.json`（指纹库）

```json
{
  "01-001": { "original": "明官制，沿汉、唐之旧而损益之。……", "norm": "明官制，沿汉、唐之旧而损益之。……" }
}
```

- `norm` 归一规则：① 繁体→简体；② 异体字归一（`適`→`嫡`、`讎`→`仇`、`倂`→`并`）；③ 全角括号 `（）` 保留（沿革括注是重要语义）；④ 缺字按上下文补（源文本已有"晋王"类缺字，按《明史》补为"晋王棡"）；⑤ 标点归一（`。，、；：` 统一，不引入新标点）；⑥ 空格清理。
- 后续每层的 `original` 字段从本库注入，差异以本库为准。

### 章节文件

- `chapters\NN_卷名.md`：`01_职官一.md` … `05_职官五.md`（本实例无 00 版本说明卷——本书无独立序跋/凡例）。

### `_extract\NN_卷名.txt`

- 格式 `条N|正文`，每卷一个：`_extract\01_职官一.txt` … `_extract\05_职官五.txt`。

### 条目切分口径（机构条目）

- **一行非空段落 = 一条目**；`◆`/`◎`/`○` 开头行与空行不计条。
- 一行含多机构（如卷 1 六部各一行）→ 仍算**一条**；一行含编制+职掌+沿革三段 → 合并为**同一条目的三段**。
- **卷目录块识别（2026-10-13 实测修正，必守）**：
  - 卷02~05 的目录行**有 `○` 标记且单行** → 标记法即可滤除。
  - **卷01 的目录行无 `○` 标记且跨两行**：L5「宗人府三公三孤太子三师三少内阁吏部户部附总督仓场礼部」+ L6「兵部(附协理京营戎政)刑部工部(附提督易州山厂)」；位置为 ◎(L3) → 卷序论(L4,含句号) → 目录(L5–L6,不含句号) → 首个机构条目(L7,含句号)。
  - **判据**：**「被正文包围的无句号段」** —— 遍历候选行，对每个不含 `。` 的行，若其**前一行含 `。`**，则视为目录块起点，向后收集连续不含 `。` 的行，全部排除。
  - **失败判据留档**（勿再试）：① 按 `◎` 之后遍历遇 `。` 即停 → 卷01 L4 卷序论含 `。` 立即停，失效；② 从首个含 `。` 行向前回溯 → L4 即首个（index 0），`j=-1` 不执行，失效。
  - 实现在 `scripts/_common.py` 的 `split_entries()`，`toc_linenos` 集合。
- 切分脚本须打印逐卷实计数与台账对账（非空 333 − `◆`5 − `◎`5 − `○`4 − **卷01 无标记目录 2** = **317 条**，已由 `build_base.py` 实测确认：53/74/55/75/60）；偏差非 0 须回查。

## 3. L1 实体层 schema

### 实体类型枚举 `ENTITY_TYPES`（继承基准库 §1.1 v7，本书适用子集）

```
person 人物 / official 职官 / institution 机构 / place 地名 / era 年号朝代
/ work 文献书名 / system 制度 / posthumous 谥号 / time 时间 / quantity 数量
/ punishment 刑罚 / doc 文书 / unknown 类型待定（兜底）
```

**本书不适用、不写入快照**（基准库有但本志无对应词条）：`object 名物`、`animal 动物`、`plant 植物`、`food 饮食`、`behavior 行为`、`star 星象`、`event 事件名`。
**别名映射**（回填通道，不占规范值）：`office`→`official`、`org`→`institution`、`book`→`work`、`artifact`→`object`、`astronomy`→`star`。

| `era` | 洪武、永乐、宣德、嘉靖、万历、崇祯；洪武元年 | 年份数 → `time` |
| `system` | 荫叙、封赠、考察、大选、廷推、军政考选、贴黄、清黄 | 具体动作 → 归 L3 流程，不建实体 |

### 判定纪律（写源数据前必读）

1. **AI 逐条判定**；代码触发词引擎只作候选。
2. **不抽纯陈述句**：编制行（"尚书一人，(正二品)"）→ 归 L4-RANK；沿革行（"洪武十三年罢中书省"）→ 归 TME。**不抽规则**。
3. **不抽括注历史**："（先是…）""（后革）"等沿革括注不抽规则。
4. **只抽现行有效规范**：职掌/铨选/考课/封赠/刑名/军政权令。
5. 组合规则（一条含多模态）→ **拆为多条记录共享 item_id**。

### v4 变更要点：差遣条目（总督/巡抚）与编制条目分流（2026-10-14）

> 卷02 实测发现：卷内 46 条（条6–51）为**总督/巡抚/总理/抚治/赞理**条目，与卷01 的编制条目**结构完全不同** —— 这是本实例的第四种条目形态。

| 形态 | 判据 | 实测 | 归属 |
|---|---|---|---|
| **编制条目** | 有品级标注 `(正从X品)`、有 `其属`/`所辖` 子机构 | 卷02 的 28 条共 **125** 处品级标注 | L4-ORG + RANK + LINE（同卷01） |
| **差遣条目** | 条首为「`<职衔>`…**一员**。」**无品级标注**；正文几乎全为沿革叙事 | 卷02 的 46 条仅 **4** 处品级标注（且全在条6 括注中，述已废漕运使） | **L4-ORG（level=差遣）+ LINE（督抚与所辖地方/军务关系）+ TME + EVO**；**RANK 只记 `count=1` 一条，grade="未明"** |

**差遣条目的处置口径（写死）**：
- `ORG`：`level = "差遣"`（**新增 ORG_LEVELS 值**，v4 registerVersion+1），`org_type = "差遣"`；`parent = "天子"`（总督/巡抚均奉敕行事、直达天子）；`total_posts = 1`；`note` 取沿革要点。
- `RANK`：**仅 1 条 posts 元素** `{office: <职衔全称>, count: 1, grade: "未明", count_form: "P4", count_evidence: "<职衔>…一员"}`；**不因「无品级」而省略记录**（宁记"未明"，不丢条目）。
- `LINE`：`line_type = "听于"` 或 `"统辖"`，表达督抚与地方三司/军务的节制关系；`note` 记所辖地方。
- `TME`：**差遣条目是 TME 的主战场** —— 每条含 3–10 个纪年事件点（"嘉靖二十九年置""万历八年革"），逐点抽取。
- `EVO`：按沿革阶段切分（初置/改置/裁并/复设…）。
- **不抽 L2 规则**：差遣条目为沿革叙事，无规范句（除个例禁令）。
- **不建 L3 流程**：无显式步骤链（沿革非流程）。

**实测数据支撑**：
- 总督条 12（条6–18）+ 巡抚条 29（条21–49）+ 总理条 2（条19–20）+ 抚治/赞理条 3（条50–51）= 46 条。
- 条38 的 `所辖` 为**管辖地域**列举（"所辖南安、赣州、南雄、韶州、汀州并郴州地方"），**非子机构**，不入 ORG `children[]`。
- 条6 的 4 处品级标注全在括注"（洪武元年置漕运使，正四品…十四年罢。）"中，属**已废机构的历史记录**，归 TME（沿革）不入 RANK。

### v5 变更要点：ORG 层级判定改「非递减」+ 宦官/女官三层嵌套（2026-10-14）

> 卷03 实测发现两个 ORG 树形结构问题，已定死口径。

**① 层级合法性判定：严格递减 → 非递减（同级允许）**

| 判据 | v4（旧） | **v5（新）** |
|---|---|---|
| 规则 | 子层级权重 **必须 <** 父层级 | 子层级权重 **≥** 父层级即合法（**同级允许**） |
| 失败例 | `宦官(内府,1) → 十二监(监,1)` 报"层级非法"；`太仆寺(寺,1) → 各牧监(监,1)` 同 | 均合法 |

**根因**：`监`/`内府` 等层级名在本书兼任**「同级机构群」**角色 —— 十二监不是"宦官的下属机构"，而是**宦官系统内 12 个同级监的集合名**；各牧监同理。严格递减会把这类合法结构误判为非法。
**实现**：`build_struct.py` 新增 `level_ok(parent_level, child_level)` = `LEVEL_RANK[child] >= LEVEL_RANK[parent]`。

**② 宦官二十四衙门 = 三层嵌套**

```
宦官(内府)
├─ 十二监(监)      ← 机构群集合名，同级
│   ├─ 司礼监(司) / 内官监 / 御用监 / 司设监 / 御马监 / 神宫监
│   ├─ 尚膳监 / 尚宝监 / 印绶监 / 直殿监 / 尚衣监 / 都知监   ← 12 个
├─ 四司(司)        ← 机构群集合名
│   └─ 惜薪司 / 钟鼓司 / 宝钞司 / 混堂司                     ← 4 个
└─ 八局(局)
    └─ 兵仗局 / 银作局 / 浣衣局 / 巾帽局 / 针工局
```

**⑤ 官职—官职关系（只建有原文依据的）**

原文「A，职掌…。B佐之」/「以A任…，B贰之」给出**直接**的官职上下级边，命中 410 处。
三种关系类型（`E.OFFICIAL_RELATIONS`）：`副贰` / `首领` / `兼领`。

**⚠ 语义方向（首跑判反，务必守）**：原文句式一律是「**A…。B佐之**」——
**B 是佐者（副贰），A 是被佐者（主官）**。故 `主官 = 窗口内第一个官职名，佐者 = 其余`。
反取会把方向整个转 180°（实测把「侍郎佐尚书」配成「尚书佐侍郎」）。

**⚠ 四条配对纪律（宁缺毋滥）**

1. **关系条通常不是编制条** ——
   `01-034`「尚书，掌天下武卫官军选授…侍郎佐之」是**职掌条**，其编制在同机构的前一条 `01-033`（兵部编制条）；`01-001` 更是卷首总述。
   故须**沿条目序回溯到最近的前序 ORG 条**（`owning_item`）确定语域，跨卷不回。
2. **关系条必须有可定位的机构语域** —— 卷首总述（`01-001`）回溯落回自身、无对应官职，
   **不得**退化为「按名字取首个」（否则随机挂到南京某部）。判据：`owning_item ∉ org_items` 即只记 evidence。
3. **合称/拆名互认** —— 原文写「侍郎」（合称），节点名是拆后 `左侍郎/右侍郎`；
   须去左右前缀后比对，否则 6 条尚书/侍郎边全丢。
4. **「兼领之」主语可以是人** —— 「命兵部尚书**于谦**兼领之」的兼领者是**人**，非官职边；
   判据：标记词前 14 字内出现「命/以…」施动句式即跳过。

| **P3** | `各A、B N人`（合称共享） | **4** | 郎中与员外郎**合计** N？还是**各** N？**真歧义** | **low** |

实测证据：
- P1 实例：`左、右侍郎各一人`（7 处，**全部带"各"**）、`左、右都御史各一人`、`左、右佥都御史各二人` → 合计 2 / 2 / 4
- P2 实例：`左、右司丞四人`、`左、右给事中二人`、`左、右善世二人`、`左、右断事二人` → 合计 4 / 2 / 2 / 2
- P3 实例：`各设尚书、侍郎一人`、`各郎中、员外郎一人`、`各道置御史或五人或三、四人`、`各设左、右断事二人`
- **决定性对照**：同书内用 `每属部设郎中、员外郎、主事各一人`（**各一人** = 各 1）表述"各 1"，而 `各郎中、员外郎一人`（**一人**）表述含糊 —— **原文自身用「各」的有无来区分"各N"与"共N"**，故 P1/P2 可高置信判定，P3 须低置信 + 待核。

其他并列符号实测：`[东西南北]、[东南西北]…人` = 0 处；`正、副各一人` 类 = 2 处。

> **口径说明（重要）**：本装置是**全文句式批量扫描**，命中含沿革叙述中的非编制句（如 `陕西、贵州、云南三司郎中各二人`、`每属部设郎中、员外郎、主事各一人`）——这些在正式抽取时属**沿革行**，归 TME/EVO **不入 RANK**。故上表 P3 = 107 是**上界**；正式执行时 RANK 层的 P3 型预计仅个位数（试点抽样中真歧义仅 `各郎中、员外郎一人`、`各设尚书、侍郎一人` 等 4 处）。

#### ④ 缺口3：EVO 加 `owner_orgs[]`（**可多值**）

**旧状**：273 条 EVO 中只有 **101 条**能按 `item_id` 关联到机构；`EVO` 记录**没有 owner 字段**，
故无法回答「吏部的沿革是什么」。

**难点**：本书沿革有一种特殊形态 —— **多机构共处一条总述条**。
`01-016`（六部总述条）内有 5 条沿革属六部共有：
```
「洪武元年始置吏、户、礼、兵、刑、工六部，仍隶中书省」→ 六部共有
「十三年，罢中书省，仿《周官》六卿之制，升六部秩，各设尚书、侍郎一人」→ 六部共有
「建文中，改六部尚书为正一品，设左、右侍中」→ 六部共有
```
而六部各自的 ORG 节点挂在**各自的编制条**下（吏部=`01-009` / 户部=`01-019` /
礼部=`01-025` / 兵部=`01-033` / 刑部=`01-041` / 工部=`01-046`）
→ **`01-016` 自身没有 ORG 节点**，纯按 `item_id` 关联必失败。

**修法**：`build_struct.py` 新增四级归属判定（宁缺毋滥，判不出即空数组）：

| 级 | 判据 |
|---|---|
| ① | 该 `item_id` 下**只有一个** ORG 节点 → 直接归它 |
| ② | 该 `item_id` 下**多个** ORG 节点 → 看沿革文本是否**显式点名**其中某机构 |
| ③a | 该 `item_id` 下**无** ORG 节点 → **个体名优先**：全库同名索引按文本点名匹配（长名优先） |
| ③b | 个体名无命中 → **集体机构名展开**：`EVO_COLLECTIVES` 触发形态命中即展开为全体成员 |
| ④ | 全库同名兜底（长名优先，避免「部」这类泛词命中） |

**字段**：
```python
r["owner_orgs"]    = [{"id": "ORG-508", "name": "礼部"}, ...]   # 可多值
r["owner_org_ids"] = ["ORG-508", ...]
```

**三条踩坑纪律**（v12 两轮实测，**必守**）：

1. **个体名优先于集体名**。`01-016` 内也有「初，洪武元年置户部」这类**只点名户部**的
   单条沿革；若先判集体，会把 8 条单独沿革错误地挂到六部全体（首跑实测全被吞）。
   → 顺序必须是「③a 个体名点名 → ③b 集体名展开」。
2. **集体侧须用显式触发形态**。原文写 `吏、户、礼、兵、刑、工六部` —— **并列单字**，
   成员全名「吏部」**一次也不出现**，故「成员全名 in txt」永远匹配不上（实测命中 `[]`）。
   → `EVO_COLLECTIVES` 须显式列形态：
   ```python
   ("六部", ["吏部","户部","礼部","兵部","刑部","工部"],
    ["吏、户、礼、兵、刑、工", "六部", "六卿", "五部属"]),
   ```
3. **去重按 `name` 而非按 `id`**。同名机构在全库有 **74 组多 ID** 实例
   （「经历司」12 个 /「司务厅」8 个 /「四司」4 个），按 id 去重会得到
   `['四司','四司','四司','四司']` 这种同义重复（首跑实测）。
   同名多 ID 时保留**作用域最贴近该 `item_id`** 者（同 item 优先，其次首个）。

**结果**：`EVO 273 条，有 owner 169（61.9%），多 owner 4`。
实测查询通过 ——「吏部沿革」返回 4 条（`EVO-512` 初置 / `EVO-513` 升秩 /
`EVO-515` 升秩 / `EVO-518` 裁并）；「六部共用沿革」返回 4 条且 `owner_orgs` 为六部全体。

**`count_form` 枚举与置信度口径（封闭 + 兜底）**：

```
COUNT_FORMS = P1 并列带各 / P2 并列不带各 / P3 合称共享 / P4 单纯 / 未明
```

| count_form | 判定优先级（**自上而下，先匹配先得**） | count 语义 | count_confidence | verify_needed |
|---|---|---|---|---|
| `P4 单纯` | 无并列前缀、无合称（如"尚书一人"） | 即字面值 | **1.0** | False |
| `P1 并列带各` | 有并列前缀（`左、右`/`正、副`/`东、西`…）**且含"各"** | **N × 并列项数** | **0.95** | False |
| `P2 并列不带各` | 有并列前缀但**不含"各"** | **N（本身即合计）** | **0.90** | False |
| `P3 合称共享` | **无并列前缀**、含 `、`、**且含"各"** | 疑为共 N，亦可能各 N | **0.60** | **True** |
| `未明` | 无法归类 | 字面值 | 0.3 | **True** |

> **判定优先级纪律（v3.1 修正，必守）**：**先判并列前缀型（P1/P2），再判合称共享型（P3）**。
> v3 首跑曾把 `左、右侍郎各一人` 误判为 P3（因先判 `、`+`各`），导致 `左、右侍郎 count:2` 被标成低置信 —— 恰恰是用户关心的那条记录。修正优先级后 `左、右侍郎` = **P1 / conf=0.95**。

**拆解口径**：
- `office_parts` 由打包器**按并列符（`、`）+ 左/右/正/副/东/西/南/北 前缀**自动生成；拆不出留空数组。
- P1 型**保留原 `office` 名 + `count` 合计值**（不强行拆成两条记录），但 `office_parts` 记录原子名 —— 这样既保持原文可溯，又支持按「左侍郎」检索。
- 若需按原子职官逐条查询，由 `build_views.py` 派生 `_views/posts_flat.csv` 时按 `office_parts` 展开（`左侍郎 count=1 / 右侍郎 count=1`），**原始层不拆**。
- `count_confidence < 0.8` 或 `verify_needed == True` 的记录，自动收集进 `verify_needs_review.csv`（V2 治理组件产物）。

### 执行注意

- **类型字段必填且命中枚举**（`org_type` / `rank_type` / `line_type` / `change_type`）；缺字段或错值 → 打包器报 ERR 并**拒绝写入**。
- `ent_ids` 用 ID 引用，**不用文本**（pitfalls.md #5）。
- **ORG 树形**：`children[]` 的数据来源是「其属」（49 处）、「所辖」（26 处）、「各设」「分设」等子机构引出词；父节点 `name` 必须与 `parent` 字段互相一致（父的 name == 子的 parent）。
- **树内边 vs 跨树边（v2 试点实测确认，必守）**：
  - **树内边** = `children[]` 表达的父子关系；与之比对时 **LINE 须排除 `superior == "天子"` 的记录**。
  - **跨树边** = 根机构直隶「天子」（如 `吏部 → 天子`），**不入 `children[]`**（天子是全书树根，非某机构子节点），单独登记在 `_views/org_tree.json` 的 `root`。
  - 校验口径：`set(children推边) == set(LINE 且 superior≠"天子" 的边)`；不一致报 ERR。试点实测：树内 5 条 == LINE 树内 5 条 ✓，跨树边 1 条（吏部→天子）单独登记 ✓。
  - **陷阱**：若不排除跨树边，会误报"仅 LINE 有 ('吏部','天子')"（v2 首跑即撞此坑，修正后 PASS）。
- **RANK 排序**：`posts[]` 必须按 `GRADE_ORDER` 升序；打包器在写入前**强制排序校验**，乱序报 ERR。
- **LINE 边表**可反向构建机构树（`superior` → 父），与 ORG `children[]` **互为校验**：两者推出的树内父子集必须一致，不一致报 ERR。

- 全部枚举收进单点 `scripts\_kg_enums.py`，含 `VERSION`（当前 **1.7**；沿革：v1 初版 → v1.2 加 `tpl` + ORG_LEVELS 4 值（南京/道/杂职/虚拟锚点）+ GRADE_ORDER "同北京" → v1.3（v7）移除 `ID_PREFIX["tpl"]`，模板容器取消 → v1.4~v1.5（v9）加 `SALARY_TABLE`/`SALARY_ITEMS`/`SALARY_UNITS`/`SALARY_FORMS`/`RANK_TYPES` 扩展 → v1.6（v11 前期）加 `SEAL_*`（印信）/ `ASSESS_*`（考核）/ `DOC_*` + `VETO_TYPES`（文书）/ `STATION_ACTIONS`（驻地）→ **v1.7（v11）加 `POWER_TYPES`（权力类型 8 值）、`DOC_UP_TYPES` 补正文词形 `题本/奏本/表文`**）。
- **基准值继承**：优先继承基准库 v7 规范值快照，不自创词形；同义值走别名映射。
- **新增值流程（V3，registerVersion）**：执行期未匹配 → 收集-报告-暂存（`pending_enums.csv`，**不中断执行**）→ 收尾决议（新增/归并/改名，新增须有实例证据 + 使用说明）→ `VERSION += 1` → 回溯存量 → 更新实例快照 + 回写工厂基准库（双写 `enum-library.md` + `enum-changelog.md`）。
- **封闭枚举硬校验**：打包前 `value ∈ ENUM_SET`，不在集内 → 报 ERR 并列出待决议清单，**不许静默写入**。
- **漂移告警**：验证报告输出每层"值种数 vs schema 定义数"，比值 > 1.5 判口径漂移。
