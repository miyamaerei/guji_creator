# 领域问句验收表（模板）

> 对应 SKILL.md §0.1 十问清单与 §13 交付必报三表之「问句逐问验收表」。
> 用法：试点与每次交付时**逐问实测作答**；凡答不了必须分类「**原文确无**」或「**结构缺陷**」——前者是原文没有相应记载，后者是层/字段没建到位（坑 #49/#50：ERR=0 只证明层内自洽，不证明能回答问题）。
> 本表为**模板**：`验收态/证据条目/结论` 三列由执行期实际填写，不得预填「能答」；「结构可达」仅表示字段与层级存在，不视为内容验收通过。

## 1. 验收态判定标准

| 验收态 | 判定 | 试点/交付处置 |
|---|---|---|
| 能答 | 给出答案 + 支撑数据条目（含 src_loc），证据链完整 | 通过 |
| 半答 | 答出部分（如只答出旧版清单、无沿革），缺项已定位 | 记缺项，给出补法，不得标通过 |
| 答不了（原文确无） | 原文确无该信息（如某卫无明确创立时间） | 写明「原文确无」+ 证据行号，不补票据 |
| 答不了（结构缺陷） | 层/字段缺失或未建，属于实现问题 | **必须修复**，修复前不得交付 |

## 3. 证据条目格式要求

- 每条证据写：`<层文件路径>:<条目ID> @ <src_loc>`，如 `_data/weis/weis_66_old.json:WEI-0001 @ 卷66-L58`。
- 跨层答案（如问句 1 = C17 节点 + L4-EVO 沿革）必须给**多条目**并说明拼接逻辑。
- 引用文本与原文逐字一致，不转述；括注内容必须置于 `notes[]`（C14 转写）或沿革节点，不得并入 `name`。

## 4. 汇总与交付

```text
能答： x/10
半答： x/10（缺项清单：…）
答不了（原文确无）： x/10（证据行号：…）
答不了（结构缺陷）： x/10（**此项必须修复**，修复后重新验收）
```
