# 卷66 卫所试点计划（Pilot Plan）

> 对应 SKILL.md §13「试点与验收」。目标：**以卷66 卫所双清单为试点，先验证 C17 解析链路与四维抽取可行性，再全卷展开**。
> 所有行号对 `assets/sources/兵志.txt`（367 行）实测。试点范围 = 旧编成树 L52–120（+ 后定编成 L122–251 复核范围，见 §3）。
> 工厂纪律：**解析器只产候选，AI 复核定稿**；覆盖率不达标/未复核不得进入定稿（阶段一/二验收硬门槛）。

---

## 1. 试点目标与范围

### 1.1 目标

1. **验证解析器**：`_weisuo_builder.py` 能把无分隔卫列长行切成候选卫/所节点，覆盖率 ≥ 95%、括注剥离率 100%、旧树无漏挂。
2. **验证词典机制**：WEI_NAME_INDEX 渐进回填（括注锚点预扫 → AI 复核回填）能收敛覆盖率，且**不引入误切**。
3. **验证双树模型**：old/new 两棵卫所树能按 C17 规格（§6.5）组装，`_views/weis_diff_<都司>.json` 三态对照可生成。
4. **验证问句可达**：十问验收表逐问实测（§0.1 十问），问句 1–3 直击双树，试点阶段必验；问句 4–10 试点阶段只验**结构可达性**（层/字段存在），内容验收随全卷展开。

### 1.2 试点范围

| 项 | 范围 | 说明 |
|---|---|---|
| 源文件 | `assets/sources/兵志.txt` | 唯一权威来源 |
| 阶段一解析范围 | 卷66 旧编成 L52–120 | 上十二卫 + 五府 + 在外都司/直隶，含 `已上` 块注与括注密集区 |
| 阶段一复核范围 | 候选树 `_data/weis/candidates_66_old.json` | 逐行 AI 复核 |
| 阶段二定稿范围 | 旧编成树 + 新清单对照 | 定稿树 `_data/weis/weis_66_old.json`（打包器 ID/护栏后） |
| 词典 | `_data/weis/wei_name_index.json` | 同名词典，AI 每复核一批回填一批 |

> 后定编成 L122–251（含南京三子树、羁縻数量行）为**全卷展开阶段的第二试点批次**，结构已预研（§4），不在本试点验收表内。

## 2. 阶段一：解析器候选验收

### 2.1 执行命令（固定入口）

```bash
python assets/tools/_weisuo_builder.py --vol 66 --ver old --lines L52-L120
# 产出 _data/weis/candidates_66_old.json（候选树 + stat + 词典）
# 另：--save-index 用括注锚点预扫收词（冷启动 37.4% → 63.6%），AI 复核后回填 → 完备词典 99.5%+
```

### 2.2 验收硬指标（不达标不得进入阶段二）

| 指标 | 阈值 | 实测基线（探查期） | 验收方式 |
|---|---|---|---|
| 卫/所切段覆盖率 | ≥ 95% | 冷启动 37.4% → 括注预扫 63.6% → 完备词典 99.5–100% | `build_coverage()` 的 `segment_coverage`，逐批回填词典后复测 |
| 括注剥离率 | 100% | 100%（括注锚点切段机制保证） | `bracket_strip_rate` + 抽查 `notes[]` 挂载 |
| 旧树无漏挂 | 0 漏挂 | 每行卫列均入树（悬空 zhangben/other 另有统计） | `build_candidate_tree` 卫/所列节点 vs 原文卫名数人工抽查 |
| CNN 数量行 | 全部正确 | `cn2int` 8 样本全对（含 `四百三十馀万束`、`十三万二千馀石`） | `_common.py` 自检 |
| AI 复核接口 | 契约可用 | `review_candidates()` 四动作（merge/rename/delete/split）已定义 | 阶段二逐行调用 |

### 2.3 词典回填规程（渐进收敛，严禁一步到位猜边界）

1. 首跑 `--save-index` 括注锚点预扫 → 词典增长、覆盖率 37.4%→63.6%。
2. AI 逐行复核候选：每确认一批卫名即 `merge` 回填 `wei_name_index.json`（`save_name_index()`）。
3. 覆盖率 ≥ 95% 且无 pending 卫列段 → 阶段一验收通过。
4. **坑 #54/#55 铁律**：无词典命中的粘连段整段标 `ai_review=required`，规则引擎**不硬猜边界**；AI 复核时以 `split + new_names` 明确逐卫边界后才回填。
5. 复核动作只改候选/词典，**不直接改 schema**。

## 3. 阶段二：AI 复核 + 问句验收

### 3.1 复核流程

1. 逐行消费 `candidates_66_old.json` 候选节点，按 `src_loc` 对照原文。
2. 卫名错误 → `rename`；粘连/误并 → `split`（**必须带 `new_names`**）；括注归属错 → `merge` 到正确叶；确认冗余 → `delete`。
3. 每完成一批 → `save_name_index()` 回填词典 → 复测覆盖率。
4. 复核完成 → 打包器 `assign_ids`/护栏（FieldCoverage / assert_no_silent_zero / check_enum）→ 定稿树 `_data/weis/weis_66_old.json`。
5. 跑 §0.1 **十问验收表**（模板见 `references/query-acceptance-template.md`），问句 1–3 必须给出「能答」级证据链。

### 3.2 双树对照（试点即可验证）

| 步骤 | 动作 | 产物 |
|---|---|---|
| 1 | 后定编成树（第二批次）定稿后，`name_norm` 归一（去方位字：`金吾前卫`→`金吾卫`） | `_data/weis/weis_66_new.json` |
| 2 | 打包器生成 `_views/weis_diff_<都司>.json`：逐都司「旧有/新有/两树皆有」三态 | 对照视图 |
| 3 | **凡两树同一卫名但沿革注不同**（如 `留守左卫(调北京)`），以 `src_loc` 保留双证据，不合并覆盖（SKILL.md §16-7） | 双证据条目 |

### 3.3 问句验收要点（十问中试点必验项）

| 问句 | 试点验收路径 | 通过判据 |
|---|---|---|
| 1 某卫隶属沿革 | 旧树 WEI- 节点 + `notes[]`（括注）+ C14 | 锦衣卫等 3 个抽查卫名可答「属府/调京/改卫」 |
| 2 都司卫所清单两版差异 | 双树遍历 + `_views/weis_diff_*.json` | 浙江都司等 2 个抽查都司可答三态 |
| 3 全国卫所总额 | 数量行 + QUAN + count_marker（旧 329/65、后 493/359） | 两版总额可答且 `num_semantic` 标注 |
| 8 卫所编制人数 | L4-WEI + QUAN | 五千六百人为卫、千一百二十人为所可答 |
| 4–7/9–10 | 结构可达性：层/字段存在、无「结构没做」 | 验收态「结构可达」，内容随全卷展开 |

## 4. 全卷展开条件（试点通过后）

1. 阶段一覆盖率 ≥ 95% + 括注剥离 100% + 阶段二十问 1–3 通过。
2. 后定编成 L122–251 第二批次（南京三子树 / 羁縻数量行）按同法展开——注意**三潭子树不得混挂**（SKILL.md §16-8）。
3. 其余卷按 §15 执行流程推进：L0 底座 → L1 实体 → C17 第二批次 → REG → C14 → C9 → L2 → OBJ → L4 四维 → 跨层整合 → 三表交付。

## 5. 风险与坑（试点期重点盯防）

| 风险 | 对策 |
|---|---|
| 无分隔长行切段（最大风险，坑 #54/#55） | 括注锚点 + 词典贪心 + 未解段 AI 复核；覆盖率硬门槛 |
| 标记文法不一致（△/○ 有无不定，坑 #47） | 语义锚定行首/上下文，不依赖单个标记；`block_title` 兼容 `上十二卫`/`在外` |
| 括注内句读误判卫列（L65 `(后改名武定，属后府)`） | classify_line 剥离括注后再查行级句读（已修） |
| 括注挂错叶（`通州卫(已上俱改为亲军)`） | 括注挂**段尾最后一片**叶（已修） |
| `已上` 被括注干扰误截断 | 先拆括注再检 `已上`，仅作用无括注尾部段（已修） |
| 数量约数/杂量纲（坑 #48/#64） | `cn2int()` 含 `馀/有奇/万` 后缀，未解即报错不静默 |
| 同名异卫 / WEI- 跨层 ID 豁免 | `_common.py` ID 校验豁免 `("ENT-","WEI-")`；C17 节点与 L4-WEI 共用前缀为设计 |
| 词典误收粘连串（`水军左卫骁骑右卫`） | 段内词尾计数 >1 强制词典分解或整段 pending，不直接定卫名 |
