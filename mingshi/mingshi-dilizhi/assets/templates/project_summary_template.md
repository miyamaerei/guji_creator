## 0. 项目概述

〔书〕数字化工程，按用户锁定口径推进：

- **AI 逐条判定 + 代码只验缺漏**（判定与验证严格分工）
- **条粒度**（按条目切分，〔替代方案〕被用户否决）
- **original 指纹注入 + 引用关联**（AI 源数据不手抄原文）
- **每卷独立 JSON + 全局归一**（先分卷产出，再归一并验证）
- **枚举顶层封闭 + 动态回填**（新增枚举值必须 version+1 并回溯存量）
- **词典全文本内生**（用户明确否决外部词典抓取）

最终形成**底座 + 〔N〕层知识资产**：〔本实例为 7 容器：底座 → 实体层 → 时间沿革(TME) → 结构化四维(GEO 政区树 / EVO 沿革 / HYD 水系河患 / GAR 卫所关隘) → 资源层(RES) → 跨层索引〕，外加 ID 对齐审计与枚举校准（V3）。

## 3. 根因分析：为什么"重复很多次无用读取"

诚实复盘，重复读取有〔N〕类根因，其中〔M〕类工程失误、〔K〕类环境与方向成本：

1. **上下文压缩后的 schema 重读（半可控）**：〔现状与改进：schema 样例固化进 summary/报告〕
2. **探查-执行边界没守住（失误）**：〔现状与改进：开工前一次探查，定死 schema 再写数据〕
3. **产物覆盖回归导致的重复验证（失误）**：〔现状与改进：修复并入打包器、脚本转 build_ 前缀可重跑〕
4. **环境噪声导致的重复跑（半可控）**：〔现状与改进：验证写 .py 脚本并重定向到文件再读〕
5. **用户多轮纠偏（方向成本，不是无用读取）**：〔现状与改进：方向性假设开工前先确认〕

## 4. 方法论沉淀（下次遇到任务的处理原则）

1. **一次探查**：开工前读完全部输入 + schema 样例 + 统计；连续两次读取不再改变计划即停止探查。
2. **先锁 schema 再写数据**：字段口径、枚举、ID 规则一次性定死；打包器注入指纹/关联/校验。
3. **AI 判定与代码验证严格分工**：判定逐条人工（AI）；代码只验缺漏。
4. **所有生成器正式化**：build_ 前缀 + 可重跑 + 幂等；修复并入生成器。
5. **验证一次到位**：校验脚本写文件输出，重跑前先确认不覆盖已修复字段。
6. **枚举单点治理**：新增枚举值 version+1 并回溯存量（registerVersion 模式）。
7. **方向假设先确认**：粒度/判定方式/交付形态开工前问清。
8. **交付按层聚合**：每层一组（归一汇总 + 验证清单 + 卷示例 + 跨层索引）。
9. **每轮任务建 task 清单**：阶段可见、完成可核。
10. **如实报告缺口**：哪里缺、缺什么、补什么方案，不静默降级。
