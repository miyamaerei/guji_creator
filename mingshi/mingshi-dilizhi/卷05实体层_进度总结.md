  - `data_part2`（091-183）：**13** 条 → 05-091、093、094、095、096、097、098、099、101、102、103、182、183
  - `data_part3`（184-269）：**0**（该段 `data_part3.py` 尚未生成，#24 未做，故无字段可校验）
- **按字段分布**：
  `ent.text` 27 / `hyd.flow` 16 / `hyd.name` 12 / `tme.event` 9 / `tme.era_raw` 7 / `gar.name` 7 / `geo.name` 2 / `geo.bearing.raw` 2 / `evo.era_raw` 2 / `evo.change` 2 / `gar.est.era_raw` 1

### 2.2 根因

`data_part2`（湖广/湖南段 05-091~183）写于「溯源 GAP 17 重标」**之前**，取值用的是旧 norm 写法：

1. **河流/政区系统别名**：江→水（沅**江**→今 norm 沅**水**、澬**江**→澬**水**、湘**江**→湘**水**）；路→府（潭州**路**→潭州**府**、衡州**路**→衡州**府**）等约 30 处。
2. **hyd.flow 抄旧 norm 长句**：如 05-094 `又东有沅江，一名朗江，又称枉水，流入界，经县东，下流入于洞庭湖`，今 norm 已改写为 `南有沅水，又有朗水流入焉，谓之郎口…`，整句不再子串命中（共 16 处）。
3. **跨条上下文误标**：部分 `tme`/`gar`/`evo` 字段在**该条自身 norm 中根本不出现**——如 05-094「洪武中 置武陵守御千户所」，而 05-094 县条正文只提「九溪卫」，武陵守御千户所信息出自湖广都司总叙，属误标，须**删除或迁移**（ent/gar/evo 共约 9 处）。

> `chk` 纪律：`gen_main.chk()` 要求 `ent.text / tme.era_raw / tme.event / geo.* / evo.* / hyd.* / gar.* / res.raw` 全部为 `reg[iid]["norm"]` 的**字面子串**（注意 registry 结构是嵌套 dict，norm 在 `["norm"]` 键，且用**全角括号（）**）。

### 2.3 修复方案（建议，未执行）

1. 改基底文件 `data_part2.py`（13 iids）+ `data_part1.py`（05-070）；05-049 已在 `data_part1.py` 修好（event=置 / place=九溪卫），只差刷新。
2. **关键陷阱**：合并顺序为 `data_part2 < part2b < part2c < part2d`，下游分片是 gen 时**深拷基底**，故改完基底须**重跑** `gen_part2b.py / gen_part2c.py / gen_part2d.py`（以及 `gen_part1b.py`）刷新深拷，否则基底修复被旧分片覆盖。
3. 具体改法：
   - **系统别名**（脚本批量）：江→水、路→府 映射（沅江/澬江/湘江/潭州路/衡州路 等约 30 处 `ent.text`/`hyd.name`）；
   - **hyd.flow 长句**：改为 norm 中真实存在的子串，或置「未明」跳过校验（16 处）；
   - **跨条误标**（武陵守御千户所 等）：从 05-094 删除，必要时迁到正确条目；
   - **tme.event / era_raw**：落到该条正文子串（9+7 处）。
4. 复跑校验器确认 **87 → 0**，再进 #25。
