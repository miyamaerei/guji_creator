## 1. 项目定位

本项目为一本书——《明史·食货志》（卷五十三～五十八，正史典志体的财政制度专志，6 卷 / 5.9 万字）——的通读、抽取、建库数字化知识工程。从原始 txt 出发，逐层产出机器可读、可交叉引用的结构化知识：

```
食货志.txt → 6 卷章节 → 条目指纹库(254) → L1 实体层 → L2 规则层 → REG 制度层 → L3 流程层
            → L4 食货四维(QUAN/INST/EVO/FISC) → C1 任职层 → C14 沿革层 → C9 论说层 → 跨层索引
```

所有层遵循同一口径：**AI 逐条判定、代码只验缺漏、条粒度、original 指纹注入、每卷独立 JSON + 全局归一、枚举封闭治理、全文本内生词典**。

## 4. 怎么使用

### 4.1 快速查询（不跑代码）
- **一行看全某条**：打开 `_kg_join_flat.csv`，按 item_id 过滤（如 `06-037`）→ 该条在 8 层的全部记录 ID 平铺一行；`_kg_join.json` 里 `layer_count` 直接告诉你贯通了几层。
- **查实体**：`_layers/ents/` 各卷文件 → 每条含 `text/norm/type/evidence`（如 `ENT-01001` 太祖 / person），`normalized` 归一体可跨卷查同一个人。
- **查制度**：`_layers/regs/regs.json` → 13 属性制度档案（主体/对象/标准/存续/文书载体/执行者/目的/沿革/史料来源…）。
- **查九边钱粮**：`_data/ledger_tree.json` 五层树（总账→镇→兵种→收入类别→明细），`ledger_flat.csv` 每行一个金额（含原文数字/量纲/约数标志）。

### 4.2 全文回查（溯源）
任何一条规则/流程/制度/数额/议论的 `item_id`（如 `06-037`）→ 在 `_data/registry.json` 里取 `original` 即逐字原文；`evidence` 字段直接复述引文。OPN 论说层 `text` 为逐字原文引述，含 `speaker/opn_type/stance`。

### 4.3 可重跑管线（改了数据后全量重建）
在 `scripts/` 下按序执行（支持 `--volumes NN` 单卷重跑）：

```bash
python build_base.py            # 切分 + 章节 + _extract + 指纹库
python build_ent.py             # L1
python build_rules.py           # L2
python build_regs.py            # REG ★
python build_proc_appt_tme.py   # L3 + C1 + C14
python build_struct.py          # L4 食货四维 + HK/LAND/TRANS 子结构
python build_opn.py             # C9
python build_ledger.py          # C16 总账树
python build_entity_links.py    # 实体引用索引（_ent_links.json）
python enrich_layers.py         # 引用写回（TME/APPT/procs 字段补全，位置固定于上一步之后）
python build_views.py           # 时间线视图（_views/timeline/）
python build_kg_join.py         # 跨层索引
python validate_layers.py       # 须 ERR=0 GAP=0 WARN=0
python summary_stats.py         # 数字总表
```

每层源数据在 `scripts/_*_ai_NN.py`（NN=01..06），AI 判定写入，打包器注入原文指纹并校验枚举。

### 4.4 扩展指南
- **加实体词条**：向对应卷 `_ents_ai_NN.py` 追加（`text` 必须出现在原文）→ 重跑 `build_ent.py --volumes NN`；新增实体类型需 `_kg_enums.py` VERSION+1 并回填存量。
- **加规则/流程/制度/结构/议论**：改写对应 `_*_ai_NN.py`（`original` 不手抄，交打包器注入）→ 重跑对应打包器。
- **新枚举值**：`_kg_enums.py` 单点修改 + VERSION+1，重跑受影响层（如 `QUAN_UNITS` 增「件/倍」已在 v1.3 做过）。

## 5. 关键设计（为什么要这样做）

1. **original 不手抄**：AI 源数据只写条号/解读，打包器从指纹库注入原文 → 杜绝手抄漂移。
2. **条粒度锚点**：item_id（NN-NNN）是所有层的共同主键；引用字段让层间可跳转。
3. **枚举单点治理**：类型/单位/形态全部收进 `_kg_enums.py`（VERSION 1.3，QUAN_UNITS 34 / QUAN_ORIGINS 24 / QUAN_FORMS 6 / QUAN_SIDES 3 / REG_DOCS 19 / TME_CATEGORIES 14 / TRANS_STEPS 14 / HK_CATEGORIES / HK_CLASSES / LAND_TYPES / LAND_ASPECTS / TRANS_MODES），新增必须 version+1 回填存量。
4. **修复并入打包器**：P0 修复写进生成器，重跑不丢。
5. **实体索引同源写回**：TME/APPT/procs 的 ent_ids 写回（`enrich_layers.py`）复用 `build_entity_links.py` 的 `build_index/match_ents` 同源逻辑，避免手写反查混入叙述文本实体；写回独立于层构建器，重建层不丢字段。
6. **跨层索引一行全看**：`layer_count` 直接告诉你该条贯通了几层；空条目率（4.3%）如实报告。
7. **三处同源**：目录名/文件名前缀/索引槽位名全部复数（ents/rules/regs/procs/structs/appts/tmes/opns），杜绝坑 #28/#29 错位。
