## 1. 问题诊断（先定性，再定量）

### 1.1 现象

遍历 8 层全部文件后确认：**803 条 ENT 实体的跨层引用数为 0**。

| 检查项 | 结果 |
|---|---|
| 实体总数（六卷标注合并） | 803（唯一 id 803） |
| 被任意层记录通过 `ent_ids` 引用的实体数 | **0（0.0%）** |
| rules 层 `subject.ent_ids` / `object.ent_ids` 槽位 | 存在但 **203 条全部为空** |
| regs / procs / structs / appts / tmes / opns 层是否有 `ent_ids` 字段 | **均无此字段**（字段清单里不存在） |
| kg_join 中 layers.ents 挂载 | 正常（254 条目中 234 条挂有实体，共 803 引数） |

**结论**：实体层与条目（registry）的挂载是通的（kg_join 已验证），但与**其余 7 层全部断链**。这不是"某些实体漏了关联"，而是**关联机制整体未建立**——rules 的引用槽位留空了，其余层连槽位都没定义。

### 1.2 语义落位核查（实体"应该属于什么"）

对 803 实体逐条做"文本 → 各层字段值"的落位匹配，判断实体语义上应归属哪一层：

| type | 总量 | 文本至少落入 1 层 | 完全无落位 | 主要落位层（按命中量） |

| person | 352 | 326 | **26** | appts(273) / regs(203) / structs(179) / rules(119) / tmes(117) / opns(85) |
| institution | 142 | 124 | **18** | regs(105) / structs(104) / tmes(73) / rules(71) / procs(48) |
| system | 110 | 107 | **3** | regs(89) / structs(89) / rules(88) / tmes(68) |

| official | 47 | 44 | **3** | regs(41) / rules(37) / structs(34) / appts(25) |

## 2. 55 条真正无落位实体的归类

逐条核对 evidence 后，55 条可分为四类"无处安放者"：

### A. 仓储/场务/分司/驿等**设施实例**（约 21 条，全部 institution）
莱州洋海仓、临濠仓、常盈仓、常平仓、通济库、泰州(分司)、嘉兴分司、沧州分司、胶莱分司、东场分司、西场分司、中场分司、交阯提举司、龙江提举司、来远驿、安远驿、怀远驿、尚膳监 等。
> 特点：它们是**制度的物理实例**（某仓在某地、某分司辖某场），REG 层只有 4 条"仓库"类制度档案（讲制度规则），不含具体设施名录。塞不进 REG 也不适合塞 QUAN。

### B. **短言事人**（约 15 条，全部 person 且证据为「某官 X 言/奏/请/疏」）
刘九皋、郑汝璧、汪应蛟、张慎言、齐庄、赵瑄、官应震、高稹、尹英、高时夏、蓝章、谢达、潘一桂、袁琦（诛宦官）等。
> 特点：OPN 层判据是 `len(quote)≥40 且命中 claim 词`，只有 55 条长奏议进层；这些一句式奏言（"御史 X 言…"）不满足判据，被 OPN 拒之门外。

### C. **不参与任何制度叙述的过场人物/武将/宗室**（约 11 条，person）
邓愈、汤和、宁王权、刘顺、张士诚、严嵩、熹宗、王恕（仅被提及）等。
> 特点：出现在屯田/庄田语境但无任职沿革、无奏议正文，仅"被提及"。

### D. **少数底线散类**（约 8 条）
- system：坊厢里、里社制、九府圜法（制度点但既有 REG 未收录）；
- official：老人、太仆丞、奉御（官职在 appts/tmes 中未出现）；
- place：登莱青(并列)、兖州、仁寿宫庄、交阯（地名未进任何层字段）；
- object：龙涎香（采造物，QUAN 无数额可挂）。

## 3. 塞入方案（主路径：补链回填，不动层架构）

先为 748 条"有文本落位"的实体建立正式引用，再单独处理 55 条。

### 3.1 新增 `_ent_links.json`（推荐，最小侵入）

写 `scripts/build_entity_links.py`，逐层回填引用并产出 `_layers/ents/_ent_links.json`：

| 目标层 | 回填字段 | 匹配方式 | 预计可建引用 |
|---|---|---|---|
| appts | `person` → ENT（person 类） | person 实体 norm 精确匹配 | 249 条（已核对 249/352 在 appts.person） |
| appts | `office` → ENT（official 类） | 精确匹配 | 19/47 |
| opns | `speaker` → ENT（person） | 精确匹配 | 56 条 speaker 全覆盖 |
| tmes | `office` → ENT（official/institution） | 精确匹配 | 3/47 + 73 institution |
| regs | `主体 / 对象 / 执行者` → ENT | norm 子串匹配 + 人工抽查 | 200+ |
| rules | `subject.ent_ids / object.ent_ids`（**槽位已存在**） | subject/object.text 精确匹配 | 203 条规则的多数 |
| structs | QUAN.name/INST.name → ENT | 精确匹配 | 100+ |
| procs | name/scope 中对象 → ENT | 精确匹配 | 36 |

**约定**：`_ent_links.json` 以 `ENT-xxxxx` 为键，值为 `{"appts": ["APPT-…"], "opns": ["OPN-…"], "rules": […], "regs": […], "procs": […], "structs": […]}`。层文件本体不动，validate 增加"实体引用连通率"指标。

### 3.2 补 rules 已有槽位

rules 的 `subject/object.ent_ids` 是留好但空着的——按 §3.1 同样规则直接回填，补完后 rules 层成为第一条真正的"实体↔规则"边。

### 3.3 对"文本命中但语义不实"的兜底

文本命中≠语义引用（如 person 在 regs 字段里出现可能只是举例）。回填时：
- **自动匹配 + 人工抽查 20%**：从每层命中结果抽 20% 人工确认语义成立；
- **超置信对**（person↔appts.person、official↔appts.office）直接落，不抽查。

## 4. 原额外层设计（已否决：不建 C17/C18/C19，缺口改为登记）

> **2026-10-13 定稿**：本节三层均不实施——55 条太少（共仅 6.9%），建 3 个层架构成本大于收益。55 条（加后续归并的其余零链接，共 93 条）统一登记进 `reports/ent_orphans.json`（含 id/item_id/type/norm 全量清单），保留在实体层即可，不影响图谱连通性校验。

### 4.1 C17 设施实例层（FAC）——消化 A 类 21 条 [原设计，已否决]

```
_fac_ai_0N.py / build_fac.py
id: FAC-xxxxx
required: name / kind(仓|库|分司|提举司|驿|场|监) / loc(驻地，可空) / 主管(可空) / 存续(初置·存续·废罢) / item_id(source) / evidence
命名前缀：FAC-，枚举：kind 与位置进 _kg_enums VERSION+1
```
EX：FAC-03042 临濠仓（kind=仓, loc=临濠, evidence=「且建临濠、临清二仓以供转运」）。

### 4.2 C18 短言事层（MEM）——消化 B 类 + 未进 OPN 的短奏言 [原设计，已否决]

```
id: MEM-xxxxx
required: item_id / speaker(言事人，关联 ENT) / office(可空) / gist(言事主旨一句) / verdict(采纳|未采纳|未明) / evidence(原句)
命名前缀：MEM-
```
EX：MEM-01056 刘九皋「言徒民实宽乡」→ 关联 ENT-01056 + ENT-01021(民户)。
> 设计理由：OPN 是"长引语+claim 词"的正式论说层，判据不该放宽；短言事是高频信息（196/352 的 person 都有言事证据），单独成层保住"谁在何时建言什么"。

### 4.3 C19 物产名物层（MAT）——消化 D 类的龙涎香等 + 采造物 [原设计，已否决]

```
id: MAT-xxxxx
required: item_id / name / kind(物产|名物|贡品) / unit(可空) / note(用途/产地，可空) / evidence
```
EX：MAT-06037 龙涎香（采造物，「分道购龙涎香，十馀年未获」）。
> 设计理由：QUAN 只有"有数额的定额"才进（龙涎香无数额），FISC 只有财政流转；无定额采造物无处可去。

### 4.4 其余 D 类兜底指引（不加层）

- system（坊厢里/里社制/九府圜法）→ 本就是制度点，**建议补进 REG**（inst_type=户口/田制/钱钞，走动态追加字段流程，VERSION+1）；
- official（老人/太仆丞/奉御）→ 属"官职典"，原有 appts.office/tmes.office 槽位，若原文有沿革信息可补条进 tmes，无则维持实体层即可；
- place（兖州/登莱青/交阯/仁寿宫庄）→ 归入 3.1 的 regs 回填（scope/对象），不再单独成层。
