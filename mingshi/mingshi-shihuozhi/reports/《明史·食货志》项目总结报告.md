# 《明史·食货志》项目总结报告

> 生成日期：2026-10-13 ｜ 项目：《明史·食货志》数字化知识工程
> 一句话：从 txt 原文到一套 8 层 + C16 总账树可溯源、可重跑、可交叉引用的典志体制度知识资产。

---

## 0. 项目概述

《明史·食货志》（卷五十三～五十八）数字化工程，按用户锁定口径推进：

- **AI 逐条判定 + 代码只验缺漏**（判定与验证严格分工）
- **条粒度**（按条目切分，按句切分被用户否决）
- **original 指纹注入 + 引用关联**（AI 源数据不手抄原文）
- **每卷独立 JSON + 全局归一**（先分卷产出，再归一并验证）
- **枚举顶层封闭 + 动态回填**（新增枚举值必须 VERSION+1 并回溯存量，v1.2→v1.3 已实践）
- **词典全文本内生**（用户明确否决外部词典抓取）

最终形成**底座 + 8 层 + C16 知识资产**：底座（254 条目指纹库）→ L1 实体层 → L2 规则层 → REG 制度层（本书骨架）→ L3 流程层 → L4 食货四维（QUAN/INST/EVO/FISC + HK 户籍/LAND 田制/TRANS 运送链子结构）→ C1 任职层 → C14 沿革层 → C9 论说层 → **C16 九边钱粮总账树** → 实体引用索引 → 引用写回 → 时间线视图 → 跨层索引，另含四卷（食货四/五/六）源数据补遗、OPN 论说缺口补录（55→66）、枚举扩展与全量校验闭环。

**四项用户裁定**（已遵守）：① 5 必建 + 3 强推荐 + 食货四维 + C16 总账树全建；② OPN 论说层建（判据 len(quote)≥40 且命中 18 个 claim 词）；③ 马政不建（原文无独立马政篇，仅附茶法）；④ 县级税额不建查表（原文无偿付定额）。

## 1. 全流程时间线（8 个阶段）

### 阶段 0：底座
- 用户交付 `食货志.txt`（177,909 字节 / 59,693 字符 / 271 非空行）。
- 切分口径：「被正文包围的无句号短行」= 条（两个失败判据留档：按 ◎ 遇。即停 / 首句向前回溯）。
- 产出：`chapters/` 6 卷章节 + `_extract/vol_NN.txt`（格式 `条N|正文`）+ `_data/registry.json` **254 条指纹库**（key=NN-NNN，value 含 original/norm/L/chars）——后续所有层 original 注入源。

### 阶段 1：L1 实体层
- 按卷循环标注，16 类封闭枚举（person/institution/system/place/official/object/doc/era/quantity/behavior/food/plant/work/punishment/animal/unknown）。
- 产出：每卷独立 `01_ents.json…06_ents.json`，**803 标注 / 716 归一实体**。
- 纠偏：实体枚举沿用 `normalize_entity_type` 归一，跨卷同人合并（如于谦、庞尚鹏、刘瑾均归一多源）。

### 阶段 2：L2 规则层
- 规范句（凡 86 / 禁 76 等）→ IF-THEN 规则。
- 产出：每卷独立，**203 条 RULE**。

### 阶段 3：REG 制度层（本书骨架）
- 按用户 13 项制度属性清单建 schema：name/category/evolution/agencies[]/targets[]/levied_items[].form/rates[]/scope+regions[]/documents[]/agents[].kind/purposes[]/abuses[]+opn_ids[]/source。字段标注 list 可拓展 + 支持动态追加（`ext_<key>` 前缀）。
- 产出：全局 `regs.json`，**122 条 REG**；与 L4-INST 分工防第四次刻画（INST 是 structs 上的类型标签，`inst.reg_id` 反指，REG 不反记 INST）。

### 阶段 4：L3 流程层 + C1 任职 + C14 沿革
- 流程：运送链 / 征收规程 / 赋役征解的步骤链。
- 产出：**45 流程 / 170 步 PROC** + **244 条 APPT** + **227 条 TME**（TME_CATEGORIES 继承工厂 11 类 + 本书新增定额变更/法弊/废置 3 类 = 14）。

### 阶段 5：L4 食货四维（定制）+ 结构子类扩展
- 本书对象是制度而非机构，定制四维：**QUAN 数额定额（271）/ INST 制度类型（120）/ EVO 沿革阶段（172）/ FISC 财政流转（107）**。
- 收官轮补三类结构子结构（缺口一）：**HK 户籍（14）/ LAND 田制（17）/ TRANS 运送链（11）**，合计 **712 条 structs**——枚举（HK_CATEGORIES/HK_CLASSES、LAND_TYPES/LAND_ASPECTS、TRANS_MODES）与 ID 前缀（HK-/LAND-/TRANS-）全部过检。
- 枚举治理：QUAN_UNITS 34（含面/株/道等）、QUAN_ORIGINS 24、QUAN_FORMS 6、QUAN_SIDES 3（主兵/客兵/未分）。

### 阶段 6：C9 论说层（OPN）
- 判据：`言：` 98 处长段引述 ≥40 字且命中 claim 词。
- 产出：**66 条 OPN**（原 55 + 收官轮补录 11），全部逐字引原文、含 speaker/opn_type/stance/evidence。
- 纪律纠偏：曾一度写入 speaker="未明"、text 为概括性议论的编造引语 → 逐字引用纪律不容编造，已删除重写（卷五同类问题同因）。
- 收官轮补录（缺口二）：以原文「言：」98 处为检索基准，43 处候选经 8/12/16/20 字滑窗命中判定后筛出 **11 条真实缺口**（如卷4 04-043/04-044/04-053/04-060 → OPN-04012..04015），逐卷 append 到 `_opn_ai_NN.py` 末尾避免 id 位移，其余 32 处为既有 OPN 已覆盖或误报（引语 <40 字 / 无 claim marker），均不入库。

### 阶段 7：C16 总账树（九边钱粮总账）
- 解析食货六 L272–L285「九边钱粮总账」段（14 镇逐镇 主兵/客兵 收入来源与数额）。
- 产出：`ledger_tree.json` 五层嵌套树（总账→镇→兵种→收入类别→明细）+ `ledger_flat.csv`（112 行）+ `ledger_towns.json`（14 镇汇总）。
- 关键判定：甘肃、固原无主兵/客兵分列 → side=「未分」合法；「有奇/馀」约数优先处理（坑 #64，cn2int 修进骨架）；大数可夹在数字中间（四百三十馀万束）。

### 阶段 8：ID 对齐审计 → 跨层索引 → 交付
- 跨层索引：`build_kg_join.py` 建 **254 条目 → 8 层反向索引**，`_kg_join_flat.csv` 平铺 **3239 行**（收官前 2383，HK/LAND/TRANS + OPN 补录后增长）。
- 收官轮新增构建链中段（缺口三）：`build_entity_links.py`（实体引用索引）+ `enrich_layers.py`（引用写回，位置固定于 entity_links 之后、kg_join 之前）+ `build_views.py`（时间线视图）。
- 对口径：目录名/文件名前缀/索引槽位名三处复数同源（坑 #28/#29）。
- 交付聚合：校验报告 + 使用报告 + 总结报告。

## 2. 反思结论

### 反思一（执行期高价值纠偏：枚举封闭治理的两次触发）
核心结论：卷六 QUAN 首次全量校验出现 7 处 `L-structs-ENUM` 违例（unit='件'×5、unit='倍'×1、origin='支放'×1）。**凡枚举确实缺失的合理值（件/倍）直接扩展枚举（VERSION 1.2→1.3），凡语义误填（支放属 FISC_STAGES 而非 QUAN_ORIGINS）则修源数据而非扩枚举**——枚举治理的边界由此定型：先问"是合理新值还是误填"再动枚举。

### 反思二（交付完整性：校验项补齐）
核心结论：早期 `validate_layers.py` 只验 8 层 + C16，未覆盖 kg_join 跨层索引；`summary_stats.py` 更把正式产物 `_kg_join.json` 误列进"遗留（已废弃）"。已补 K 段校验（键集守恒/结构字段/layer_count 一致性/挂载悬空回溯/空条目率入报告/flat 行数守恒）并修正 summary_stats 分类。**交付前校验范围必须覆盖全部正式产物，否则报告数字会自相矛盾。**

### 反思三（收官轮：引用写回复跑与同源回填）
核心结论：TME/APPT/procs 的 ent_ids 写回必须与 `build_entity_links` 同源（同一 `build_index/match_ents`），直接反查 `_ent_links.json` 会混入叙述文本实体（如 TME-01001 误混入"太祖"person）。写回以独立 `enrich_layers.py` 落在构建链末尾而非手改层文件，保证 `build_proc_appt_tme.py` 重建后不丢字段；全链重跑后 validate 仍 ERR=0，证明写回字段（dict 化 person/office、新增 agent 等）全部通过 schema required/enum 检查。

## 3. 根因分析：为什么"重复很多次无用读取"

诚实复盘，重复读取有 4 类根因，其中 2 类工程失误、2 类环境与方向成本：

1. **上下文压缩后的 schema 重读（半可控）**：流程跨多轮，schemas.md 样例未固化在批次提示内 → 改进：schema 样例固化进 summary/报告，valldatable 段直接给样例。
2. **产物覆盖回归导致的重复验证（失误）**：旧 `layers/` 与新 `_layers/` 并存，曾导致验证读到旧数据 → 改进：T1 已把所有 build 脚本统一到 `_layers/`，`_legacy/` 归档、FROZEN_DIRS 护栏告警。
3. **环境噪声导致的重复跑（半可控）**：PowerShell 下 `--volumes 01,02,03` 被拆参致 0 条（坑 #12/#63 同类）→ 改进：多卷用缺省全量或逐卷跑，验证写 .py 脚本并落盘再读。
4. **用户多轮纠偏（方向成本，不是无用读取）**：OPN 判据一开始未核实引语逐字纪律，卷五/卷六各发生一次编造引语返工 → 改进：方向性纪律（逐字引用、枚举边界）开工前先确认、判断标准写死进 SKILL/schemas。

## 4. 方法论沉淀（下次遇到任务的处理原则）

1. **一次探查**：开工前读完全部输入 + schema 样例 + 统计；连续两次读取不再改变计划即停止探查。
2. **先锁 schema 再写数据**：字段口径、枚举、ID 规则一次性定死；打包器注入指纹/关联/校验。
3. **AI 判定与代码验证严格分工**：判定逐条人工（AI）；代码只验缺漏。
4. **所有生成器正式化**：build_ 前缀 + 可重跑 + 幂等；修复并入生成器；多卷参数避免拆参陷阱。
5. **验证一次到位**：校验脚本写文件输出，覆盖全部正式产物（含索引层），重跑前先确认不覆盖已修复字段。
6. **枚举单点治理**：先区分"合理新值 vs 误填"再决定扩枚举或修数据；新增枚举值 version+1 并回溯存量。
7. **方向假设先确认**：粒度/判定方式/交付形态/引用纪律开工前问清。
8. **交付按层聚合**：每层一组（归一汇总 + 验证清单 + 校验报告 + 跨层索引）。
9. **每轮任务建 task 清单**：阶段可见、完成可核（本项目 T1–T7 全程 todo 化）。
10. **如实报告缺口**：空条目率、未建判定（马政/县级税额）、原文边界（Q10/Q11）一律显式写，不静默降级。
