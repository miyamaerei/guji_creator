# 《新官轨范》知识阅读器 · 功能说明与复刻要点

> 用途：给其他项目复刻参考。本文档说明阅读器的定位、架构、数据模型、功能清单与可移植约定，并列出换书复刻的步骤与坑。

---

## 1. 一句话定位

古籍 / 规范类书籍数字化后的**知识浏览器**：把一本书的「原文阅读 + 实体/规则/流程/事件/结构/跨层贯通」六层知识资产放进一个界面，可读、可查、可溯源、可互跳。纯静态前端，双击即开，无后端、无构建。

当前实例：《新官轨范》（明代官箴书）——11 章 274 条目、实体 591、规则 273、流程 274、事件 229、结构 677、五层贯通 209。

## 2. 形态与运行方式

- **纯静态**：1 个 HTML + 2 个 JS + 1 个 data.js，`file://` 直接打开，不依赖服务器。
- **数据内嵌**：`file://` 下浏览器禁止 fetch，因此全部数据由打包脚本固化为 `data.js`（`window.KG`）。
- **三页 + 面包屑 + hash 路由**：`#/reader`（阅读器）、`#/list?layer=…`（总览列表）、`#/detail?kind=…&id=…`（详情页）。

## 3. 目录结构（文件职责）

```
新官轨范_阅读器/
├── 新官轨范阅读器.html   # 入口：布局骨架（顶栏统计/面包屑/左目录/三视图）+ 全部 CSS + 脚本挂载
├── js/
│   ├── kg-common.js      # 共享层 ~30KB：hash 路由/面包屑/卡片与详情组件/规则树组件/文本实体化/原文块
│   └── kg-pages.js       # 页面层 ~45KB：目录渲染/正文渲染/总览列表/详情页/搜索高亮/事件委托/启动
├── data.js               # window.KG 全量数据（1.6MB，勿手工改；改源后重跑打包器）
├── raw/                  # 各层原始 JSON 保真副本（标注/规则/流程/事件/结构/章节/索引 7 个子目录）
├── _backup/              # 修订历史备份（非交付物）
└── _shots/               # 自检截图（非交付物）

build_reader_data.py      # 数据打包器（在项目根目录）：读各层归一 → data.js + raw/
```

## 4. 数据模型（KG 结构 —— 复刻的核心约定）

```js
window.KG = {
  meta:     { chapters, items, entities, rules, procs, events, structs, join_all_five },
  chapters: [ { no, file, name, vol,
                items: [ { iid, text, entities:[{t,ty,s,e,n,eid,c}] } ] } ],
  rules:    { "XGF-R-001": { rule_id, item_id, type, modals, condition, subject,
                             subject_ent_ids, obligation_action, prohibited_action,
                             allowed_action, object, purpose, deadline, punishment,
                             original, source, confidence } },
  procs:    { "XGF-P-001": { process_id, event_type, title, trigger, timeline,
                             steps:[{step_id,state,action,agent,condition,next,agent_ent_ids}],
                             next_process, derived_from, source, original, events[] } },
  events:   { "XGF-E-001": { event_id, type, title, who[], action, what[], when, where,
                             who_ent_ids, derived_rule, original, source } },
  structs:  { "LGR-…": { name, doc_type, fraud, keyword, section, purpose, mechanism,
                         section_cn, item_id, derived_rule, original, source, confidence } },
  entities: { "ENT-001": { normalized, type, surfaces[], count, first_source, alias[] } },
  join:     { "01-001": { item_id, source, rule_id, proc_ids[], event_ids[], struct, ent_ids[] } }
}
```

要点约定：

- **条目粒度（iid）**：`章号-序号`，如 `01-001`，全书唯一、可排序；正文、标注、各层、跨层索引全部以它为键。这是所有结构化的对齐锚点。
- **实体 span**：原文偏移 `s/e` + 归一词 `n` + 主键 `eid` + 类型 `ty`（12 类封闭），阅读器据此做原文着色与点击绑定。
- **跨层索引 join**：一个条目一行，列出它拥有的 rule/proc/event/struct/entity 各层 ID——"五层贯通"页和条目详情全层表都靠它。
- **书证三件套**：每层记录保留 `original`（原文指纹，AI 不手抄）、`source`（出处）、`confidence`（置信度），保证可溯源。

## 5. 页面与交互功能清单

### 5.1 阅读器页（`#/reader`）三栏

| 栏 | 内容 | 关键交互 |
| --- | --- | --- |
| 左·目录 | 卷 → 章 → 1-5 分组 → 条目（四级） | 分组带 ▾/▸ 展开收起；`.cur` 当前组 / `.active` 当前条 / `.open` 展开态三态高亮跟随；点条目正文**只单列该组**（不回列之前组）并滚动定位 |
| 中·正文 | 分组懒加载的条目原文 | 实体词按 12 类型着色可点；点"点击查全层→"进条目详情；搜索关键词 `<mark>` 高亮；分组点击**覆盖式渲染**（不追加） |
| 右·概览 | 当前对象关联总览 | 条目/章/实体/规则/流程/事件/结构卡片，卡片可点进详情；底部 tab 切换「正文 / 条目全层信息」 |

### 5.2 总览列表页（`#/list?layer=…`）独立全宽

- 七个 tab：实体 / 规则 / 流程 / 事件 / 结构 / 条目 / 五层贯通（顶栏统计数字即入口）。
- **独立全宽页**：进入 list 时左目录自动隐藏、列表占满主区，与阅读器视觉分开；面包屑回阅读器。
- 左筛选栏：
  - 规则层渲染为**多级可展开树**：1 级=6 基类（禁止/义务/允许/程序/时限/处罚）→ 2 级=双基类组合 → 3 级 → 4 级；节点计数=子孙累计，**前缀匹配语义**保证「计数=过滤结果数」。
  - 其余层为类型 chip（按数量排序）。
- 右列表：按分类分组的卡片（实体/流程/事件/结构/条目）或规则行（精确 type 分组，带模态徽标与置信度）。

### 5.3 详情页（`#/detail?kind=…&id=…`）

- 保留左目录与顶栏，观感像页面刷新；面包屑完整记录来源链（阅读器 → 总览 → … → 当前对象）。
- 类型化详情（每种内容物有专门渲染）：
  - **条目**：原文（实体着色）+ 全层表；
  - **实体**：词形/别名 + 关联规则 + 关联事件 + 关联结构 + 出现条目反查；
  - **规则**：类型→槽位树 + 补充字段 + 原文 + 来源条目 + 关联流程/事件 + 主体实体；
  - **流程**：流程图（步骤节点+条件分支+箭头）+ 触发/时序 + 原文 + 来源条目 + 来源规则 + 关联事件；
  - **事件**：五元组（who/action/what/when/where）+ 原文 + 来源条目；
  - **结构**：名称/维度/机制 + 引用目录 + 关联；
  - **五层贯通（join）**：**原文之下直接铺开五层**（规则全槽位树、流程步骤序列、事件五元组摘要、结构卡片、实体 chips），无需再点各层引用。

### 5.4 通用组件（复刻直接搬）

| 组件 | 位置 | 作用 |
| --- | --- | --- |
| 面包屑 CRUMBS + `nav/crumbTo` | kg-common | 统一导航、回跳、hash 路由；同页同参去重 |
| `goDetail/goList/goReader` | kg-common | 详情/列表/阅读器统一入口（自动记面包屑） |
| 卡片体系 `bwCard/ruleCard/procCard/eventCard/structCard` | kg-common | 各层列表与详情复用的卡片 |
| `entify(text)` | kg-common | 已知实体词 → 彩色可点 span（文本级绑定） |
| `ruleTypeTree(r)` | kg-common | 复合规则类型 → 槽位树（规则详情核心组件） |
| `oriBlock(text, itemId)` | kg-common | 原文块可点击回来源条目 |
| `itemGroups/renderBodyTo/renderBodyGroupOnly/focusItem` | kg-pages | 目录分组与正文懒加载/覆盖式/单组聚焦 |
| `highlight(q)` | kg-pages | 搜索词 mark 高亮（TreeWalker） |
| 事件委托 | kg-pages | 全局 click 委托，全部 `closest()` 化，跳转统一走 `data-obj/data-id` |

## 6. 复刻步骤（换一本书怎么搬）

### 6.1 数据侧

1. 建**条目底座**：书拆章拆条 → `{iid, text}`（iid=章-序号，唯一可排序），条粒度是硬约定。
2. 建**知识层**：至少一个结构化层（实体 NER 标注 / 规则抽取 / 流程事件…），每层输出归一 JSON，字段自定但保留 `id / original / source / confidence` 三件套。
3. 建**跨层索引 join**：逐条回填各层 ID——五层贯通与条目全层表都依赖它。
4. 改 `build_reader_data.py`：替换输入路径与各层读取逻辑，输出 `data.js`（+ `raw/` 保真副本）。**换书 = 换数据，前端基本不动。**

### 6.2 前端侧

1. 保持「HTML 骨架 + kg-common（共享）+ kg-pages（页面）」三件分离；路由在 common 定义，页面实现由 pages 覆写 `dispatchView`。
2. 目录四级懒加载 + 覆盖式渲染是"大书不卡"的关键（`GROUPS=5` 可调）；点条目单组聚焦避免回列。
3. 实体 12 类型色板集中在 `TYPE_COLOR`；换书可改类型表，但保持 span 渲染契约（`ent ent-<type>` + `data-eid`）。
4. `file://` 环境：数据必须内嵌 data.js；图片要么本地相对路径要么经发布链接，禁止运行时 fetch。

### 6.3 已踩过的坑（直接规避）

- `file://` 禁 fetch → 数据内嵌；改源必须重跑打包器，别手工改 data.js。
- 分组/条目点击曾因「数字/字符串比较不一致」导致目录不显展开态 → 统一 `parseInt` 后再比较。
- 正文覆盖式渲染后需 `scrollTop=0`，否则残留滚动位置触发懒加载误加载下一组。
- 规则树过滤曾用"包含语义"导致计数≠结果数 → 改为**前缀匹配**（节点=子孙累计，点击节点=该子树全部规则）。
- 所有卡片跳转统一事件委托 + `data-obj/data-id`，不写内联 onclick。

## 8. 已知局限 / 可扩展方向

- 单文件内嵌 1.6MB 可接受；书更大时可切分 data 或改用 `http://` + fetch（需本地起服务）。
- 流程/事件的"时序推理"依赖人工/AI 标注的 `steps` 顺序，前端不做自动推断；要状态机/时间轴推理需在抽取层补时序建模。
- 当前为纯前端只读浏览；若需落库（如双库 WorkflowCore + SqlSugar）或多人协作，需另行接入后端。
- 移动端做了媒体查询堆叠（<900px 左目录变顶栏、单列布局），复杂表格型详情建议在移动端再专项优化。
