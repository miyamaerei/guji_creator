## 2. 底座（公共地基）

1. 输入文件：`E:\git\ToolBox\guji\minghuidian\明会典.txt`（2.5MB / 26608 行 / UTF-8）。**唯一权威来源**。
2. 卷切分（**已用 `build_base_v2.py` 修复，180/180 卷全覆盖**）：按卷次标题切 180 卷。已知 OCR 问题及处理：
   - "会"常作"防"（"明防典"="明会典"）
   - 卷标题首字变体 **`眀`(U+7700)**（卷33）→ 正则容忍 `明/眀/朙`
   - "卷"字被 OCR 成**私用区字形 `U+EB08`**（卷128/129/130）→ 分隔符接受 `卷` 或私用区字形
   - **卷122 天头（卷首标题）整行缺失**（仅存页脚）→ 检测"仅一次出现且为页脚"的卷，用前卷页脚作其卷首（其内容"兵部十七·马政"已归位，**非源缺卷**）
   - 每卷标题通常出现两次（天头地脚），以首次出现为卷起点
   - **v1 遗漏的器物/礼仪内容**（卷60/149/150/152/153）：器物行（器物名+数量词）与兜底长行现已单独成条
3. 大卷组切分：按 `references/volume-map.md` 把 180 卷归入 9 组。
4. 条目切分：
   - "凡…"开头的连续段 = 一条事例（item）
   - "诸司职掌"/"皇明祖训"/"大诰"/"大明令"/"明集礼"等典籍直引段 = 一条 CIT
   - 名录段（仓名/卫所/驿/巡检司/器物清单）= 一个 NAM 对象
   - 沿革段（"国初置…洪武X年改…"）= ORG 沿革记录
5. 指纹库 `_item_registry.json`：key=`GG-NNN`（GG=大卷组号 G0–G8，NNN=组内条序），value=original/norm。
6. **ID 由打包器分配**：AI 源数据只写组内槽位，不手写业务 ID。
7. OCR 归一规则：
   - "明防典" → "明会典"
   - "奉防" → "奉旨"
   - 其余错字不强行纠正，保留原文 + norm 字段标注

## 4. L2 规则与时间层

### 4.1 RUL 事例条

- 槽位：`rule_id / item_id / type / modality / condition / subject(含 ent_ids) / action / object / purpose / punishment / source_marker / era / original`
- **文体标记 source_marker 枚举**（凡例自陈）：`诏 / 敕 / 奏准 / 议准 / 奏定 / 议定 / 令 / 凡`
- **规则类型 type 枚举**：`禁止 / 义务 / 允许 / 程序 / 时限 / 处罚 / 优先级`
- **模态 modality**：`不许 / 毋 / 勿 / 务要 / 须 / 止许 / 俱 / 照例 / 违者治罪`

### 4.2 TIM 制度时间线

- 一个事目下的所有 RUL 按 era 排成演变链：`立 / 改 / 罢 / 复 / 增 / 减`
- 例："漕运"事目下，洪武→永乐→宣德→正统→…→弘治，按年串
- `tim_id / item_id / subject(制度名) / era / event_type(立改罢复增减) / detail / ref_rule_ids`

**⚠ 枚举缺漏声明**：source_marker / type / modality 三个枚举是基线，**执行期若遇新文体（如"敕谕""榜谕""条约"）或新模态，必须收集-报告-暂存，走 V3 校准**。

## 5. L3 结构关系层（会典灵魂）

| 子层 | ID前缀 | 干什么 |
|---|---|---|
| ORG 部门结构 | `ORG-` | 衙门→司→事目→属官→属衙的树；建置沿革（"国初置…洪武X年改…"） |
| GEO 地理管辖 | `GEO-` | 布政司→府→州→县；都司→卫→所；十三道→照刷衙门；驿路 |
| RANK 品级等级 | `RANK-` | 品级→章服→车舆→房舍→伞盖（"一品二品正堂五间九架…"） |
| NJC 两京对照 | `NJC-` | 北京制度 vs 南京异制（凡例："南京诸曹分附北京诸曹末，不别立条目，惟体例与北京异者乃别出"） |
| XREF 互见 | `XREF-` | "见某衙门" / "今归某司" / "已上征纳/措备/支给"分组 |

**⚠ 枚举缺漏声明**：RANK 等级枚举（公侯伯一品二品…九品未入流）是基线，执行期若发现新等级对象（如"敕封""诰封""捐纳"），收集后决议。

## 8.5 治理组件（强制启用）

- **V2 人工校验闭环**：同名异人/存疑判定自动收集入"待核清单.csv"（含 provenance），人工核前不强行合并（宁建勿并）。
- **V3 枚举校准（本书重点）**：
  - 执行期打包器收集**未匹配枚举值**（不中断），入 `_pending_enums.csv`
  - 每完成一个大卷组输出枚举使用分布报告
  - 批处理决议：新增 / 归并 / 改名（新增值必须有原文证据）
  - registerVersion+1，回溯存量（旧值→新值映射，dry-run 后 commit）
  - **用户原话："枚举可能有缺漏，要注明如有缺需补上"——本流程是本书质量护栏，必须严格执行**
