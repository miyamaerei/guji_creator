## 〇、一句话结论

**现在的产出是一套"骨架齐全、血肉偏薄"的**索引层**——它把 85 万字切成了可寻址的条目，也抽出了一批名录和主档；但它**还不是一个"可研究的制度知识库"**。核心症结有三：

1. **会典的灵魂（制度因革演变、部门-职掌-品级-俸禄的完整链条、两京差异）没有被建出来**，而这恰恰是研究者最需要的东西；
2. **已经建出来的层，关键字段大面积残缺**，且存在用 `"未明"` 占位充数的"假填充"（如 laws 层 94% 的处罚类型是"未明"）；
3. **层与层之间没有真正打通**——父子关系只有 60 条（1.6%），规则条没有实体 ID，无法做"某衙门牵涉的所有事例"这类反向检索。

如果这次研究的目标是"一次性把明会典结构化"，**当前完成度约 35%**：底料切分基本可用（这一步价值很高，不要浪费），但**知识层需要按下面的路线图系统性重建**。

## 二、够不够？——分三个层次回答

### 2.1 作为"可寻址的索引"：**够了**
任意一条原文都能按 `卷-事目-条` 定位，`item_id` 可回原文。这一步的工程价值真实存在，**不要推翻，要在此之上重建**。

### 2.2 作为"可查询的部门/官职手册"：**基本够，但有明显洞**
- "吏部尚书是几品、管什么、上级是谁"——**能答**。
- "这个官职的**沿革**（哪年设、哪年改、哪年罢）"——**答不了**（history 仅 1%）。
- "这个衙门的**完整属司树 + 每司职掌**"——**只对 73 个衙门有效**，且 child 关系 37%。
- "这个官职的**散官对应、勋官、封赠**"——**残缺**（散官 70、勋官 12）。

### 2.3 作为"可研究的制度知识库"：**远远不够**
研究《明会典》的人，真正要问的是**制度如何运作、如何演变、彼此如何勾连**。当前产出在这些问题上基本无法作答——详见第四部分 10 个问题。

**根本判断**：当前产出把会典当成"**名录 + 条文清单**"来抽，而会典的本质是"**以职掌为纲、以事例为目、以因革为脉**"的**制度体系**。抽取口径与文本性质错位，是"不够"的深层原因。

## 三、字段够不够？——逐层诊断

### 3.1 rules（规则事例）——**最需要重做的一层**

设计 schema 要求：`rule_id / item_id / type / modality / condition / subject(含 ent_ids) / action / object / purpose / punishment / source_marker / era / original`

实际只有：`item_id / type / source_marker / subject / action / condition / purpose / id / confidence`

| 缺失字段 | 为什么致命 |
|---|---|
| `original` 原文 | 无法溯源、无法核对——**正史研究的底线** |
| `subject_ent_ids` | 无法反查"某衙门的所有事例" |
| `object` 对象 | 无法问"关于漕运的所有规定" |
| `condition` 仅 6% | 规则缺"适用条件"，等于没有 IF |
| `punishment` 0% | 处罚类规则形同虚设 |
| `era` 时间 | 无法做时间线 |

**结论：rules 层需要按 schema 重抽**，重点是补齐 `original`（可从底座回填）、`era`、`condition`、`object`、`subject_ent_ids`。

### 3.2 office_profiles（官职主档）——**字段设计好，但没填满**

已设计的字段很到位（品级/类型/系统/编制/职责/上下级/位置/沿革/俸禄/散官）。问题在填充率：
- **history 1%**：会典里大量"国初置…洪武X年改…"沿革没抽出来；
- **child_offices 13%**：属官关系没建；
- **duties_source 35%**：职责缺出处。

### 3.3 org_profiles（部门主档）——**质量最好的层，但只覆盖 73 个衙门**
应扩展到：六部各司、都察院十三道、五寺、翰林院、地方三司、卫所、宦官二十四衙门、女官六局等。目标 **200+ 衙门**。

### 3.4 geo_profiles（地理主档）——**数量够，但没成"管辖树"**
2,047 条覆盖府/州/县/卫/所，但 `parent_geo` 大量是占位符字符串（如 `"都司"`），**没有真正的省→府→州→县链条**，也没和"驻防卫所/驿站/仓场"关联。GEO 层（2,913 条）与 geo_profiles 重复且未打通。

### 3.5 laws / rituals / foreign / inspect / dress ——**存在"未明"假填充**

这是**最需要警惕的质量问题**：
- laws：`punishment_type` 307/326 = "未明"，`source_law` 297/326 = "未明"；
- rituals：`location` 299/410、`participants` 287/410、`source` 339/410 = "未明"。

这些字段"填了"，但填的是"不知道"。**记录数虚高，实际信息量为零**。必须要么真抽、要么留空并标注"待补"。

### 3.6 person_profiles / process_profiles ——**名不副实**
- person_profiles 157 条**没有人物姓名**，只有官职名，无法使用；
- process_profiles 490 条**没有步骤**，`process_name` 只是标题截断。

### 3.7 底座字段 ——**建议增补**
`_item_registry.json` 已有 `section/title/original/norm/source`。建议增加：
- `node_kind`（事目/事例/名录行/标题/沿革）——解决过度切分；
- `volume`（卷号，便于按卷检索）；
- `era_hint`（该条涉及的年号列表）。

## 五、补全路线图（建议按此优先级推进）

### P0 — 修复地基与假填充（1–2 天，收益最大）
1. **补 9 个缺失卷**（033/060/122/129/130/149/150/152/153，含 OCR 漏识别的 130 卷）；
2. **清除"未明"假填充**：laws / rituals / foreign / inspect 中把 `"未明"` 改回空值并标注 `_todo`，避免误导；
3. **底座增补 `node_kind` + `volume` 字段**，把 11,135 条区分为 事目/事例/名录行/标题/沿革；
4. **实体类型归一**：`institution→org`、`official→off`、`person_title→off`，与 schema 对齐。

### P1 — 重建核心层（3–5 天，决定研究价值）
5. **rules 层重抽**：补齐 `original`（底座回填）+ `era` + `condition` + `object` + `subject_ent_ids`；
6. **建 TIM 制度时间线层**（Q1）：以事目为单位，把"国初置…洪武X年改…"抽成演变链；
7. **office_profiles 补沿革**（history 1%→70%+）、补 `child_offices`、补 `duties_source`；
8. **org_profiles 扩到 200+ 衙门**，建立真正的部→司→科树。

### P2 — 补缺失结构层（3–5 天）
9. **建 RANK 品级等级树**（Q7）：一品→九品 × 章服/车舆/房舍/伞盖；
10. **建 NJC 两京对照层**（Q5）；
11. **建 XREF 互见层**（Q3），复原"已上某"分组体系；
12. **geo 成管辖树**（Q6）：省→府→州→县，并关联卫所/驿站/仓场。

### P3 — 数字、文册、器物（2–3 天）
13. **建 NUM 数字则例层**（Q8）：税粮/俸禄/工价/祭品的键值对；
14. **建 REPORT 文册勘合层 + 扩 CIT 到全 12 部书**（Q9）；

### P4 — 打通与交付

17. **重建 `_kg_join`**，rules 挂上 ent_ids，实现反向检索（Q10）；
