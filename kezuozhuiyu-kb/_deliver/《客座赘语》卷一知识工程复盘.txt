《客座赘语》卷一知识工程复盘
（填写阶段 + 验收阶段方法与教训，供卷二至卷十照抄）

────────────────────────────────────────
一、本次执行概览

卷一（34 条正文）作为全工程第一本试装卷，完成 13 层知识层
（ent/event/cit/obj/cus/ming/geo/appt/nam/lit/opn/rel/trl）实装、
统一打包与三连自检。最终规模：
  ent 598 | event 29 | cit 35 | obj 74 | cus 31 | ming 34
  geo 47 | appt 20 | nam 10 | lit 16 | opn 29 | rel 12 | trl 34
跨层 _kg_join 34 条，零层条目 0，每条至少命中一层。
自检结论 PASS（缺字段 0 / 重复 ID 0 / 坏引用 0）。

────────────────────────────────────────
二、填写阶段：经验与教训

1. 实体标注先行，ENT 是引用解析的地基

第一次打包暴露的最大问题：*_ent_ids 引用未解析量大。
根因不在匹配逻辑，而在 obj 层名物（卷一 01-012~018 的植物、
动物、饮食）在 ENT 源数据里基本未标注——ENT 当时只标了
地理、人物、书目。

教训：写任何一层之前优先盘点本卷"必标实体清单"；补标实体
要跟着 obj/cit/geo 等层的实际提及走，不能只凭感觉标人物地名。
卷一为此补标约 90 条（ENT 从 508 → 598），修复成本远高于
一开始就摊开的标注成本。

2. 名称规范化：用括注消歧，不留无出处词形

REL 源初稿里的"皇太子（朱高炽）""朱元璋（高皇帝）"
"王公（顾起元外舅）"这类"主名（括注）"形式不处理，精确匹配
必失败。卷一最终定的规范：引用侧写主名，括注只用于消歧，
由打包器按"剥括注 → 括注内 → 双向子串"逐级解析；同时 ENT
侧把别名登记进去（如"高皇帝""先大夫"）。

教训：源数据里凡是引用了人物/书名/地名的，先确认该词形已在
ENT 登记，或按 ENT 的标准词形改写，不要自造无出处的新词形。

3. 字段键名必须对齐 schema，不许凭印象

卷一自检第一次跑出"event 29 条全缺字段、cit 70 个缺字段"，
根因是自检脚本按印象写了 event: [summary/when]、cit:
[title/quotation]，而实际 schema 是 event: [type/action/who/
where/when/what]、cit: [cited_work/citation_type/context]。

教训：写法与校验都必须以 LAYERS 配置的 must_fields 为唯一
真源，任何一层都不允许手写第二份字段清单。卷二起直接复用
校验脚本，避免同型错误。

4. 一条正文条目对应多条同层记录是常态

同一 item 下的 event、cit、obj、cus 往往多条（卷一 event 29
条、cit 35 条、obj 74 条，对应 34 个 item）。_kg_join 里同层
键接收集合而非单选，填写时每条记录仍以 item_id 为锚、各自
独立成条，不要试图合并。

────────────────────────────────────────
三、验收阶段：经验与教训

1. 自检脚本必须读真实产物，不读猜测

- _kg_join 的产物是 _layers/_kg_join.json（统一文件，键 rows，
  每行含 volume 字段），不是按卷拆分的 _kg_join_01.json。
  首次自检用 read_layer_volume("_kg_join", vol) 读到 0 条，
  属读取路径错误，已改为专门读 join 文件并按 volume 过滤。
- miss 日志语义要写清楚：打包器打印的"缺字段 N"里的 miss
  指引用未解析（含"成功命中也被误记"的 bug，已修复），不是
  真的字段缺失。看 _validate/*_缺失清单.txt 时先区分两类问题。

2. 验收分三步走（三连自检）

(1) 字段完整性：逐层核对 must_fields 非空、无占位词
    （未明/不明/无不记 miss）；
(2) 主键与关联一致性：ID 无重复、引用字段指向的 ID 必须存在
    （ID_REF_FIELDS 全查）、join 只包含 registry 中真实存在的 item；
(3) 抽样原文回查：抽 ent 核对 start/end 偏移与原文逐字一致；
    抽 opn 核对 topic/stance/argument 是否忠实原文；
    抽 trl 核对译文忠实度与 style/confidence 标注合理。

卷一抽样结果：ent 偏移逐字一致、OPN 论断与 TRL 译文均忠实
原文，才判定 PASS。

3. 修复顺序要按根因倒推

引用未解析时按"缺 ENT 标注 → 名称词形不规范 → 匹配逻辑不足"
的顺序排查，先补数据，最后才动匹配器。卷一正是先补标 90 条
ENT、规范化 REL/ming 词形后，剩余未解析才归到匹配逻辑增强
（剥括注、子串兜底、剔占位词）。

────────────────────────────────────────
四、卷二至卷十执行口径（可照抄）

【填写前】
1. 通读本卷 _extract/<NN>_卷N.txt 全文，确认 _item_registry.json
   中 NN- 前缀条目数与卷内小标题一致；
2. 按本卷正文列"必标实体清单"草稿（人物/地名/职官/书目/名物，
   名物尤其留意植物、动物、饮食、器物），先补 ENT，再写其他层；
3. 引用关系中出现的任何词形，先查 ENT 是否已登记；未登记先补，
   或用 ENT 已登记的标准词形改写。

【填写中】
- 每层源文件只写 item_id + 本层语义键；业务 ID（ENT-/EVT-/
  CIT-/OBJ-/CUS-/MING-/GEO-/APPT-/NAM-/LIT-/OPN-/REL-/TRL-）
  一律不手写，由打包器按序分配；
- 字段键名严格照 LAYERS 配置的 must_fields，不自创键；
- original/norm 不手抄，靠打包器从 registry 注入。

【填写后】
  python build_layers.py --volumes NN
  python validate_layers.py --volumes NN

- 打包输出看三点：13 层条数、_kg_join 总数、零层条目数（应为 0）；
- 自检输出必须逐层 0 缺字段 / 0 重复 ID / 0 坏引用，join 口径不变；
- 补一个抽样回查（ent 偏移 + opn + trl 各 2-3 条）；
- 全部通过后交付 _deliver/_kg_join_flat.csv 与 _layers 层文件。
