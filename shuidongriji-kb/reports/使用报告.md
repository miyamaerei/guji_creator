# 《水东日记》使用报告

> 生成日期：2026-10-10 ｜ 适用读者：后续接手者 / 需要查询这套知识资产的人
> 一句话：明・叶盛《水东日记》（四库本，约 12.8 万字无句读原文）→ 一套可查询、可溯源、可重跑的 8 层知识库 + 全书记译文本合册。



***

## 1. 项目定位

本项目为明・叶盛笔记《水东日记》（四库全书本，38 卷 + 卷首四库提要 1 卷，共 1197 条记事）的数字化知识工程，服务明朝职官知识图谱（人物 / 职官任职 / 机构 / 制度供料）与独立可查询知识库。从无句读原文出发，逐层产出机器可读、可交叉引用的结构化知识：



```
水东日记.txt（无句读）→ 卷拆分(39卷) → 条目切分(1197条指纹) → 实体标注层(ent)
  → 职官任职层(appt) / 事件层(event) / 典章制度层(reg) / 文献资产层(lit)
  → 人物关系层(rel) / 名录谱牒层(nam) → 古今翻译层(trl) → 跨层索引(_kg_join)
```

所有层遵循同一口径：**词典 + 规则先行候选 → AI 逐条判定 → 人工校验闭环；条粒度（item\_id）；original 指纹注入（AI 不手抄原文）；每卷独立 JSON + 全局归一；枚举封闭治理（registerVersion）；全文本内生词典（不取外部词典）**。

## 4. 怎么使用

### 4.1 快速查询（不跑代码）



* **一行看全某条**：打开 `交付物/01_跨层索引.csv`，按 `item_id`（形如 `17-003`）过滤 → 该行平铺列出该条在 ents/appts/events/regs/lits/rels/nams/trls 各层命中的 ID 与 `layer_count`（贯通层数）。

* **查实体 / 别名反查**：`data/ent/ent_keys.json` → `entities[]`（ent\_id/normalized/type/count/first\_source/surfaces）；`alias_index` 支持 "归一化词形 → ENT ID" 反查（2291 条）；`交付物/02_实体主键表.csv` 为同一数据的扁平表。高频实体如：六科 ENT-161（45 次）、叶盛 ENT-145（42 次）、京师 ENT-020、礼部 ENT-001、吏部 ENT-183、锦衣卫 ENT-175。名录人物补建登记见 `data/ent/名录补建登记.csv`，同名异人待核见 `data/ent/同名异人待核清单.csv`。

* **查任职**：`data/appt/appt_NN.json` 或 `交付物/层聚合/appt.csv`，按 item\_id /person/office 过滤；字段 person/office/institution/when/status/evidence。

* **查制度 / 文献 / 事件 / 关系 / 名录**：对应层聚合 CSV 同法过滤；nam 层 `entries` 列是 JSON 字符串（四元组 {seq, person, courtesy\_name, hometown, office}），表格类题名（如卷 17 都御史题名 86 人、两广方岳郡守题名 154 人）在其中展开。

* **读译文**：`交付物/全书记译文本/《水东日记》全书记译文本（38卷合册）.md`，按 `### NN-NNN` 定位任意条译文与译注。

### 4.2 全文回查（溯源）

任何层记录都带 `item_id`、`original`、`norm` 三字段：`original` = 指纹库原文（打包器注入，非手抄）；`item_id` → `_extract/items/NN_卷名.txt` 与 `_extract/volumes/NN_*.xhtml` 回查原文位置；`ent_keys.surfaces` 列出该实体出现过的全部条目号。ent 标注另带 `start/end` 字符偏移与 `source` 原文片段。

### 4.3 可重跑管线（改了数据后全量重建）



```
# 全量重建（底座 → 实体主键 → 8 层 → 跨层索引 → 验证）
python run_all.py

# 仅重跑指定卷（幂等；build_base 已修复为增量合并，单卷复跑不截断共享指纹库）
python run_all.py --volumes 01 17

# 单层重跑
python build_ent_keys.py --volumes 01
python build_nam.py --volumes 29
```

跑完核对 `reports/验证缺漏清单.txt`：结构性问题 ERR = 0 为通过标准。

### 4.4 扩展指南



* **加实体词条**：AI 源数据中先查 `ent_keys.json` 的 `alias_index`，已存在直接复用 ENT ID，新建才分配；打包器 `build_ent_keys.py` 幂等合并。

* **加层记录**：编辑 `sources/_<layer>_ai_NN.py`（只写条号 + 解读字段，original 不手抄）→ 重跑对应 `build_<layer>.py`。

* **新枚举值**：单点修改 `_kg_enums.py` 并 `registerVersion+1`，重跑受影响层（预期不需要 —— 当前枚举已封闭：APPT\_STATUS 9、ENTITY\_TYPES 8、EVENT\_TYPES 15、REG\_TYPES 11、LIT\_TYPES 10、REL\_TYPES 12、REL\_DIRECTIONS 3、NAM\_TYPES 6、TRL\_STYLES 3、VOL\_MODES 7）。

* **重新生成交付物**：`交付物/` 由一次性聚合脚本产出（跨层 CSV、实体主键表、8 层 JSON/CSV、合册），管线重跑后需重新执行该聚合步骤使交付物与 data/ 同步。

## 5. 关键设计（为什么要这样做）



1. **original 不手抄**：AI 源数据只写条号 / 解读，打包器从指纹库注入原文 → 杜绝手抄漂移。

2. **条粒度锚点**：item\_id（NN-NNN）是所有层共同主键；kg\_join 按 item\_id 一行贯通 8 层。

3. **枚举单点治理**：全部类型收进 `_kg_enums.py`，验证器按 registerVersion 快照核对（校验维度 G）。

4. **ID 段位防撞号**：各层 ID 按 "卷号 ×500+1" 分断（卷 01 试点占 1–99、卷 17 占 301–425），跨卷全局唯一，validate 按层全局判重。

5. **逐卷阅读模式**：38 卷按主导类型分配层优先级（制度 05/06/30、名录 17/29、谱牒 15/16/18/20、文献 19/22/35/13/26、长文卷 14/21/23/24/28/30/37/38、均衡 01），层稀疏分布是模式产物而非缺陷。

6. **TRL 全量硬校验**：每卷条目数 = 翻译数（validate 维度 F），当前 38 卷逐卷相等，合计 1192 = 1192，零执行缺口。
