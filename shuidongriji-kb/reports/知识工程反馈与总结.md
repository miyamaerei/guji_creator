# 《水东日记》知识工程反馈与总结

> 生成日期：2026-10-10 ｜ 面向：book-knowledge-factory 及后续同类实例
> 一句话：明·叶盛《水东日记》38 卷 × 8 层知识工程全量执行后的复盘——设计回顾、问题与根因、可修正项分级反馈、枚举拓展建议。

---

## 1. 项目设计回顾

### 1.1 输入与底座
- 输入：无句读原文（约 13.3 万字，四库全书本）。
- 底座：按"卷首行 + 卷尾落款"切分 39 卷（卷 00 四库提要 + 卷 01–38 正文）；逐行切条，剔除装饰行（书签行/撰者题名行/钦定行），产出 1197 条指纹库 `_item_registry.json`（key=NN-NNN，value 含 original 与 norm 双形态）。
- 指纹库是全部 8 层的锚点：AI 源数据只写条号+解读，原文由打包器按条号注入——杜绝手抄原文引入的转写误差。

### 1.2 8 层结构（不建 L2/L3）
| 层 | 内容 | 本实例最终量 |
|---|---|---|
| ent | 实体标注（8 类封闭枚举） | 标注 2253 / 归一实体 2291（person 1577，含名录补建 391） |
| appt | 职官任职（person/office/institution/when/status） | 237 |
| event | 事件（who/action/what/when/where） | 234 |
| reg | 典章制度（name/type/content/institutions/officials） | 72 |
| lit | 文献资产（title/author/type/content_location） | 180 |
| rel | 人物关系（person_a/person_b/type/direction） | 126 |
| nam | 名录谱牒（entries 四元组数组化） | 54 记录 / entries 567 行 |
| trl | 古今翻译（注释性翻译·余光中风格，全量逐条） | 1192 |

跨层索引 `_kg_join` 按 item_id 把 8 层命中聚为一行（layer_count=贯通层数），JSON+CSV 双形态。

### 1.3 卷阅读模式
7 种模式（制度/人物/文献/谱牒/名录/文事优先 + 均衡全层）标注到卷，决定层优先级与预期稀疏度：制度 05/06/30、名录 17/29、谱牒 15/16/18/20、文献 19/22/35/13/26、长文 14/21/23/24/28/30/37/38、均衡 01。诗文/谱牒卷 APPT/REG/REL 空层为模式产物而非遗漏，均已在源数据注释登记。

### 1.4 ID 段位与全局唯一
各层 ID 跨卷全局判重（validate seen_ids）。确立"卷 NN × 500 + 1 起编、段容量 500"（卷 02→1001…卷 38→19001；试点卷 01 占 1–99、卷 17 占 301–425）。层间独立命名空间。

### 1.5 管线
scaffold 模板（幂等）→ AI 逐条判定（先查后建、只写条号+解读）→ 逐层打包 → 逐卷验证（本卷 ERR=0）→ 全量收敛（python run_all.py 权威重建）。治理机制：枚举封闭（_kg_enums.py，registerVersion 单点）、词典全文本内生（不取外部词典）、宁缺毋滥（REL 只建有直接证据的关系）。

### 1.6 交付形态
按层聚合 JSON+CSV（跨层 CSV 置最前）、实体主键表、全书记译文本 38 卷合册（1192 条）、《使用报告》《项目总结报告》；全部文件形态（不落库）。

## 2. 执行中发现的问题与根因（逐项）

1. **build_base --volumes 截断共享指纹库**：原实现从空字典重建 registry、按 --volumes 过滤，单卷复跑会把共享指纹库从 1197 条抹成该卷条数（试点两卷都曾触发），下游各卷产物对照"不在指纹库"报 ERR。已修复为增量合并语义（加载现有 registry → 只重算请求卷 → 合并写回；全量模式仍从空重建为权威），并补 volume_summary.csv 增量合并（数字字段转 int）。
2. **跨卷业务 ID 撞号**：各 worker 从 001 起硬编码分配 APPT/SDJ-E/REG/LIT/REL/NAM/TRL 编号，validate 又按层全局判重，并行执行必然撞号（卷 01/17 试点即互撞）。根因：ID 分配权在 AI 源数据而非打包器。段位方案缓解，治本见 3.1。
3. **并行子代理半写文件与汇总竞态**：并行片写入 sources 过程中，他片 run_all 的 build_kg_join/汇总步骤读到半写文件触发瞬时 ValueError；summary 类共享文件存在"最后写入者覆盖"。均为瞬时态，重跑即恢复，未污染最终产物。根因：无原子写入、共享文件无合并语义。
4. **枚举与原文不匹配（执行期 5 次中断）**：LIT 无"集"、EVENT 无"军政/司法/边政"、REG 无"祭祀"、APPT_STATUS 无"起复/世袭/举荐"。执行期按就近合法值归并（语义损耗），详见第 4 章。
5. **TRL 长文翻译体风险**：碑文/序/奏议/书启等长文卷（13/14/19/21/22/23/24/26/28/30/37/38）翻译主观性最强，易滑向翻译体公式；以余光中七条规范（译原意不译原字、长句拆并联、专名保留+括注、忌翻译体）约束，但机器产出仍需人工复核闭环兜底。
6. **名录卷"行=表格行"与条目切分的张力**：指纹库逐行切条，而题名表一行多人、跨行四元组（卷 17 都御史题名/两广方岳郡守题名、卷 29 六科旧僚题名、卷 34 宣府守将题名、卷 25/32 表格式题名）不能按行硬拆。口径：NAM/APPT 按表重组、entries 四元组数组化、一行多人分行承载，卷内上下文（科/路/官位分段）作为 office 上下文。
7. **卷 00 不入 8 层**：按已确认方案，四库提要 5 条不入层、无 TRL，跨层索引 layer_count=0。
8. **ent 层键名不统一**：ent 单卷 JSON 顶层键为 annotations，其余层为 records，聚合器需特判（集成阶段已处理，但属于 schema 瑕疵）。
9. **validate --volumes 语义名不符实**：带 --volumes 参数仍全卷检查，仅靠"只看本卷行"约定判定本卷质量，易误读全局 ERR 数。
10. **trl.csv 物理行 ≠ 逻辑行**：译文单元格内含换行，物理行 1313 ≠ 逻辑行 1192，属 CSV 引号正确行为，解析须按逻辑行（csv.reader）判数。
11. **跨层 ent_ids 大量留空**：试点起为避免并发悬空引用 ERR 采用空数组约定，kg_join 按 item_id 链接，实体级连通弱。任务 A（名录补建）已按人名回填 NAM ent_ids，但同名异人需人工核（清单见 data\ent\同名异人待核清单.csv）。

## 3. 可修正项（对 book-knowledge-factory 反馈，分优先级）

### 3.1 建议修正

**P0（治本）**
- **build_* 增量模式语义统一**：所有 build 脚本统一"加载现有共享文件 → 只重算所请求卷 → 合并写回"；全量模式从空重建为权威。杜绝"重建即截断"类事故（本项目 build_base 已修，建议推广到 summary/join 等全部共享产物）。
- **ID 分配改为打包器自动分配**：源数据只写"槽位"（如 `{slot:1}` 或按卷内顺序），打包器按卷段位自动编业务 ID；AI 不再手写 ID。消除跨卷撞号、重编号成本与"ID 即内容"的错误耦合。

**P1（体验与效率）**
- **层聚合字段统一**：各层 JSON 顶层键统一（records），或聚合器自动识别 annotations/records；每记录必带 volume 字段。
- **validate --volumes 语义修正**：真正按卷过滤输出，或改名并明确"全卷检查、只看本卷行"约定。
- **卷模式→层优先级自动化**：volume-profile 机器可读化，scaffold 按模式自动生成各层模板与建议量级（制度卷 reg 模板、名录卷 nam 模板）。
- **指纹库与源数据的校验时机前移**：源数据落盘即校验条号存在性（scaffold 后、填写前），避免"源文件存在但条目号不在指纹库"类 ERR 晚发现、晚返工。

**P2（鲁棒性）**
- **并行写 sources 原子性**：写临时文件 + rename 落盘，避免半写文件被并行 build 读取。
- **summary/共享文件合并规则**：统一为增量合并（本项目 build_base 已修，其余层 summary 待统一）。
- **TRL 长文分段规范**：长文卷提供"分句群译"模板与篇幅参考，减少机器翻译的主观漂移。

### 3.2 建议保留
条粒度（item_id 全层锚点）；8 层 + 跨层索引结构；卷阅读模式索引；词典 + 规则先行 → AI 逐条判定 → 人工校验闭环；先查后建（alias_index 幂等累积）；宁缺毋滥（REL 只建有直接证据的关系）；original 指纹注入（AI 不手抄原文）；枚举封闭治理（registerVersion 单点）；ID 段位方案。

### 3.3 建议新增机制
- **人工校验闭环接口**：产"待核清单 CSV"（本项目已落地 data\ent\同名异人待核清单.csv：ent_id/人名/四元组/来源卷/nam_id/原因/建议），专家修订后回写（合并 ENT/改 normalized/修订 TRL），版本化记录。
- **provenance 溯源字段**：每个记录携带 source（卷-条号）与 evidence（判定依据）；新建实体带 first_source；图谱化阶段可逐条追溯。
- **同名异人登记表**：与 alias_index 分离的独立表；跨卷同名自动收集待核（本项目任务 A 落地，人工核前不强行合并）。

## 4. 枚举拓展建议（本实例实测）

### 4.1 验证充分的项（建议保持）
| 枚举 | 现状 | 实测证据 | 结论 |
|---|---|---|---|
| ENTITY_TYPES 8 项 | person/place/official/work/institution/era/unknown/posthumous | person 1577（含名录补建 391）、place 271、official 141、work 134、institution 77、era 76、unknown 14、posthumous 1 | 覆盖充分；posthumous 低频但真实（谥号称谓），保留 |
| NAM_TYPES 6 项 | 官员题名/同僚题名/迁谪录/谱牒/题名记/其他 | 54 条记录全覆盖 | 充分 |
| REL_TYPES 12 项 | 同僚/师生/姻亲/同乡/同科/举荐等 | 126 条全覆盖（"举荐"已有） | 充分 |
| TRL_STYLES 3 项 | 直译/意译/注释性翻译 | 注释性翻译为主，直译/意译零星 | 充分；直译/意译可保留为兜底标签 |
| VOL_MODES 7 项 | 制度/人物/文献/谱牒/名录/文事/均衡 | 全卷有归属（长文卷并入文献/文事） | 充分，无需新值 |

### 4.2 建议新增值（理由 + registerVersion 处理）
| 枚举 | 建议新增 | 理由（实例证据） | registerVersion 处理 |
|---|---|---|---|
| LIT_TYPES | **"集"**（后续可再拆"别集/总集"，本期只加"集"） | 原文出现诗文集/全集标"集"（卷 08 金台集、张养浩全集），现归"其他"损失类型信息 | registerVersion+1；回溯存量：将 title 含"集/全集/文集"且现 type="其他"的条目改回"集"（本项目约 1–2 条，逐条核对） |
| EVENT_TYPES | **"军政"、"司法"、"边政"**（或明确三词与现"军事/其他/边事"的分界） | 卷 26 五品奏请断罪（司法色彩，现归"其他"）；卷 22 整饬边备、军事整编（现归"军事"）；边地治理（现归"边事"）——语义损耗 | registerVersion+1；回溯：将"其他"中司法类、"军事"中军政类、"边事"中边政治理类改回 |
| REG_TYPES | **"祭祀"**（从"礼仪"拆出或明确定义"礼仪"含祭祀） | 卷 30 祭社稷/城隍/山川为明代典制实体，现归"礼仪" | registerVersion+1；回溯卷 30 祭祀条目改 type |
| APPT_STATUS | **"起复"、"世袭"、"举荐"** | 原文出现丁忧起复、武职世袭、荐举入仕（卷 05/06 等），现归"现任"等，语义失真 | registerVersion+1；回溯：执行期误归"现任"的起复/世袭/举荐条目改回 |

### 4.3 建议修正项
- **命名对齐**：EVENT 与 REG 枚举词表不一致（EVENT 无"军政/边政"而 REG 有；REG 无"祭祀"而 EVENT 无此概念）——执行期两处混用（卷 22 误用"军政"、卷 30 误用"祭祀"各一次）。建议两枚举共享概念词表（同一词干），仅层语义不同。
- **合并**：无强合并需求；TRL 的"直译/意译"占比极低，可并入"注释性翻译"变体或保留兜底。
- **拆分**：LIT 加"集"后可再按需拆"别集/总集"；ENTITY_TYPES 的 unknown 兜底保留（拒识优于乱识）。
- **定义补全**：每个枚举值加一句"使用说明"（语义 + 正反例），从源头减少同名不同义误用。

### 4.4 对 book-knowledge-factory 的通用建议（枚举如何随实例校准）
1. **流程**：实例先跑 → 打包器收集"未匹配值"（不终止，入 pending 表）→ 每卷/每片结束输出枚举使用分布 → 批处理决议（新增/归并/改名）→ registerVersion+1 → 回溯存量（旧值→新值映射，逐条 dry-run 再 commit）→ 更新快照。
2. **校验模式**：把枚举校验从"报错终止"改为"收集-报告-暂存"——执行期不因枚举缺失中断（本项目 5 次中断均因此），收尾统一决议，显著降低返工。
3. **新增值必须有理由与实例证据**（如 4.2 证据表），避免拍脑袋扩表。
4. **动态回填工具**：registerVersion 递增后提供回溯脚本（按映射批量改、dry-run 预览、commit 留痕），供旧实例升级。
