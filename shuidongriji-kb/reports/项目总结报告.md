# 《水东日记》项目总结报告

> 生成日期：2026-10-10 ｜ 项目：明·叶盛《水东日记》数字化知识工程
> 一句话：从 13 万字级无句读四库原文到一套 8 层可溯源、可重跑、可交叉引用的明朝笔记知识资产 + 全书记译合册。

---

## 0. 项目概述

《水东日记》（明·叶盛撰，四库全书本）数字化工程，按用户锁定口径推进：

- **词典 + 规则先行候选 → AI 逐条判定 → 人工校验闭环**（判定与验证严格分工：AI 写解读，代码只验缺漏）
- **条粒度**（每行 = 一条记事；名录/谱牒表格式行按表重组，不硬拆）
- **original 指纹注入 + item_id 引用关联**（AI 源数据永不手抄原文）
- **每卷独立 JSON + 全局归一**（先分卷产出，实体主键随卷累积、先查后建、幂等合并）
- **枚举顶层封闭 + 动态回填**（`_kg_enums.py` 单点治理，新增必须 registerVersion+1 并回溯存量）
- **词典全文本内生**（不取外部词典；实体归一靠先查后建与 alias_index）

最终形成 **底座 + 8 层知识资产**：实体层 ent → 职官任职 appt → 事件 event → 典章制度 reg → 文献资产 lit → 人物关系 rel → 名录谱牒 nam → 古今翻译 trl，外加跨层索引 `_kg_join`。按方案决策：**不建 L2/L3 抽象层**、**双库落库（数据库入库）为非默认、本期未做**，全部产物保持 JSON/CSV/Markdown 文件形态。

## 1. 全流程时间线（9 个阶段）

### 阶段 0：底座（39 卷拆分 + 1197 条指纹库）
输入无句读原文；按"卷首=钦定四库全书行 + 卷尾落款"切分 38 卷正文 + 卷 00 四库提要，共 39 卷；每行 = 一条候选条目，切出 `_extract/items/NN_卷名.txt`（条N|正文），产出 `_item_registry.json` **1197 条**指纹（key=NN-NNN，value 含 original/norm）——后续所有层 original 注入源。装饰行（书签行、撰者题名行、钦定行）剔除。

### 阶段 1：实体主键表（ent_keys）
先查后建：执行每卷前查 `alias_index`（按归一化词形），已存在直接复用 ENT ID，新建才分配；随卷累积、幂等合并。最终 2291 个归一实体（ENT-001..ENT-2291，其中名录人物补建 391 个 ENT-1901..ENT-2291）、alias_index 2291 条、surfaces 词形表 2185 条；高频实体（六科 45 次、叶盛 42 次、京师 41 次等）零重复建号。

### 阶段 2–8：8 层逐卷判定与打包
- **ent**：全卷逐条标注（text 须可在 original 定位、type 8 类枚举、normalized 归一、confidence、source 片段），共 2253 条标注。
- **appt**：只抽文本有明确任职句者（person/office/institution/when/status/evidence），237 条；when 未明显式"未明"；status 9 枚举（现任/致仕/升迁/贬谪/罢黜/兼领/暂代/追赠/未明）。
- **event**：五元组 who/action/what/when/where，234 条，15 类事件枚举。
- **reg**：一条目多项制度拆多条共享 item_id，72 条，11 类制度枚举。
- **lit**：title 无篇名取首句、author 佚名写"未明"，180 条，10 类文献枚举。
- **rel**：只建有直接证据的关系（person_a/person_b/relation_type/direction），126 条，12 类关系枚举、3 向性。
- **nam**：表格式名录整体一条、entries 四元组数组化（seq/person/courtesy_name/hometown/office，无则"未明"），54 条记录、567 行四元组。
- **trl**：全量逐条注释性翻译（余光中风格：译原意不译原字、长句拆并联、专名保留+括注、忌翻译体公式），1192 条 = 正文条目数，零缺口。

### 阶段 9：跨层索引 → 验证 → 交付聚合
`build_kg_join` 按 item_id 把 8 层命中并成一行（layer_count 贯通层数），输出 `_kg_join.json` 1197 行 + flat CSV；`validate.py` 输出七维度校验；最终按层聚合 JSON+CSV、全书记译合册、两份报告交付。

## 2. 底座与管线的两处关键工程决策

1. **build_base 增量合并修复**：早期 `--volumes` 单卷重跑会把共享指纹库/卷概要截断；修复为"只重算所请求卷并合并写回"，全量（不带参数）仍从空重建为权威口径。此修复并入打包器，重跑不丢。
2. **ID 段位防撞号**：各层 ID 跨卷全局唯一（validate 按层判重）。段位规则"卷 NN × 500 + 1 起编、段容量 500"（卷 02→1001、卷 29→14501…卷 38→19001）；试点例外卷 01 占 1–99、卷 17 占 301–425。层间独立命名空间，允许同段起始。

## 4. 各卷阅读模式落实

逐卷"主导类型/阅读模式"标注落地为层优先级：制度优先 **05/06/30**（reg 密集）、名录优先 **17/29**（nam 题名表）、谱牒优先 **15/16/18/20**（nam 谱牒四元组 + rel）、文献优先 **19/22/35/13/26**（lit 全抽）、长文卷 **14/21/23/24/28/30/37/38**（行=条长文、ent/event 为主）、均衡全层 **01**。层稀疏分布（如诗文卷 APPT/REG/REL 空层）是模式产物，均已在源数据注释登记；各卷层分布可查 `data/<layer>/<layer>_summary.json` 的 volumes_covered 与逐卷 JSON。

## 5. 质量与验证

- 每卷完成后 `python run_all.py --volumes NN` 验证本卷 ERR=0；分片并行期 ent_keys.json 为共享累积主键表（加载→合并→写回，幂等收敛）。
- 最终全量 `python run_all.py`：**结构性问题 ERR=0、执行缺口 GAP=0、通过项 OK=322**。
- 校验维度七项：A 底座完整性（1197 指纹）/ B 源数据覆盖（38 卷 × 8 层 = 304 项齐备）/ C 打包器产物完整性 / D 格式 / E 引用 / F TRL 覆盖（逐卷条目数=翻译数，38 卷零 mismatch）/ G 枚举口径快照（registerVersion=1，10 组枚举值核对）。
- TRL 全量硬校验：38 卷逐卷条目数 = 翻译数，合计 1192 = 1192；全书记译本合册 `### NN-NNN` 条目计数复核 = 1192。

## 6. 反思与方法论沉淀

1. **一次探查、先锁 schema 再写数据**：开工前读完全部输入与字段口径，连续两次读取不再改变计划即停止探查，避免反复 schema 重读。
2. **AI 判定与代码验证严格分工**：判定逐条由 AI 完成；代码只验缺漏（ERR/GAP 二分），不越权改判定。
3. **所有生成器正式化**：build_ 前缀 + 可重跑 + 幂等；修复（build_base 增量合并）并入生成器，重跑不丢。
4. **验证写文件输出**：`reports/验证缺漏清单.txt` 落盘，重跑前先确认不覆盖已修复字段。
5. **枚举单点治理**：`_kg_enums.py` + registerVersion，快照核对进维度 G。
6. **方向假设先确认**：条粒度、8 层不建 L2/L3、双库落库非默认等方向性口径开工前冻结。
7. **如实报告缺口**：哪里缺、缺什么、补什么方案，不静默降级（见 §7）。
