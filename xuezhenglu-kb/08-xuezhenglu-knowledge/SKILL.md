## 1. 执行流程总览

按**四段式**执行（`docs/新书开工流程.md` §8），每阶段收尾对照工厂 `../../Skills/00-book-knowledge-factory/references/checklists.md`：

```
① build_base.py（切卷切条 → _extract/ + _item_registry.json）
→ ② _src/ 装填（AI 逐条：只写条号 + 解读字段，绝不手抄原文）
→ ③ build_<layer>.py（打包：ID 分配 / 归一 / 枚举硬校验 / 从指纹库注入 original）
→ ④ build_kg_join.py + validate_layers.py（跨层索引 → 校验 → _deliver/）
```

## 2. 底座（C3，公共地基，先做）

1. 输入文件：`assets/sources/政学录_卷一~五.txt`（**唯一权威来源，随实例存放**；底本为清·郑端辑《政学录》畿辅丛书本，5 卷）。**卷拆分文件为切分主源**；`assets/sources/政学录_全文.txt`（合并版）作交叉校验（卷拆分与全文逐条对账）。外部资料只作内容性质/学术定位辅助，不作条目抽取依据。
2. 白话文对照引用源：`assets/sources/政学录_全文_白话.txt`。**不作抽取依据**，仅在需要译文时按条目对应引用。
3. 章节划分：**5 卷**，卷号按原书顺序直接映射（01 卷一=六部则例 / 02 卷二=直省事例 / 03 卷三=官箴+钱粮技术（上）/ 04 卷四=吕叔简救命会+十家牌法+钱粮技术（下）/ 05 卷五=状式+刑戒+狱政），卷号表见 `references/schemas.md` §1。
4. 条目切分（仅条目级）：
   - **标题条目**：正文 `○`/`△` 开头的标题行，每个标题与其后正文（至下一标题或卷尾）为一条；`○`/`△` 之后与正文之间空一格（`○吏部`、`△选法` 为标题本身，正文自标题行后）；
   - **卷级条目**：无 ○/△ 符号但有独立标题与正文的段（卷一"内阁/六部/科道"3 个）整段为一条；
   - 纯总目行（卷一"吏部/户部/礼部/兵部/刑部/工部"6 行，无正文、后随 ○吏部）**不计数**、不进入条目正文，仅作切分参考；
   - 产出 `_extract\NN_卷名.txt`（格式 `条N|○标题|正文`），预计 **183 条**（卷1=23/卷2=15/卷3=111/卷4=2/卷5=32）。
5. 指纹库 `_item_registry.json`：`{item_id: {original, norm}}`；**norm 归一规则**：繁体/异体字归一为规范简体（厯→历、廵→巡、覈→核、曡→叠、賸→剩、■〈…〉 缺字保留原形），标点按现代句读归一。
6. 全部条目建 task 清单（阶段可见、完成可核）。
7. **业务 ID 由打包器自动分配**：AI 源数据只写卷内顺序槽位，不手写业务 ID；打包器按「卷号 × 段容量 +1」段位分配，段容量默认 500（C2）。
8. **写盘与并行纪律**：写文件一律「临时文件 + rename 落盘」；共享汇总文件统一增量合并语义（`--volumes` 只重算请求卷、合并写回）；验证脚本写文件输出，不依赖 stdout。

## 3. 实体层方案（ent，启用）

- layer_key=`ent`，前缀 `ENT-`，目录 `_layers/ent/`；schema_fields = `ent_id, item_id, text, type, start, end, normalized, confidence, source`；enum_fields = `type`。
- 实体类型枚举（**继承基准库快照 → 落 `_kg_enums.py`**，封闭 + 兜底"unknown"）：本书实际启用子集 = `person / official / institution / place / era / work / doc / system / behavior / punishment / time / quantity / unknown`（object/animal/plant/food/star/event/posthumous 无成体系证据，不启用，保留在单点文件中作封闭全集）。
- 种子词典规则：全文本内生（词条必须出现在原文，否则自动剔除）；种子来源：衙门官职（内阁/六部/科道/部院/督抚/藩臬/州县/府厅/佐贰/首领官/司狱官/刑房吏/禁子/牢头/仵作/书吏）、制度（选法/考课/钱粮/漕运/盐课/关税/钱法/祀典/士额/秋审/军政）、文书（状式 28/刻册/底簿/廒经流水/批回/由票/柜式）、人名（吕坤（吕叔简）/王守仁/邹南皋/卢兴祖/田六善/李天裕/姚文然/于可托/张松龄 等疏臣）、地名（直隶/江南/河南/山东/山西/陕西/浙江/福建/广西/广东/江西/湖广/四川/贵州/云南 15 省+府州）、纪年（顺治/康熙/万历/洪武/永乐 年号）。
- 归一规则：异体/繁体→简体（同底座 norm）；同义复合词形用 alias_index 手工映射，不动标注。
- **跨书对齐（重要）**：本书卷三~五大量条目辑录自吕坤《实政录》（吕坤 39 处/状式 28/刑戒/狱政/钱粮技术），与《吕公实政录》（lgs，07 实例）实体高度重叠——归一与主键表尽量对齐 lgs 词形（状式名/狱政术语/钱粮条目），联邦库并入时跨书查重价值高。
- 主键表：ENT-001..N + alias_index（词形 → ent_id）。

## 4. 规则层方案（rule，启用）

- layer_key=`rule`，前缀 `RULE-`，目录 `_layers/rule/`；schema_fields = `rule_id, item_id, type, modals, condition, subject, subject_ent_ids, action, object, purpose, punishment, original, confidence`；enum_fields = `type`。
- 触发词表（候选引擎，AI 逐条复核）：`不许 / 不得 / 务要 / 须 / 止许 / 只许 / 许 / 毋 / 勿 / 禁 / 严禁 / 责罚 / 重责 / 枷号 / 挐问 / 访察 / 参降 / 革职 / 处分 / 限 N 日 / 不过 N 日 / 违者 / 犯者 / 依律 / 定行 / 例 / 著 / 照例`。
- 规则类型枚举（**继承基准库快照 → `_kg_enums.py` RULE_TYPES 7 值**）：禁止型 / 义务型 / 允许型 / 程序型 / 时限型 / 处罚型 / 优先级型。
- **组合规则口径（定死）**：一条规范句 = 一个规则单元，type 取行为规范的主模态；"违者/犯者……"处罚并入同条 punishment 槽位，不单拆处罚型；一句话并列多个独立行为规范拆多条共享 item_id；一句多模态 type 取约束更强的一方。
- 则例体（卷一~二）处理：部覆/奉旨引出的"已定见行事例"以程序/时限/禁止型抽规则；制度沿革叙事句（"旧例……后改……"）抽规则时取**现行有效**规范；历史演变说明不抽（归 L1 制度实体 + L4 记录）。
- 官箴体（卷三~五）处理：戒条（"不可/勿/不许"引出的禁令）逐条抽规则；劝诫说理句（"嗟乎/呜呼"引出的议论）不抽。

## 5.5 制度层方案（reg，启用，2026-10-12 增量）

- layer_key=`reg`，目录 `_layers/reg/`；ID 前缀 `REG-`（全局唯一）；schema_fields = `reg_id, item_id, name, type, content, evolution, target, original, confidence`；enum_fields = `type`。
- **定位**：制度本体静态描述登记（制度名 + 内容要点 + 沿革 + 出处）。与 L1 system 实体分工：L1 标制度**词**为实体；REG 记制度**条目级描述**。与 L4 分工：L4 从维度切片对象（角色/防弊/文簿/时限），REG 收制度本身。
- 制度类型枚举（**本书归纳，封闭+兜底** → `_kg_enums.py` REG_TYPES）：官制 / 铨选考课 / 钱粮赋役 / 刑名狱政 / 保甲乡约 / 文教祀典 / 军政边防 / 驿递河工 / 吏治政术 / 其他。
- 执行口径：一条目含多个制度可拆多条共享 item_id；沿革要点（"旧例…后改…"）记 evolution 不另拆事件；content 写要点不抄原文（C3）。

## 5.6 事件层方案（evt，启用，2026-10-12 增量）

- layer_key=`evt`，目录 `_layers/evt/`；ID 前缀 `EVT-`（全局唯一）；schema_fields = `event_id, item_id, type, who, who_ent_ids, action, what, when, where, original, confidence`；enum_fields = `type`。
- **定位**：沿革/建言事件五元组登记（who/action/what/when/where）。**集中在卷一~二**（则例体条陈→部覆→奉旨沿革叙事），卷三~五以规范句为主，未建模条目如实记缺口（不强行造事件）。
- 事件类型：**继承基准库 `enum-library.md` §1.3 顶层 27 值**（朝政/建言/制度/人事任免/经济…，封闭+兜底"其他"）→ `_kg_enums.py` EVENT_TYPES；本书不新增顶层，未匹配值走 V3 收集-决议。
- 执行口径：一条 MEM 式"臣疏→部覆→奉旨"全链记一个 EVT（type 取主导：建言/制度/朝政），不拆成多次往来；沿革叙事（"某年某人条陈某事，遂改为…"）记 EVT + REG（REG 收制度结果、EVT 收事件过程）。

## 6. 跨层整合（kg_join，必建）

- ID 对齐审计点：实体主键唯一 / 引用槽位合法 / item_id 全回填（183 条全覆盖）/ target 用 ID / 枚举口径一致。
- 跨层索引：`_kg_join.json` + `_kg_join_flat.csv`（每行 = 一条目）：`item_id / volume / source / rules / regs / events / structs / ents / layer_count`（槽位按启用层裁剪）。
- 枚举治理（C5）：单点 `_kg_enums.py` + registerVersion（新增值 version+1 回溯存量）；校验用**「收集-报告-暂存」**模式，未匹配值入 pending 表不中断，收尾统一决议；改值须双写 `enum-changelog.md`。

## 6.5 治理组件（默认启用）

- **V2 人工校验闭环**（layer_key=`review`）：同名异人/存疑判定（如官职异名、复合词形）自动收集入"待核清单"CSV（含 provenance），人工核前不强行合并（宁建勿并），核后回写。
- **V3 枚举校准**（layer_key=`enum_calib`）：执行期未匹配枚举值 → 收集-报告-暂存 → 收尾决议（新增/归并/改名）→ registerVersion+1 → 回溯存量；新增值必须有实例证据。

## 7. 管线与验证（四段式）

- 工程根：`xuezhenglu-kb/`（与实例同目录，内含式）。
- 命令序列（从工程根执行）：
  - `python build_base.py` —— ① 底座：切卷切条 → `_extract/` + `_item_registry.json`
  - `python build_ent_keys.py --volumes NN` —— 实体层（含主键表）
  - `python build_rules.py --volumes NN` —— 规则层
  - `python build_struct.py --volumes NN` —— 结构化层
  - `python build_reg.py --volumes NN` —— 制度层
  - `python build_events.py --volumes NN` —— 事件层
  - `python build_kg_join.py --volumes NN` —— 跨层整合
  - `python validate_layers.py` —— 校验（`_validate/` 缺漏清单 ERR=0/GAP=0 才算过）
  - `python run_all.py [--volumes NN]` —— 全量 / 单卷幂等重跑
- **键名约定**：各层产物顶层键统一 `records`；打包器内建源数据键名映射表（SRC_KEY），源数据键名与打包容器键分处声明；`_src/` 只写条号 + 解读字段（C3）。
- 验证：每层"验证缺漏清单.txt"问题数 = 0（实体未归一 / 规则缺 item_id / struct target 悬空 / item_id 未全回填等）；区分结构性错误 ERR 与执行缺口 GAP；验证脚本写文件输出，不依赖 stdout；未注册枚举值记 ERR 不静默放行（C5）。
