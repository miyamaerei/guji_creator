# 译注古籍结构化方法论
### —— 以《焚书》（李贽·张建业译注，中华书局）EPUB 项目为完整实例

> 本文档是「译注古籍结构化工厂」（annotated-classics-factory）的方法论核心。
> 它回答三个问题：JSON 怎么设计、EPUB 怎么解析、8 类产物怎么拆分导出；并沉淀本项目踩过的坑。
> 新书实例化时：先读本文档 → 按“新书适配清单”探查新书 → 确认 JSON 设计 → 生成书实例 skill。

---

## 一、适用范围与核心模型

**适用对象**：采用「译注体例」的古籍数字书——即正文按 **标题（篇目）→ 写作背景（题解）→ 原文 → 注释 → 译文** 的循环组织。典型如中华书局《中华经典名著全本全注全译》丛书。载体以 EPUB 为主（本质是 zip 包内 HTML），PDF/其他格式先转文本后同样适用。

**核心数据模型**（贯穿 JSON 设计与全部导出产物）：

```
卷(volume)
 └─ 篇(article)          —— 书内 h2 级标题，如“答周西岩”
     ├─ 题解(ti_jie)     —— 该篇写作背景（可有可无）
     ├─ 单元(units)[]    —— 原文/注释/译文 的最小组合循环
     └─ 子篇(sub_articles)[] —— h3 级标题（“附××”“又”“第×段”、卷六各诗）
```

**单元（unit）** 是全书的锚点：一个单元 = 若干原文段 + 注释 + 译文，对应书上 `【原文】→【注释】→【译文】` 的一个循环。散文卷通常 1 原文段 ↔ 1 译文段；诗歌卷（如卷六）常为多原文段（按联）对一段/多段译文（按首）——**对齐粒度允许“1:1”与“整体”两种，差异是内容属性而非缺陷**。

## 二、JSON 格式设计（规范）

### 2.1 顶层结构

```json
{
  "meta": {
    "书名": "焚书", "作者": "李贽", "译注者": "张建业",
    "丛书": "中华经典名著全本全注全译", "出版社": "中华书局",
    "版本": "2018年7月", "格式": "epub"
  },
  "front_matter": [ { "title": "自序", "type": "annotated", "article": {…篇结构…} } ],
  "volumes": [ { "no": "卷一", "name": "书答", "full": "卷一 书答", "articles": [ … ] } ],
  "appendices": [ { "title": "附录一 序跋", "articles": [ { "title": "李氏焚书跋", "author": "黄节", "paragraphs": [ … ] } ] } ],
  "warnings": [ "……解析告警，供人工复核……" ]
}
```

字段说明：
- `front_matter`：卷首各条目。`type` 区分 `annotated`（有完整原文/注释/译文结构，如《自序》，按篇处理）与 `plain`（纯文本，如版权页/目录/凡例，按段落保留）。
- `volumes[].articles[]`：正文篇目，见 2.2。
- `appendices`：附录。目录性附录（如“征引书录”）用 `paragraphs` 一行一条；有序跋等结构化内容的用 `articles[{title, author, paragraphs}]`。
- `warnings`：解析过程中的规则性告警（如“某篇诗序丢失【原文】标记，已自动归位”），**必须保留，供人工校验闭环**。

### 2.2 篇（article）结构

```json
{
  "id": "j1-001",                  // 稳定标识：卷号缩写+卷内序号
  "title": "答周西岩",             // 篇目标题（书内 h2）
  "anchor": "b001",                // 源 HTML 锚点 id（可回溯原文）
  "source": "text/part0006.html",  // 源 EPUB 内部文件（重跑解析用）
  "title_anchors": [],             // 标题上的 sup 标注（如“答澹然师①”的 ①）
  "ti_jie": [ "……题解段落……" ],   // 写作背景，数组=多段
  "units": [
    {
      "seq": 1,                    // 单元序号（篇内，从 1 起）
      "对齐": "1:1",               // "1:1" = 原文/译文逐段对应；"整体" = 整组对应
      "原文": [ "天下无一人不生知①，……" ],   // 原文段，sup 标注内联保留（与印本一致）
      "标注": [ ["①","②","③","④"] ],       // 每原文段的 sup 标注列表（与 原文 段一一对应）
      "注释": [ { "key": "①", "term": "生知", "text": "语出《论语》……" } ],
      "译文": [ "天下所有的人没有一个不是……" ]
    }
  ],
  "sub_articles": [
    { "title": "附 衡湘答书", "units": [ …同 unit 结构… ] }
  ]
}
```

### 2.3 关键设计决策（为什么这么设计）

| 决策 | 理由 |
|---|---|
| 中文键 + 少量英文键（id/title/seq）混用 | 古籍内容键（原文/译文/注释/标注/题解）中文自明；程序键（id/title/source/anchor）英文稳定。如需接入 kgWorkflow 可整体映射为英文键（见 2.4） |
| 标注内联保留 + 单独 `标注` 字段 | 内联保留保证“原文与印本逐字一致”；单独字段保证“段落→词解释”可程序化（标注列表与注释 key 一一对应） |
| `对齐` 字段显式记录 1:1/整体 | 诗歌卷“原文段数≠译文段数”是常态；显式标记避免下游误判为数据缺失 |
| 每个 article 带 `source` | 回源纠错（重新解包 EPUB 改 HTML）不靠猜 |
| `warnings` 与“校对报告”分离 | JSON 保证结构化完整性，报告保证人工可复核（符合“词典+规则先行、人工校验闭环”偏好） |

### 2.4 英文键映射（接知识图谱流水线时用）

```
volume:  {no, name, full, articles}
article: {id, title, anchor, source, title_anchors, background(题解), units, sub_articles}
unit:    {seq, alignment(对齐), original(原文), anchors(标注), notes[{key,term,text}], translation(译文)}
```

## 三、EPUB 解析逻辑（可迁移方法）

### 3.1 解剖 EPUB

1. EPUB 是 zip：`zipfile` 解包（无需第三方库）。正文通常在 `text/part*.html`（或 `OEBPS/text/*.html`），目录在 `toc.ncx`（navMap 层级）或 `nav.xhtml`。
2. **先读 toc.ncx 建立“目录树”**：卷（h1）→ 篇（h2）→ 子篇（h3）的完整层级，识别同卷内并列的篇、跨 part 文件的篇。
3. 抽查 3~5 个 part 文件，**锁定标记规律**（这是解析成败的第一关键步）：
   - 标题标签：`h1`=卷？`h2`=篇？`h3`=子篇？（带 id 锚点，如 `id="b001"`）
   - 正文段：`p class="xxx"`？哪些是原文段、哪些是各小节内容段？
   - 小节标记：`【题解】【注释】【译文】` 出现在什么标签内（如 `<b>`）？
   - 标注字符：原文段的 ①②⑪(21) 是 `sup` 标签吗？注释条目是否以 `①…` 序号开头？

《焚书》实测规律（作为“标准样板”）：
- `h1`=卷标题（“卷一 书答”）；`h2`=篇目（id 形如 `b001`）；`h3`=子篇目（id 形如 `c001`）
- `p.calibre1`（非【】标记）= 原文段；`p.calibre1` 内 `<b>【题解】/【注释】/【译文】</b>` = 小节标记；`p.block1` = 各小节内容段
- 原文段 `sup` 标注内联保留；注释条目以 ①②③ 序号开头解析 key/term/text

### 3.2 状态机（核心算法）

```
状态：当前篇 / 当前小节(题解|原文|注释|译文) / 当前单元
规则：
  新篇(h2/h3)  → 新建 article；闭合当前单元
  题解标记     → 进入题解区；后续 block1 归 ti_jie
  原文段       → 若已有单元且当前小节在注释/译文之后 → 新建单元；
               否则追加进当前单元原文
  注释标记     → 当前单元的注释区；【注释】/【译文】都归属当前单元，
               由“新篇/题解/新原文段”闭合，绝不因小节切换而误生成新单元
  译文标记     → 当前单元的译文区
  单元闭合时机：新篇、新题解、新原文段
```

**本项目踩过并已修复的坑（务必内化为规则）**：
- 把【注释】【译文】误 flush 成新单元 → 全书泛滥“有原文无译文”孤儿；修正为注释/译文归属当前单元。
- `volumes` 漏接（`doc["volumes"]=sb.volumes` 忘写）→ 卷数恒为 0，**每次跑完必须核对顶层计数**。
- 卷号解析把“卷一 书答”整串当卷号 → `--卷 卷一` 过滤失效；修正为只取“卷X”。

### 3.3 标注与注释的对应

- 原文段 `sup` 标注 → 内联保留 + 追加进该段 `标注` 列表；
- 注释条目序号（`①…`）→ 解析为该条注释的 `key`；
- “段落 → 词解释”查询 = 原文段 → 该段标注列表 → 同 key 的注释条目。
- 注释条目的 `term`（词头）解析：取 key 之后到首个标点（：/。）之间的词；解析不稳时留空，靠文本检索兜底。

### 3.4 源书特例策略（非标准排版）

以下特例**不能猜，要按规则处理并写进报告留痕**：
1. 题解区紧跟带 sup 标注的段落 → 极可能是丢失【原文】标记的诗序/诗句（《焚书》中《夜半闻雁 四首》《慰郑子玄 三首》如此）：规则“题解区带标注段 → 按原文段归位”。
2. 紧跟原文段的“无标记长行” → 原文续段归并（《李涉赠盗》引诗长行如此）。
3. 封底/空页 → 空 part 文件特判跳过。
4. 卷六（诗）h2 是诗体类别而非篇目 → 标记 `type=category`，真正篇目在 h3。

### 3.5 校验（人工校验闭环的自动化部分）

`校对报告` 必须自动产出并随产物交付：
- 统计：卷数 / 篇数 / 子篇数 / 单元数 / 注释条数
- **孤儿单元检查**：有原文无译文、有译文无原文 → 必须为 0（非 0 即解析 bug）
- 注释序号缺失检查（有原文标注但无对应注释 key）
- **段数不对齐清单**：1:1 与整体分类列出；散文卷不对齐必须人工回源裁定，诗歌卷不对齐属正常
- 规则告警：自动归位/归并等特例处理，逐条留痕

抽查法：取 3 篇（首卷/中卷/尾卷各一），JSON 原文与源 HTML **逐段**比对，必须完全一致。

## 四、拆分导出逻辑（8 类产物）

### 4.1 产物总表（《焚书》实测规模：6 卷 / 210 篇 / 118 子篇 / 773 单元 / 6979 注释）

| # | 目录 | 内容 | 粒度 | 说明 |
|---|---|---|---|---|
| 00 | `00_命名说明.txt` | 重名/特殊字符消歧清单 | — | 供人工核对 |
| 01 | `01_目录结构.txt` | 全书目录树（卷→篇→子篇） | 1 文件 | 被改名篇标注 `→ 实际文件名` |
| 02 | `02_原文txt\` | 纯原文（已去标注序号） | 按卷 | 【篇】分节 |
| 03 | `03_篇txt\卷X\` | 整篇：题解+原文+注释+译文 | **按篇** | 文件名=标题 |
| 04 | `04_译文txt\` | 译文全文（无注释） | 按卷 | 【篇】分节 |
| 05 | `05_背景txt\` | 全书题解汇总 + 每卷文件夹每篇背景 | 汇总+按篇 | 每章一个文件夹 |
| 06 | `06_原文注释md\卷X\` | 原文+注释 Markdown | **按篇** | 逐单元「原文/注释」相邻 |
| 07 | `07_原文拆分txt\卷X\` | 纯原文（无标注序号） | **按篇** | 与 03 同名对应 |
| 08 | `08_译文拆分txt\卷X\` | 纯译文 | **按篇** | 与 03 同名对应 |

### 4.2 拆分粒度决策

- **散文卷**：按 h2 篇目为一个文件；篇下子篇（附××/又/第×段）**独立成文件**（便于逐条引用）。
- **诗歌卷（卷六型）**：h2 是诗体类别（无正文）→ 不生成文件，仅作目录类目行；**每首诗（h3）独立成文件**。
- **仅题解无正文的篇**（总题解，如《观音问》《豫约》《寒灯小话》）：不生成 02/07/08 拆分文件（无原文/译文），其正文在子篇中；03/06 仍生成（含题解）。

### 4.3 命名规则（重名消歧，全部记入 00_命名说明.txt）

1. 文件名 = 标题（sanitize 后）。
2. 标题重复 → 散文篇加卷前缀：`卷一_答邓明府.txt`、`卷二_答邓明府.txt`。
3. 子篇标题无区分度（`又`、`第×段`、`小引`）→ 一律 `父篇_子篇`：`观音问_又_3.txt`、`寒灯小话_第一段.txt`；后续重复加序号。
4. Windows 非法字符（`\ / : * ? " < > |` 与换行）→ 替换为 `_`；文件名结尾的 `.`/空格去除。
5. **导出前清空输出根目录**（避免旧命名残留），导出后**目录树与实际文件逐行核对**（TOC 中每个改名条目与文件系统一一对应）。

### 4.4 标注序号取舍（重要产品决策）

- **去序号**：纯原文产物（02 按卷、07 按篇）——无注释对应，①(21) 无意义。用“标注”字段精确移除（按段一一对应，不误删正文）。
- **保留序号**：03 整篇、06 md——原文与注释相邻，序号支撑段落↔注释对应。

### 4.5 编码与兼容

- 所有 txt/md 用 `utf-8-sig`（带 BOM，Windows 记事本/Excel 直接打开不乱码）；JSON 用 `utf-8`。
- 纯 Python 标准库（zipfile + html.parser + json + re + shutil），无第三方依赖，Windows 可直跑。

## 五、经验与坑（新书复用清单）

### 5.1 通用经验
1. **探查先行**：toc.ncx 目录树 + 3~5 个 part 文件抽查 + 标记规律锁定，一次做透，胜过反复试错。
2. **状态机闭合**：小节的归属（注释/译文属于哪个单元）是最大错误源；用“闭合时机”显式定义。
3. **校验即交付**：孤儿单元、注释缺失、段数不对齐、告警留痕——这些是“人工校验闭环”的自动一半，必须随产物交付。
4. **可重入**：解析与导出都要能重跑（parse 覆盖 JSON+txt+报告；导出清空目录后全量重写），重跑不产生脏数据。
5. **查询与数据分离**：查询命令读 JSON，不依赖解析时的内存态；改解析逻辑后重跑 parse，查询自动生效。

### 5.2 环境坑（Windows）
- PowerShell 下内联 `python -c` 传多行中文脚本会被引号解析破坏 → **写脚本文件再执行**。
- 中文文件名/路径在 PowerShell 传参注意编码；文件读写统一显式 `encoding="utf-8"`。
- `html.parser` 是默认标准库（无 lxml 时用它）；标题/段落的 class 判定用 `attrs.get('class')` 列表成员判断。

### 5.3 命名坑
- 古籍书名号 `《》`、缺字 `□`、顿号均合法（Windows）；但 `\ / : * ? " < > |` 必须净化。
- “又”“第×段”“小引”这类标题**单独出现必重名**，父篇前缀是唯一解。
- 同卷内同名篇（《焚书》卷一有两个《答邓明府》）也要处理，不只在跨卷层面。

### 5.4 数据正确性坑
- 卷号只取“卷X”，不要带“卷一 书答”整串（影响按卷过滤）。
- `doc["volumes"]=sb.volumes` 这类“忘接主数据”的 bug 要用顶层计数校验兜住。
- 注释 key 用 ① 等（与原文标注一致）；`(21)` 等两位序号也要能解析（原书 20 之后用半角括号）。

## 六、新书适配清单（工厂实例化时按此探查/确认）

新书（EPUB 译注体例）进工厂时，按以下清单逐项探查并确认，确认后生成书实例 skill：

- [ ] **体裁确认**：是否译注体例（题解/原文/注释/译文循环）？非译注（如白话全译本）→ 调整 JSON 模型（可能无题解/无注释/无标注）。
- [ ] **目录树**：toc.ncx（或 nav）→ 卷/篇/子篇层级；跨 part 文件归属。
- [ ] **标记规律**：h1/h2/h3 与 class 映射；【题解】【注释】【译文】标记所在标签；sup 标注形式（①②…(21)）。
- [ ] **单元对齐粒度**：散文 1:1？诗歌整体？还是新形态（如偈颂、语录）？
- [ ] **命名冲突面**：预扫标题重复清单（跨卷/同卷/子篇），确定消歧规则参数。
- [ ] **特例扫描**：题解区带标注段（丢失【原文】标记）、长行归并、空页、非标准卷（如卷六型“类目下藏篇”）。
- [ ] **交付物确认**：8 类产物是否需要调整（增删目录/粒度）？json 键中英？接不接 kgWorkflow？
- [ ] **实例化产物**：`<book-slug>-structure` 书实例 skill（含 SKILL.md + 适配后的 fen_shu.py/export_fenshu.py + 校对报告模板）。
