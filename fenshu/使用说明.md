# 《焚书》EPUB 结构化工具 · 使用说明

数据源：`焚书 ([明] 李贽 著  张建业 译注) (z-library.sk, 1lib.sk, z-lib.sk).epub`
版本：中华书局《中华经典名著全本全注全译》丛书（全二册），2018年7月。

---

## 一、产物清单

| 产物 | 说明 |
|---|---|
| `fen_shu.py` | 主工具：解析 + 查询一体（Python 3，仅标准库） |
| `export_fenshu.py` | 导出工具：JSON → 6 类成品（目录/原文/篇/译文/背景/md） |
| `焚书_结构化.json` | 全书结构化数据（卷 → 篇 → 子篇 → 单元{原文/注释/译文}） |
| `分卷txt\` | 带标记的分卷 TXT：卷首、卷一~卷六、附录一、附录二、封底 |
| `原文txt\` | 每卷**仅原文**的 TXT（保留原文中的①等标注字符） |
| `导出\` | 6 类成品（见下节“五、导出产物”） |
| `校对报告.txt` | 解析统计 + 段数不对齐清单 + 规则告警（供人工复核） |

## 二、JSON 结构

```json
{
  "meta": { "书名": "焚书", "作者": "李贽", "译注者": "张建业", ... },
  "front_matter": [ { "title": "自序", "type": "annotated", "article": {...} }, ... ],
  "volumes": [
    {
      "no": "卷一", "name": "书答", "full": "卷一 书答",
      "articles": [
        {
          "id": "j1-001", "title": "答周西岩", "anchor": "b001", "source": "text/part0006.html",
          "title_anchors": [],              // 标题上的 sup 标注（如“答澹然师①”）
          "ti_jie": [ "……写作背景/题解段落……" ],
          "units": [
            {
              "seq": 1, "对齐": "1:1",
              "原文": [ "天下无一人不生知①，……" ],     // 原文段（保留①②等标注内联）
              "标注": [ ["①","②","③","④"] ],            // 每原文段的 sup 标注列表
              "注释": [ { "key": "①", "term": "生知", "text": "语出《论语》……" } ],
              "译文": [ "天下所有的人没有一个不是……" ]
            }
          ],
          "sub_articles": [ { "title": "附 衡湘答书", "units": [...], ... } ]
        }
      ]
    }
  ],
  "appendices": [ { "title": "附录一 序跋", "articles": [ { "title": "李氏焚书跋", "author": "黄节", "paragraphs": [...] } ] } ]
}
```

**结构模型**：正文每篇（h2）下可有子篇（h3，如“附××”“第×段”、卷六各诗）。
每篇由若干**单元**组成，一个单元 = 若干原文段 + 注释 + 译文，对应书上
`原文 → 【注释】 → 【译文】` 的一个循环。散文卷多为 1 原文段 ↔ 1 译文段（`对齐: "1:1"`），
诗歌卷（卷六）一首诗常为多原文段对一段/多段译文（`对齐: "整体"`，属正常粒度差异）。

**“标注 ↔ 注释”对应**：原文段里的 `①`（sup 标注）与 `注释[].key` 一一对应；
段落级查词解释即：原文段 → 标注列表 → 同 key 的注释条目。

## 三、命令用法

```bat
:: 0. 从 JSON 导出 6 类成品（目录/原文/篇/译文/背景/md，见第五节）
python export_fenshu.py

:: 1. 重新解析 EPUB（生成 JSON / 分卷TXT / 原文TXT / 校对报告）
python fen_shu.py parse

:: 2. 按卷/篇只拿原文（不加 --篇 则整卷；--输出 可写文件）
python fen_shu.py 原文 --篇 童心说
python fen_shu.py 原文 --卷 卷一 --输出 卷一_原文.txt

:: 3. 某篇的写作背景（题解）
python fen_shu.py 题解 --篇 童心说

:: 4a. 段落对应词的解释：按标注取（① 为该篇内每条注释的序号）
python fen_shu.py 注释 --篇 答周西岩 --锚 ①
:: 4b. 全书按词检索解释
python fen_shu.py 注释 --词 生知

:: 5. 对应译文（--段 为篇内段落序号，1 起）
python fen_shu.py 译文 --篇 童心说 --段 1
python fen_shu.py 译文 --篇 童心说

:: 6. 全文检索（原文/题解/注释/译文）
python fen_shu.py 检索 --词 童心

:: 7. 按卷列篇目
python fen_shu.py 篇目 --卷 卷六
```

篇目支持模糊匹配；同名篇目（如卷一、卷二都有《答邓明府》）用 `--卷` 限定或给出更精确的 `--篇`。

## 四、解析规则与已知特例

1. 正文识别：`p.calibre1`（非【】标记）= 原文段；`【题解】【注释】【译文】` = 小节标记；
   `p.block1` = 各小节内容。无标准结构的卷首（版权页/目录/李贽论/凡例）按纯文本保留；
   《自序》有完整“原文+注释+译文”结构，按篇处理；附录一按 篇题/作者/正文 处理。
2. 标注字符：原文段的 `①⑪(21)` 等 sup 标注**内联保留**（与印本一致），并单独记录于 `标注` 字段；
   注释条目的序号由每条注释文本开头解析。
3. 源书特例（已在`校对报告.txt`“解析告警”中列出，可人工复核）：
   - 《夜半闻雁 四首》《慰郑子玄 三首》的“诗序”原文丢失了【原文】标记，直接跟在题解后，
     工具按“题解区带标注段 → 原文段”自动归位；
   - 《李涉赠盗》引录刘伯温诗的长行以无标记段落排版，按“紧跟原文段的段 → 原文续段”归并。
4. 校验：抽查 卷一《答周西岩》、卷三《童心说》、卷四《寒灯小话》等篇，JSON 原文与源 HTML
   逐段完全一致；卷六诗歌段数不对齐属正常（原文按联、译文按首）。

## 五、导出产物（JSON → 6 类成品）

运行 `python export_fenshu.py [输出目录]`（默认 `导出\`），从 `焚书_结构化.json` 一次性生成：

| 目录 | 内容 |
|---|---|
| `01_目录结构.txt` | 全书目录树：卷 → 篇（序号）→ 子篇；被改名的文件标注 `→ 实际文件名` |
| `02_原文txt\` | 每卷一份纯原文（按【篇】分节，已去除①②等标注序号） |
| `03_篇txt\卷X\` | **每篇一个 txt**，文件名=标题，含该篇【题解】【原文】【注释】【译文】全文 |
| `04_译文txt\` | 每卷一份译文全文（不带注释，按【篇】分节） |
| `05_背景txt\` | `全书题解汇总.txt` + 每卷一个文件夹，内为每篇的写作背景（题解） |
| `06_原文注释md\卷X\` | 每篇一个 Markdown：标题 + 题解 + 逐单元「原文/注释」 |
| `07_原文拆分txt\卷X\` | **每篇一个纯原文 txt**（文件名=标题，已去除标注序号，与 03 同名一一对应） |
| `08_译文拆分txt\卷X\` | **每篇一个纯译文 txt**（不带注释，文件名=标题） |

**拆分粒度**：散文卷按 h2 篇目；卷六诗歌按“每首诗”拆（诗体类别不单独成文件，仅作类目列于目录 txt）；篇下的子篇（附××、又、第×段、卷六各诗）独立成文件，方便逐条引用。仅题解而无正文的篇（如《观音问》《豫约》《寒灯小话》的总题解）不生成 07/08 拆分文件，其正文在各子篇文件中。

**标注序号取舍**：`02`、`07` 是纯原文产物，无注释对应，已去除原文段中的 ①②(21) 等标注序号；`03` 整篇与 `06` md 中原文与注释相邻，序号保留，用于段落↔注释对应。

**命名规则**（重名消歧，全部记录在 `00_命名说明.txt` 供人工核对）：
1. 文件名=标题；同一标题重复出现时，散文篇加卷前缀（如 `卷一_答邓明府.txt`、`卷二_答邓明府.txt`）；
2. 子篇标题无区分度（`又`、`第×段`、`小引`）时，一律用 `父篇_子篇`（如 `观音问_又_3.txt`、`寒灯小话_第一段.txt`）；
3. Windows 非法字符（`\ / : * ? " < > |`）自动替换为 `_`，文件名结尾的 `.`/空格去除。

## 六、与知识图谱流水线的衔接建议

- 实体/词条抽取可直接遍历 `volumes[].articles[].units[].注释`（6979 条，含 `term` 词头字段）；
- 篇章背景即 `ti_jie`（题解）字段，可按篇 id（如 `j1-001`）关联；
- 原文↔译文已在单元内对齐，诗歌卷整组对应，可自行决定拆句粒度后再入库。

## 七、方法论文档与工厂 skill

- `结构化方法论.md`：本项目沉淀的完整方法论——JSON 格式规范（含英文键映射）、EPUB 解析逻辑（状态机/标注对应/特例策略/校验）、8 类导出逻辑（粒度/命名/序号取舍/编码）、经验坑库、新书适配清单。
- 已安装工厂 skill：**`annotated-classics-factory`**（译注古籍结构化工厂，meta-skill，位于 `workspace/.user_skills/`）。
  以后传入新译注古籍（如《续焚书》），对它说“传这本书做成技能/按流程处理”，工厂会：结构性探查 → JSON 设计确认 → 生成该书实例 skill（`{书名slug}-structure`，含适配后的 fen_shu.py/export_fenshu.py）→ 试点校验 → 交付；之后直接调用实例 skill 完成解析→JSON→8 类导出。
