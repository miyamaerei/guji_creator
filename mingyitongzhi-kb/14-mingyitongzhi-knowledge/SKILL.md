## 1. 执行流程总览

```
底座（卷切分 + 府级条目指纹库）
  → L1 实体归一
  → GEO 地理实体树 + 属性
  → EVO 建置沿革链
  → MTN 山川
  → PER 人物
  → SITE 古迹建筑
  → PROD 物产（薄层）
  → CIT 引书
  → 跨层整合（_kg_join）
  → 交付
```

**禁止全文载入**：每次只载一个 region（≤10 卷），单府抽样 ≤30 行。

## 2. 底座（公共地基）

1. 输入文件：`E:\git	oolboxeijing	estaw	est.txt`（6.89MB / 6552 行 / UTF-8）。**唯一权威来源**。
2. **正文边界**：文件尾部混入《钦定大清一统志》卷首（约 29K 字符）。正文只取 "总志之属,大清一统志" 标签之前的部分（~2.27M 字符）。
3. 卷切分：按卷次标题切 90 卷（卷二十七 OCR 为 `綂`，正则接受 `统/綂`）。
   - 卷首 = 00（提要/序/进表/职名）
   - 卷 1–90 = 正文
   - 每卷标题通常出现两次（天头地脚），以首次出现为卷起点
4. 条目切分：
   - **府级条目** = 从 "XX府【" 或 "XX州【" 到下一个同型标题之间的完整块（含固定 20 门）。跨卷府（如顺天府卷1–6）按卷分段，GEO 树合并。
   - 卷首（00）= 单独条目（不拆）。
   - 外夷国（卷89–90）= 每个国名块为一个条目。
5. 指纹库 `_item_registry.json`：key=`NN-NNN`（NN=卷号，NNN=卷内条序），value=original/norm。
6. **ID 由打包器分配**：AI 源数据只写卷内槽位，不手写业务 ID。
7. OCR 归一规则：
   - `明一綂志` → `明一统志`
   - 私用区字形 `` → `隶`（直隶）
   - 其余错字不强行纠正，保留原文 + norm 字段标注

## 4. GEO 地理实体层（★本书骨架）

### 4.1 府/州/县树

- schema：`geo_id / item_id / name / type(prefecture/department/subprefecture/county/metro/post) / parent(geo_id) / children[] / region(京师/南京/山东/山西/…) / volume_range`
- 根节点：京师、南京、十三布政使司
- 府级条目跨卷时：`volume_range` 记 `"卷3–卷6"`

### 4.2 府级属性（与节点并存）

- `borders` 四至八到：数组 `{direction, to_place, distance_li}`
- `to_capital` 至京师/南京：`{capital, distance_li}`
- `households` 编户：`{count, unit="里"}`
- `grain_tax` 粮额：`{amount, unit="石"}`
- `jun_name` 郡名：`string`
- `topography` 形胜：`text + cit_ids[]`
- `customs` 风俗：`text + cit_ids[]`
- `garrisons` 公署/卫所：`[{name, type, location_text}]`
- `fiefs` 藩封：`[{name, type, note}]`

## 5. EVO 建置沿革层

- schema：`evo_id / item_id / geo_id / dynasty / era / institution_name / action(置/废/改/并/复/因之) / detail / original`
- 按府/州/县组织：一条目下可有多个 EVO 记录（沿革链）
- 朝代枚举：`秦/汉/三国/晋/南北朝/隋/唐/五代/宋/元/明/未明`（封闭+兜底）

## 6. MTN 山川层

- schema：`mtn_id / item_id / geo_id / name / type(山/岭/峰/冈/岩/洞/泉/溪/江/河/湖/潭/池/堰/关/桥/井/其他) / location_text / description / lore / original`
- type 枚举：从文本归纳，封闭+兜底"其他"
- `lore` = AI 解读典故（非原文）

## 7. PER 人物层

- schema：`per_id / item_id / geo_id / name / type(名宦/流寓/人物/列女/仙释) / dynasty / native_place / office / summary / original`
- `summary` = AI 要点概括（非原文）
- 同名异人：自动收集待核，人工核前不合并（V2）

## 8. SITE 古迹建筑层

- schema：`site_id / item_id / geo_id / name / type(寺观/祠庙/陵墓/古迹/宫室/学校/书院/坛庙/城池/苑囿/关梁/其他) / location_text / history_lore / original`
- `history_lore` = AI 解读沿革/典故（非原文）

## 9. PROD 物产层（薄层，仅外夷卷 89–90）

- **范围限定**：仅抽取卷 89–90（外夷诸国：安南/占城/暹罗/西域诸国等）。府级条目不做物产抽取。
- schema：`prod_id / item_id / geo_id / name / category(动物/植物/矿物/织物/饮食/珍宝/药材/其他) / note / original`
- 外夷卷物产密集（胡椒/苏木/犀象/玳瑁/珊瑚等），府级物产稀少（密度信号：物产仅 6 处），故府级跳过

## 10. CIT 引书层

- schema：`cit_id / item_id / cited_work(含 ent_ids) / context(引用目的：立论/证俗/考源/补遗/其他) / original`
- 引用方式：暗引/泛引（无书名号），以【出处】标记为准
- 与 LIT 分工：本书无整篇收录/抄录的文献，故不建 LIT

## 11. 跨层整合

- ID 对齐审计：实体主键唯一 / 引用槽位合法 / item_id 全回填 / target 用 ID / 枚举口径一致
- `_kg_join.json` + `_kg_join_flat.csv`：每行 = 一条 item，贯通各层 ID

## 12. 治理组件（强制启用）

- **V2 人工校验闭环**：同名异人/同名异地/存疑判定自动收集入"待核清单.csv"（含 provenance），人工核前不强行合并（宁建勿并）。
- **V3 枚举校准**：
  - 执行期打包器收集**未匹配枚举值**（不中断），入 `_pending_enums.csv`
  - 每完成一个 region 输出枚举使用分布报告
  - 批处理决议：新增 / 归并 / 改名（新增值必须有原文证据）
  - registerVersion+1，回溯存量（旧值→新值映射，dry-run 后 commit）

## 13. 管线与验证

### 13.1 源数据组织（分片，不攒大文件）

地理书数据量大，**禁止把多府/多县塞进一个大 JSON**。采用「每卷一文件夹、每条目一文件」：

```
_data/
  vol19/
    19-001_太原府.json       # 府级条目（含 geos/evos/mtns/pers/sites/cits/ents）
    19-001_c01_阳曲县.json   # 县条目（独立文件，含该县山川/古迹/人物）
    19-001_c02_榆次县.json
  vol20/
    20-001_平阳府.json
    20-001_c01_临汾县.json
  vol21/
    21-001_大同府.json
    ...
```

- **府/州/土司条目** = `NN-NNN_<名称>.json`，内含该府全部 7 层记录
- **县条目** = `NN-NNN_cXX_<县名>.json`，c01/c02 顺序编号，内含该县自己的 mtn/site/per/cit
- 每个文件 ≤ 50KB，改单条不动全局
- 贵州（o_000EmRulUba）正在按老格式跑，交付后手动转成新分片格式

### 13.2 合并打包器

`build_merge.py`：扫 `_data/volNN/*.json`，按层聚合产 `_layers/`，可重跑幂等，支持 `--vol NN` 单卷重跑。
`build_pack_pilot.py` 是当前临时合并脚本，后续由 build_merge.py 取代。

### 13.3 验证

- `validate_pilot.py`：ERR（结构性错误，必须 0）+ GAP（执行缺口，登记）
- **GEO 树校验强制**：
  - geo_id 全局唯一
  - children/parent 指向的 geo_id 必须在 geos 表存在（悬空引用 = ERR）
  - 国内 prefecture/department 必须至少有一个 county/subprefecture/tusi 子节点（否则 GAP）
  - parent 必须是 geo_id 字符串，禁止填中文 region 名
- 填充率体检：每层扩展字段「已填/总数/填充率」，填充率=0 判失败
