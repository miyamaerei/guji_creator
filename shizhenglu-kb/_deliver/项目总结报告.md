## 0. 项目概述

《吕公实政录》（明·吕坤）数字化工程，按用户锁定口径推进：

- **AI 逐条判定 + 代码只验缺漏**（判定与验证严格分工）
- **条粒度**（119 条：111 个 ○/△ 标题条目 + 8 个卷级条目）
- **original 指纹注入 + 引用关联**（AI 源数据不手抄原文）
- **每卷独立 JSON + 全局归一**（先分卷产出，再归一并验证）
- **枚举单点治理**（C5 `_kg_enums.py`，新增枚举值必须 version+1 并双写回填）
- **词典全文本内生**（词条必须出现在原文，否则剔除）

最终形成**底座 + 实体层 + 规则层 + 结构化四维层 + 跨层索引**知识资产，执行契约线 C1–C7（实例 SKILL.md §0.2）并全程用 MCP 工具核对契约与枚举基准。

## 1. 全流程时间线（关键阶段）

### 阶段 0：底座（15 卷 / 119 条 + 指纹库）
`build_base.py` 切分全书 → `_extract\NN_卷名.txt`（格式 条N|正文）+ `_item_registry.json`（key=NN-NNN，value 含 original/norm，含异体字归一：廵→巡、飬→养等）——后续所有层 original 注入源，自校验通过。

用户两次纠偏：① 删除过时 `.user_skills` 工厂副本，以 README 指定的 `Skills\00-book-knowledge-factory` 为权威工厂重建；② 创建技能须考虑 README 中 MCP 用法 → 按 `docs\新书开工流程.md` 契约线执行（book-mcp selftest 20 项、list C1–C7、enum ENTITY 20 值+3 别名 / RULE 7 值）。实例编号 07，落 git 仓库内含式。

### 阶段 2：实体层（卷 01–15）
逐卷 AI 标注 651 条 → 全局归一 573 实体（ENT-0001..0573）。跨卷复用由 `build_ent_keys.py` 先查后建（如"掌印官/按察司/乡约/保甲"跨卷同 ID）；alias_index 词形反查。

### 阶段 3：规则层（卷 01–15）
规范句 → 规则 664 条。训谕体逐规范句抽规则不抽议论（卷03 明职 59 条）；序文/白话劝语无规范句者如实判空（卷01/13 = 0）；卷14 提刑事宜 55 条（人命 12 款/盗情 11 款/奸情 4 款/监禁 10 款/听讼 12 款/用刑 4 款/状式总则）；卷15 按察事宜+宪纲十要+狱政 67 条。

## 2. 反思结论

### 反思一（源数据多段写入覆盖）
多部分源数据用多次 Write 会整体覆盖前段（卷14/15 规则层两次踩坑）。**结论：多段源数据以"一次 Write 写全文件"为准；写后逐文件体检条数对账再打包**。

### 反思二（struct 维度类型字段）
struct 记录必须携带维度专属类型字段（act_type/frd_type/lgr_type/tme_type），且值必须命中 `_kg_enums.py` 枚举；缺字段/错值会被打包器跳过并报 ERR（卷05 曾静默丢 1 条）。**结论：schema 必填字段在写数据前对照 schemas.md 检查**。

### 反思三（全量缺省模式）
`run_all.py` 无 `--volumes` 时四个打包器曾报 `TypeError`（parse_volumes 返回 None）。**结论：已修复为缺省扫描 `_src` 全部已装填卷，全量回填 119 条 GAP=0**。

## 3. 根因分析：为什么出现重复读取/重复验证

诚实复盘，重复工作主要来自产物覆盖回归：

1. **多段 Write 覆盖源数据（失误，2 次）**：卷14/15 规则文件被整体覆盖 → 重读原文重写/合并。改进：一次写全 + 写后体检对账。
2. **枚举错值静默丢条（失误）**：卷05 struct act_type 未注册 → 校验清单暴露（ERR 列表）→ 修复。改进：写 struct 前核对枚举。
3. **上下文压缩后 schema 重读（半可控）**：参考 schemas.md §2/§9 试点口径重读。改进：试点样例固化进实例。
4. **用户多轮纠偏（方向成本，不是无用读取）**：两次纠偏（工厂版本 / MCP 用法）最终定案正确。

## 4. 方法论沉淀（下次遇到任务的处理原则）

1. **一次探查**：开工前读完全部输入 + schema 样例 + 统计；连续两次读取不再改变计划即停止探查。
2. **先锁 schema 再写数据**：字段口径、枚举、ID 规则一次性定死；打包器注入指纹/关联/校验。
3. **AI 判定与代码验证严格分工**：判定逐条人工（AI）；代码只验缺漏。
4. **所有生成器正式化**：build_ 前缀 + 可重跑 + 幂等；修复并入生成器。
5. **源数据一次写全 + 写后体检**：多段内容合并为单次 Write；写后对账每条目数。
6. **枚举单点治理**：新增枚举值 version+1 并回溯存量（registerVersion 模式）。
7. **一卷一文件**：多卷源数据不得共用/覆盖。
8. **交付按层聚合**：每层一组（产物 + 验证清单 + 跨层索引）。
9. **每轮任务建 task 清单**：阶段可见、完成可核。
10. **如实报告缺口**：哪里缺、缺什么、补什么方案，不静默降级。
