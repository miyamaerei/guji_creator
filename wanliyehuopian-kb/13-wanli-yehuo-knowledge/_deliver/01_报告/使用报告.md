## 1. 项目定位

《万历野获编》（明·沈德符）数字化知识库。本知识包把 34 卷 **1,451** 条笔记掌故，逐条拆解为
**实体 / 规则 / 事件 / 任职 / 关系 / 引书 / 论说 / 纪事 / 沿革 / 制度** 10 个知识层，
并以一条 `item_id` 主键贯穿全部层，形成**可溯源到原文、可跨层回查、可脚本重跑**的研究资产。

**关键特性**：
- 全部记录挂 `item_id`，可与 `_item_registry.json` 原文指纹互指（溯源闭环）
- `_kg_join.json` 给出一条笔记**贯通几层**的即时视图（`layer_count`）
- 生成器带**写盘前硬校验**：所有 `original`/`evidence`/`quoted_text` 必须与源文段逐字子串匹配，不符则**拒绝写盘**
- 跨卷实体通过 `_global/ent_keys.json` 归一（不改写原 ID，另建映射层）

## 4. 怎么使用

### 4.1 快速查询

```python
import json, os
BASE = r"E:\git\ToolBox\guji\wanliyehuopian-kb\13-wanli-yehuo-knowledge"

def load(layer, vol):
    p = os.path.join(BASE, "_layers", layer, f"{layer}_{vol:02d}.json")
    d = json.load(open(p, encoding="utf-8"))
    return d["records"] if isinstance(d, dict) else d

# 例：全书搜"矿税"相关事件
hits = [r for v in range(1, 35) for r in load("events", v)
        if "矿税" in json.dumps(r, ensure_ascii=False)]
```

**按条目看全貌**（查一条笔记贯穿哪些层）：

```python
join = json.load(open(os.path.join(BASE, "_kg_join.json"), encoding="utf-8"))["records"]
rec = next(r for r in join if r["item_id"] == "16-027")
print(rec["entry_title"], rec["layer_count"], rec["layers"])
```

**按人物看一生**：直接读 `views/timeline/张居正.json`
→ `ENT-0015`（词形「张太岳」）、涉 16 卷、**83** 条记录（appts 4 / events 17 / mings 12 / opns 23 / rels 27）。

**按制度看沿革**：`views/institution_evolution/` 下 54 个制度（如「东厂」）。

### 4.2 全文回查溯源

每条记录都带 `original` / `evidence` / `quoted_text` 等引文片段，且**经生成器逐字校验**
（必为源文去空白后的子串）。回查原文步骤：

```text
1. 从记录取 item_id（如 16-027）
2. 到 _item_registry.json 查该条目 → 得 original（前 200 字预览）与 norm（归一文本）
3. 需全文 → assets/sources/万历野获编.txt 按【条目标题】定位
4. 记录中的 original/evidence 应能在该段逐字命中（去空白后）
```

### 4.3 可重跑管线

```bash
cd 13-wanli-yehuo-knowledge
python -X utf8 scripts/validate_layers.py    # 结构 + 覆盖率校验 → 期望 GAP=0
python -X utf8 scripts/build_ent_keys.py     # 重建 _global/（实体归一）
python -X utf8 scripts/build_kg_join.py      # 重建 _kg_join.json / _kg_join_flat.csv
python -X utf8 scripts/build_views.py        # 重建 views/（全量删除后重建）
python -X utf8 scripts/_audit_origins.py     # 条目级分段自检（1451/1451）
```

⚠️ `build_views.py` 会 `shutil.rmtree(views)` 后重建——它是**纯派生物**，可随时重跑。

### 4.4 扩展指南

补新条目/新卷：

1. 在 `scripts/` 仿现有 `gen_gap*.py` 写生成器，**从 `_kg_enums.py` 导入全部枚举**；
2. 用 `build_segments(vol)` 从 `assets/sources/` 切出每条源文段；
3. 所有引文经 `q(item, s, field)` 逐字校验后才 add；
4. 任何 `ERRORS` 非空 → `main()` **拒绝写盘**（这是护栏，不要绕过）；
5. 写完跑 `validate_layers.py` 确认 GAP=0，再重跑 `build_kg_join` + `build_views`。

**枚举纪律**：新增枚举值必须改 `_kg_enums.py` 的 `VERSION` 并回溯存量（registerVersion 模式）；
构造器内的 `chk()` 是唯一防线。

## 5. 关键设计（5 条）

1. **`original` 不手抄，逐字硬校验** —— AI 只给出条目定位，脚本文本比对，保证引文零漂移；
   校验卡在**写盘之前**（`main()` 见 ERRORS 即拒绝落盘）。
2. **条粒度锚点** —— 一切记录挂 `item_id`（1451 条），跨层、跨卷、跨视图均以它为唯一关节。
3. **枚举单点治理** —— 全部 17 组枚举集中在 `scripts/_kg_enums.py`，构造器 `chk()` 逐一验；
   分片并行的 5 个撰写者共用同一份 `_spec_v01.md` 契约（签名逐字）。
4. **构建器与生成器分离** —— `gen_*.py` 产数据、`build_*.py` 建索引与视图；
   `_layers/` 是源，`views/` 与 `_kg_join*` 是**可重跑派生物**。
5. **跨层索引一行全看** —— `_kg_join.json` 的 `layers` + `layer_count` 让"这条笔记值多少"一眼可判；
   `canonical_ents` 给出归一后主键。
