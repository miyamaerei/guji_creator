## 1. 执行流程总览

按序执行，每阶段收尾对照 checklists：

```
底座（拆分 + 指纹库） → 启用层逐层抽取（AI 判定 + 代码验证） → 跨层整合 → 交付
```

## 2. 底座（公共地基，先做）

1. 输入文件：`assets/sources/万历野获编.txt`（UTF-8，8587 行，1.8MB；底本=文硕阁 epub 转 txt）
2. 章节划分：39 章（`●` 标记切分）
   - 00 卷 = 前言（序/续编小引/补遗序/补遗跋/分类凡例，不入条目库）
   - 01–30 卷 = 正卷
   - 31–34 卷 = 补遗卷一~四
3. 条目切分：以 `【标题】` 为最小单元；卷内 `○` 标记为二级分类上下文（不单独切条）→ 预计 **~1400 条**
4. 指纹库 `_item_registry.json`：key=`NN-NNN`，value=original/norm；norm 归一规则：繁体→简体（实例统一简体）、异体字归一、全角→半角标点
5. 全部条目建 task 清单（阶段可见、完成可核）
6. **业务 ID 由打包器自动分配**：AI 源数据只写卷内顺序槽位，不手写业务 ID；打包器按「卷号 × 段容量 +1」段位分配，段容量默认 500
7. **写盘与并行纪律**：写文件一律「临时文件 + rename 落盘」；共享汇总文件统一增量合并语义

## 2.5 工程侧护栏（打包器骨架，Phase ③ 必接）

> 依据：工厂 `references/error-taxonomy.md` —— A/B/G/P 四族合计 **30/65 条（约 46%）**。

1. **复制骨架**：工厂 `assets/skeletons/packer_skeleton.py` → 本实例 `scripts/_common.py`，填写 `LAYER_SPECS`（12 层三元组）。
2. **不删护栏**：任何护栏函数不适用时须写明理由。
3. **A 族（静默失败）**：凡新增扩展字段，必须登记进 `FieldCoverage(fields=[...])`；填充率表与 ERR/GAP **并列交付**。
4. **B 族（命名契约）**：目录名 / 文件名前缀 / 索引槽位名 / schema 键名**四处同源**，只用 `LAYER_SPECS` 声明一次。
5. **G 族（幂等/原子）**：写盘一律 `atomic_write_*()`；各层落盘走 `merge_layer()` 增量语义。
6. **P 族（流程语境）**：判语域一律锚定原文开头（`SemanticGate`）；数值/单位解析 `cn2int()`；枚举校验「收集-报告-暂存」+ `drift_ratio()` 漂移告警。
7. **收尾**：每个 `build_*.py` 结尾调用 `run_guardrails(name, errs, gap)`。

## 3. 实体层方案（L1）

- 实体类型枚举（**继承基准库 + 本书归纳增量**）：人物(person)/机构(institution)/地名(place)/职官(official)/书名(book)/民族/ethnic/宗教(religion)/事件名(event_name)/其他(other) + 兜底"类型待定"
- **扩展字段**：
  - `role_in_entry`：主体/客体/评论对象/引用人物/关联人物
  - `faction`：东林/楚党/齐党/浙党/昆党/宣党/宦官/无/待定（**跨层通用字段**，REL/APPT 共享）
  - `exam_info`：`{year, era, rank, title}` —— 科举信息
  - `career_span`：书中提及的仕宦时段
- 种子词典规则：全文本内生（词条必须出现在原文，否则自动剔除）
- 归一规则：异体/同义/复合词形
- 主键表：ENT-001..N + alias_index
- 每卷 JSON + 全局归一 + 标注总报告

## 4. 规则层方案（L2）

- 触发词表：不可/不许/务要/须/止许/毋/勿/著为令/定制/例/不得/禁止/禁/罢/革
- 规则类型枚举：禁止/义务/允许/程序/时限/处罚/优先级
- 槽位 schema：条件/主体/动作/对象/模态/目的/处罚/出处
- **扩展字段**：
  - `rule_origin`：祖制/诏令/惯例/奏议定/上谕/其他
  - `actual_practice`：遵行/变通/名存实亡/完全违背/未明（**核心价值字段**——本书常记"祖制如此，然今已…"）
  - `violation_evidence`：违背证据摘要
  - `time_marker`：适用时段（"国初""嘉靖后""万历间"）
- 组合规则口径：一条多模态拆多条共享 item_id

- 事件类型枚举：**继承基准库事件类型子库** + 本书归纳增量（朝政/制度变动/科举/军事/边政/司法/宫廷/人事/灾异/社会/其他）
- **扩展字段**：
  - `event_significance`：重大政治/制度变动/人物转折/一般掌故/轶闻
  - `political_impact`：政治影响摘要（AI 概括，非原文）
  - `source_type`：亲历/传闻/文献转引/综合（**跨层通用字段**，MING 共享）
  - `vs_official_history`：补正史之阙/异于正史/正史不载/与正史合/未考（**跨层通用字段**，MING/REG 共享）

- 执行方式：试点 1 卷验收 → 全量

## 8. 跨层整合

- ID 对齐审计点：实体主键唯一 / 引用槽位合法 / item_id 全回填 / target 用 ID / 枚举口径一致
- 跨层索引：`_kg_join.json` + `_kg_join_flat.csv`
- 枚举治理：枚举单点文件 + registerVersion

### 8.1 职官任职层方案（C1 APPT）

- 任职动词词典：授/擢/迁/改/除/罢/谪/致仕/兼/领/督/巡抚/提督/升/调/起/复
- **扩展字段**：
  - `appointment_context`：任命背景（"以某某推荐""因某某罢""特旨"）
  - `controversy`：无争议/有争议/遭弹劾/被驳回
  - `faction_implication`：派系含义
  - `concurrent_posts`：兼职信息数组
- 一条目多任职拆多条共享 item_id

### 8.2 人物关系层方案（C3 REL）

- 关系类型枚举：同僚/师生/姻亲/同乡/同科/举荐/弹劾/恩怨/上下级/父子亲属/敌对/党派/其他
- **扩展字段**：
  - `relationship_evolution`：关系演变（"初善，后反目"）
  - `political_consequence`：政治后果
  - `evidence_strength`：直接表述/推断/旁证
  - `time_span`：关系存续时段
- 只建文本有直接证据的关系，推测关系不建（宁缺毋滥）

### 8.3 引书索引层方案（C6 CIT）

- 引用方式枚举：直引/转引/泛引/暗用/考辨
- **扩展字段**：
  - `citation_purpose`：立论/佐证/对比/反驳/补遗/掌故引用
  - `accuracy_note`：作者对被引文献的准确性评价
  - `quoted_text`：引文片段（短引保留，长引截断+原文锚点）
- 书名实体归 L1（type=book）；CIT 记录条目级引用

### 8.4 作者论说层方案（C9 OPN）

- 判据：`按`/`余谓`/`予谓`/`余以为`/`余尝`/`窃谓`/`愚以为`
- 立场枚举：肯定/否定/怀疑/讽刺/中立
- **扩展字段**：
  - `commentary_type`：褒扬/贬斥/考辨/感慨/讽刺/劝诫/中立评述
  - `target_entities`：评论对象实体 ENT-ID 数组
  - `evidence_cited`：作者引用的论据
  - `historical_parallel`：作者援引的历史类比（"如唐之X""宋故事"）
  - `tone`：严肃/愤慨/惋惜/嘲讽/客观
- 建层前实测密度：379 处"按"字，确认充分

### 8.5 明代纪事层方案（C10 MING）

- 涉明类型枚举：朝政/人物/科举/风俗/灾异/亲历见闻/制度/边政/军事/其他
- **扩展字段**：
  - `reign_focus`：洪武/永乐/洪熙/宣德/正统/景泰/天顺/成化/弘治/正德/嘉靖/隆庆/万历/跨朝
  - `firsthand_witness`：亲历/亲闻（父祖述）/传闻/不详（**跨层通用字段**）
  - `supplements_what`：补正史之什么（AI 概括）
- 与事件层分工：MING 只做涉明条目索引 + 亲历标记，不重复建模事件

### 8.6 时间沿革层方案（C14 TME）

- 纪年正则：`(洪武|永乐|洪熙|宣德|正统|景泰|天顺|成化|弘治|正德|嘉靖|隆庆|万历|泰昌|天启|崇祯)(元|[一二三四五六七八九十百]+)年`
- 变动类型枚举：初置/改置/升秩降秩/废置/复设/改称/裁并/增员/移驻/职掌变更/未明
- **扩展字段**：
  - `institution_target`：沿革涉及的机构/制度 + ENT-ID
  - `cause`：变动原因
  - `before_after`：`{before, after}` 变动前后对比
- 配套 `REIGN_ORDER` 排序键（继承 enum-library §1.21）

### 8.7 制度层方案（REG，笔记掌造型 7 属性）

> 区别于政书型 REG（13 属性），本书用精简 7 属性——笔记中的制度描述是**叙事性的**，非条目式的。

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | str | 制度名称 |
| `category` | enum | 官制/科举/礼制/军事/财政/司法/边政/宦官/宗室/其他 |
| `establishment` | str + TME-ID[] | 创设时间与背景 |
| `content_summary` | str | 制度内容概要（AI 概括，非原文） |
| `actual_practice` | str | 实际运作情况（**核心价值**：制度 vs 现实的差距） |
| `abuses_reform` | str[] | 弊端与改革尝试 |
| `key_figures` | ENT-ID[] | 相关人物（创设者/改革者/破坏者） |

- 与 L2 分工：L2 记具体规范句（IF-THEN），REG 记制度整体画像
- 与 TME 分工：TME 记时间点事件，REG 记制度全貌
- `vs_official_history` 字段同 L5（**跨层通用**）

## 10. 交付清单
